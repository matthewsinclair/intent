## The denominator, and why it is not written in this sentence

**Count it: `ls -1d intent/plugins/claude/skills/*/ | wc -l`.** Outside the source tree, `intent claude skills list` names the catalogue the installed Intent carries. The figure is deliberately absent from this prose, because `WP-15`'s own objective records it going stale repeatedly in one document -- right at authoring, wrong when `in-handoff` retired, corrected in the view and silently reverted by a regeneration, corrected in canon in a field that carried it twice so one copy was repaired and the other left contradicting it, and stale a third time when `in-next` and `in-start` retired. **A denominator in prose goes stale by construction.** `AT-15.1` (`native/rust/crates/intent-cli/tests/skills_triage_covers_the_catalogue.rs`) asserts this table's rows against the catalogue **enumerated at close**, as a set equality rather than a count, so a skill added or removed after this document was written reddens a test rather than quietly falsifying a sentence.

**AN ABSENT ROW AND AN UNEXAMINED SKILL ARE THE SAME ABSENCE.** Every skill the enumeration returns has a row below, including every one whose verdict is KEEP with no change. A triage that lists only what it changed has an unmeasured arm, and the unmeasured arm is precisely the skills nobody looked at.

## ZERO RETIRE IS A RESULT, AND THE GROUNDS I LOOKED FOR ARE NAMED SO THE ZERO CAN BE ARGUED WITH

A triage returning no retirements against hv's premise that _a lot of skills don't make sense anymore_ owes its reasoning, not a shrug. **Retirements have ALREADY happened and I verified each is gone**: `in-handoff`, `in-next` and `in-start`, so the premise was acted on before this table existed.

**Each of these grounds would have produced a RETIRE, and each was driven:**

- **Names a verb the surface does not carry.** Every `intent <verb>` spelling in every skill was extracted and invoked. **All ship**, including the ones I expected to fail: `at lint`, `fc`, `claude subagents`.
- **Names a v2-era path.** The remaining hit is `intent/llm/AGENTS.md` in `in-essentials`, and **it retires the thing it names in the same sentence**. The naive stale-reference test scores **no true positive** on this corpus, which is the discriminator constraint `AC-15.2` recorded (withdrawn 2026-09-11; its text stands as a record) and this is its measurement.
- **Orphaned -- no caller.** Every skill has non-catalogue references. `AT-00.4` (`native/rust/crates/intent-cli/tests/every_skill_has_a_live_caller.rs`) holds a weaker property, transitively: every `chains_to` target exists, and every skill is chained to or invoked by name in `AGENTS.md`, `CLAUDE.md`, `usage-rules.md` or a `SKILL.md`. Because `usage-rules.md` names every skill, it cannot report one as unreached. **The first pass of this measurement was WRONG and inflated every count**, because `usage-rules.md`'s Skills table lists every skill by construction; a reference count including it measures being CATALOGUED, not being CALLED. Re-driven with catalogue documents excluded.
- **Superseded by a mechanism that replaced it** -- the rule library, `critic-<lang>`, the AC/AT contract. No skill was found duplicating one; the language packs point AT the rule library rather than restating it.

**THE TCA QUESTION THIS TRIAGE LEFT OPEN WAS hv'S, AND hv RULED IT ON 2026-10-25 (ST0088 WP-01).** The five `in-tca-*` skills left the catalogue with their scripts, and so did `in-cost-analysis`, with its script and rates table, and `in-debug`. The Total Codebase Audit stays as the written procedure in `intent/docs/total-codebase-audit.md`, which names the critics and no skill.
