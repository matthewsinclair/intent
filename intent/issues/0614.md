## What

In a linked git worktree, Intent's post-merge, post-rewrite and branch-switch post-checkout carriers run `intent sync --apply` against the worktree's OWN store, and that store can be older than main. In Molt, a rebase in a worktree re-rendered peers' whiteboard views backwards: molt-cc's board showed an old name and focus. The re-rendered views were then swept into a commit made from the worktree.

Molt's workaround: run `git checkout -- intent/whiteboard` after creating a worktree, and never commit `intent/` from one.

## Relation to 0483

Issue 0483 (closed 2026-09-19) stopped the carrier on a fresh worktree's first checkout, when the previous HEAD is the null id. Its closing note keeps the rest as it was: "a branch switch inside an existing checkout still syncs, and post-merge and post-rewrite are unchanged". This report is that remainder, seen in use.

## Not yet measured here

Reported by molt-dc from molt-vc's board (Molt, 2026-10-22), on Intent 3.2.4. vc has NOT reproduced it in Intent. The lane that takes this measures first:

- which carrier fired;
- what store the worktree held, and from which commit it was built;
- what the sync wrote, and in which direction.

Only then does it choose between skipping the carriers in a linked worktree, building the worktree's store from the tree it now stands on, and refusing to write views backwards.

## Expected

A sync inside a linked worktree never writes a view older than the commit the worktree stands on. Nothing a hook writes in a worktree can be swept into a commit as a regression.

THE MECHANISM. `land_board_write` in `intentsvcs/src/facade.rs` projects every board from the store and writes each one whose bytes differ from the file on disk. A store whose file index holds no row for a board's `board.json` cannot count a change git brought to that file as moved; that is 0619's mechanism. So the carrier leaves the newer file on disk and the older board in the store, and the next board write by any node re-renders that board backwards. 0619's fix (5d28210ad, in v3.2.5) makes a cold warm record the rows. It prevents the gap in a store 3.2.5 warms, and it repairs none in a store an older pair warmed.
