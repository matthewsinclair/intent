The finding (ic, from hv's Console screenshot at 20:12 local): `intent daemon logs` ran `tail -q -n 40 -F intentd.log intentd.err.log`, which prints the last lines of `intentd.log` and then the last lines of `intentd.err.log`, one block after the other. The Console showed `intentd.log` ending at 2026-09-16T19:12:42.909Z (`intentd listening on ...`), and under it the error log's older lines from 2026-09-15T22:42:02Z to 2026-09-16T16:55:02Z (`database is locked`). The older errors therefore sat below the newest start line and read as if they had happened after the restart.

The shape vc routed:
1. The backlog is one list: the last N lines of both files merged by each line's leading RFC 3339 UTC stamp (issue 0321 put one on every line intentd writes), in a pure function in intentsvcs that takes the two files' lines and N and does no I/O.
2. A line with no stamp (written before stamps began, or a continuation) inherits the last stamp above it in its own file, lines before any stamp in a file sort first, and ties keep file order, so a multi-line record never splits.
3. `--lines` counts lines of the merged list. `--follow` prints the merged backlog, then follows both files from their ends as lines arrive, with no second copy of the backlog.
4. The Console reads `daemon logs --follow`, so it needs no change of behaviour.
5. The dispatch row and reference prose that describe the per-file order are corrected, with the table regenerated in the same change.
