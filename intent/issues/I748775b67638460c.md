AE found this on 3.5.2. `intent issues close` takes no note or reason, so a close that records how the issue was resolved needs an `issues edit` first.

Fix (b353): `intent issues close --reason <text>` adds `Resolution: <text>` to the issue's body in the same close. A blank reason is refused. A reason given to an issue that is already closed writes nothing, and the CLI says so.
