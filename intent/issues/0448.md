`intent init` writes neither aggregate view, and doctor counts an absent aggregate view as skew even on an estate with no thread. So the first commit of every new project is refused by the gate that `claude upgrade --apply` just wired, with a remedy the new user has to work out (`intent sync --to-disk`, which the store page says is almost never what you meant). The second drive, with `intent sync --to-disk` run once after `bootstrap`, commits cleanly.

## The fix (XS)

Either `init` writes the two aggregate views it will otherwise demand, or doctor does not count an absent aggregate view on an estate that has nothing to render. The first is simpler and makes `init`'s output complete. Pinned by one arm: init, upgrade, commit, rc 0.
