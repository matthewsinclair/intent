The release driver's footer-only view classifier (`bin/.devbin/cmd/build.d/release:1156`) selects changed lines with `grep -E '^[-+][^-+]'`. In a unified diff, a markdown bullet line reads `-- item` or `+- item`, and an added or removed empty line reads `+` or `-` alone, so none of them is selected. A view whose only real change is to a bullet or a blank line is therefore classed footer-only and folded into the release commit as if it were the version footer. critic-shell drove it on a sample. There is also no `pipefail` on the `git diff` pipeline, so a failed diff reads as footer-only too.

Fix: select every changed content line (`^[-+]` excluding only the `---`/`+++` file headers, which `-U0` still prints), and fail on a failed diff. S. vc's next-line list, item 4.
