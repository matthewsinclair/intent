**What happens.** `intent wb edit` (0523) reports whether any file under `intent/` still holds an edited item's old text: at HEAD, and in what the next commit would carry. In a project that is not a git repository, neither search can run. The answer still prints the all-clear, "no file under intent/ holds the old text, at HEAD or in the next commit" (facade.rs:8779-8783 and 8815-8819; render.rs:4496-4501), and `wb_edit_door.rs` asserts that sentence in a project with no git. So the verdict claims a search that never ran. It is true only vacuously, and it reads exactly like a clean result.

**What the fix has to do.** Where the project is not a git repository, the answer says the two searches did not run and why, and claims nothing about HEAD or the next commit. The arm in `wb_edit_door.rs` asserts that wording in place of the all-clear. A project with git reads exactly as before.
