## The defect this issue owns

**No verb repairs an unreadable search-index table in place.** `intent index rebuild` is the obvious door, and it is behind the same wall: it cannot run until the read it would repair succeeds. The only way out today is by hand -- restore a snapshot, or rebuild the store -- and neither has a verb: `intent backup` is one-way ("no restore verb ships"), and the store's own remedy says never to delete it, correctly, because it is the source of truth.

## The fix, as far as it can be sized from here (S to M)

`intent index rebuild` must be able to run when an index table cannot be read. It opens the store without reading the prose sections, drops and recreates the fts5 tables from the schema, and re-indexes from the tree. Sections are derived, so nothing is lost. When it lands, 0447's remedy names it; the remedy's "No verb in this build repairs it in place" sentence is the line to change, and 0447's arms say where.
