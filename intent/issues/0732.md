`Facade::day_of_event` (native/rust/crates/intentsvcs/src/facade.rs, `fn day_of_event(&self, id: &str) -> Option<String>`, line 7662 in the bank) gives a work package's `created` as the day of its origin event's ts in the store's log. It folds a store read failure into `None`, the same answer as "the log has no such event". So a reader of `IdRecord.created`, eg `intent id`'s candidates or AmbiguousId's, cannot tell an absent event from a store it could not read (IN-AG-NO-SILENT-001).

Expected: the read failure is a typed error carrying a remedy. That means `record_of` returns a Result, which changes WP-10 Part 1's `id_of`. `None` stays only for an event the log does not hold.
