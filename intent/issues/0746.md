ST0093 is a record the project does not realise, but git tracks its views (issue 0707's residue). The release format re-shapes a thread's cover, and the upgrade re-renders only realised views, so this tracked cover stays in 3.4.0's shape. The post-landing dehydrate goes through organize's gate, which refuses a view that differs from its render as a possible hand edit. After the format move that difference is the renderer's, not a person's, so nothing short of an overwrite clears it. The workaround, brew 3.4.0's `organize --apply` before the upgrade, is gone for anyone who ran `brew upgrade` first.

Meaning (cc): a tracked view of an unrealised record whose work-tree bytes equal HEAD's blob loses nothing when removed, because git holds every byte and `git checkout` restores it. The upgrade's post-landing dehydrate takes such a view, names it on a `removed:` line and in upgrade.paths, so the closing line's `git add` stages the deletion. A view that is dirty against HEAD stays refused as a possible hand edit, as now. organize's own rule does not change.
