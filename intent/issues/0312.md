## What

The spine does not apply an `enum` positional argument's declared `values`, so a row can declare a permitted set that nothing enforces. Every renderer arm matching such a slot is the only enforcement there is, and must be exhaustive itself.

## Evidence, driven

`wb archive` declares `kind` as `"type": "enum"` with `["doing", "todo", "decision", "watchout"]`. Before the fix, the renderer's arm ended `_ => WbItemKind::Watchout`, and:

```
$ intent wb archive --node cc nonsense 1
ok: cc has no live watchout 1
```

clap accepted `nonsense` and the arm mapped it to `watchout` — a silent write against the wrong kind for any word at all. Nothing between the operator and the store objected.

## Why it is the spine and not the row

`declared_values_are_enforced.rs` already records the mechanism for the FLAG case, in the `st edit` slot's own comment: *the spine reads `arg.default` for enum args and never `arg.values`*. The same is true of positionals, and there is no guard that catches a renderer arm with a catch-all — `declared_values_are_enforced` requires a DISPOSITION per slot, which is satisfied by declaring the slot `Unenforced` with an issue number as much as by enforcing it.

## Why clap is the wrong place to fix it

A clap rejection exits **2**, the USAGE code the pre-commit gate FAILS OPEN on, and the requirement that `Disposition::Enforced` states is an exit-1 refusal naming the permitted set. The same reasoning is already recorded against `st edit`, `wp rescope --size` and `critic <lang>`. So a blanket `value_parser` in the spine would satisfy the word and break the contract.

## What was done here, and what is left

`wb archive` is `Disposition::Enforced` via `render::enum_arg`, a sibling of the existing `enum_flag` that reads the roster THE TABLE declares rather than copying it into the match. That closes this one slot.

What remains is the general question: whether any other arm matching an enum positional relies on the spine to have narrowed it. **That has not been audited** — the slot census in `declared_values_are_enforced::DECLARED` is the place to start, since it already enumerates every slot declaring `values`.
