**`intent estate slots release` IS SOMETIMES REFUSED FROM A BACKGROUND SCRIPT OF A LIVE SESSION, AND THE LANE THEN STAYS HELD WITH NOTHING SAYING SO.**

**What was seen.** vc's judge wrappers run in the background of vc's Claude Code session: `slots wait`, then `slots start`, the run, then `slots release`. On 2026-11-10 at about 21:15Z and on 2026-11-11 at 07:47Z the release was refused with `error: no Claude Code session file names session <id>` (`SlotError::NoSession`, `intentsvcs/src/estate/slots.rs:48`), while `slots start` from the same script, minutes earlier, was accepted. The same wrapper released without trouble five other times on 2026-11-11 (05:06Z, 05:21Z, 05:58Z, 06:43Z, 07:40Z). A foreground `slots release` from the same session seconds later was accepted both times.

**What it costs.** The request has a start and no end, so the lane reads as running. On 2026-11-10 cargo sat held for 16 minutes until the desk asked. Nothing tells the desk or the asker that a release was tried and refused: the refusal goes to the script's own output.

**What is not known.** Why the caller's session file is not found at that moment. `slots::caller` reads Claude Code's session files under `<claude dir>/sessions` and looks for the one naming `CLAUDE_CODE_SESSION_ID`. Not measured: whether Claude Code rewrites that file in a way a reader can meet half-done, whether the file's recorded pid or state changes while the session is between turns, or whether the read fails and is reported as absent. The session was alive throughout, and its foreground call was accepted.

**What a fix has to hold.** A session that started a slot can end it. Either the caller lookup survives whatever the session file is doing at that moment (a retry, or a read that tells unreadable from absent, which the remedy does not today), or a release is accepted from the session id that the start recorded. And a start with no end, whose asker's session is alive and idle, is shown to the desk as that.

**Found by** vc and devbin-vc during the 3.3.0 build; hv's standing rule puts it in 3.3.0.
