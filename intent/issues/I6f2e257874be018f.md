`mcp_session_with_env` (intent-cli/tests/common/mod.rs) parses the server's stdout with `String::from_utf8_lossy`. If `intent mcp` writes bytes that are not UTF-8, each one becomes U+FFFD, and the test that reads the frame still passes.

Found by critic-rust (IN-AG-RED-CONTROL-001, a recommendation) when it reviewed the I37f8e18 follow-up at bank 97fa1ba3b (on main as 6fbc1c06b). Before that follow-up, mcp_stdio_serves and the_mcp_organize_door_answers_in_project_relative_paths read stdout with a strict `String::from_utf8(..).expect(..)`. So they checked "the wire is UTF-8" as a side effect. They now go through the helper, and that check is gone. The follow-up kept to the five test files, so the helper did not change.

Fix (owner cc, size XS): in `mcp_session_with_env`, convert stdout with a strict `String::from_utf8` that names the failure before the frames are parsed. This one change covers every caller of `mcp_session`. Before the fix, check that no caller needs output that is not UTF-8.
