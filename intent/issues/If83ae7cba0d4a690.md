Three manual parity tools assume the first `st new` in a fresh fixture is `ST0001` instead of reading the id the verb printed:
- intent/st/ST0056/parity/tools/canon_race_check.sh: fixture commands go to /dev/null unchecked, so on a git-style build the fixture is silently empty and the race arms measure refusals, not a race.
- intent/st/ST0056/parity/tools/read_claim_probe.sh: `wp new ST0001` fails, so the tool cannot run on a current build.
- intent/st/ST0056/parity/tools/inert_arg_check.sh: its "flag is inert" verdicts would come from unknown-id refusals; `ST0001/01` was never created.

Expected: each reads the minted id with `minted_id` from bin/.devbin/cmd/shared/mint.lib and passes it on, and checks every fixture command's status.
