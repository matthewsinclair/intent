`bin/devbin build release --skip-tests` returns from `preflight` (`bin/.devbin/cmd/build.d/release:599`) before the `gh auth status` check (`:693`), so a re-run with `--skip-tests` on an unauthenticated `gh` commits, tags and pushes to both remotes, and only `gh release create` finds the problem. The header lists gh auth as a pre-flight gate, and the script's own rule for the contract and docs/reference checks is that a read that is not a suite is not skipped by `--skip-tests`.

Fix: move the gh check above the `--skip-tests` return. XS. Found in dc's doc sweep of 2026-09-18 (vc's next-line list, item 2).
