`--list-guards` reports a self-classifying guard as `present`, and it is the one state that cannot be true or false yet.

The runner's `--list-guards` arm computes a state column per roster row: `MISSING` when the guard file is not there, `not-applicable` when the row's `applies-when` names a path the tree does not carry, and `present` otherwise. Since issue 0506 there is a fourth condition it cannot express -- a guard whose applicability is a DECLARATION rather than a path, which settles the question itself and answers exit 3.

**THE ARM CANNOT ASK, AND THAT IS ITS CONTRACT RATHER THAN A GAP IN IT.** `--list-guards` returns before any dispatch, deliberately: its own header records what it cost the last time a read-only report answered a question by running the thing -- `int hooks` grepped `cmd/prepush` for the string `--list-guards`, matched a COMMENT, invoked it, and prepush cloned the repository and cold-built it every time anyone asked what the hooks were wired to. So a self-classifying guard reads `present` here, meaning only that the roster's path test says yes and nothing was asked beyond that. Its real answer appears in the RUN's tally, where it was paid for.

**WHAT IT WOULD TAKE, AND WHY THAT IS NOT A RIDER ON 0506.** The roster row would have to DECLARE that a guard self-classifies, which means a fourth field. The row is split with `|` into three parts and `g_unchecked` is `${g_rest#*|}`, which takes the rest of the line -- so a fourth field lands inside it. The parse moves, every row moves, and every reader that splits this output moves with them, `int hooks` included (it already has to name the fifth column because a bash `read` of four hands the fourth the rest of the line). That is a roster-format change. It is the same argument that split 0506 out of 0505, applied one level down: a format change does not ride in under a classification fix.

**ORIGIN.** 0506's Expected clause asked for the not-applicable answer to be "named in `--list-guards`'s state column". The classification landed without it and vc ruled 0506 closeable on that basis (2026-09-22), with the column becoming this issue. Recorded so the trail holds rather than reading later as a clause someone quietly dropped.

**WHAT ELSE WANTS A HOME HERE.** 0505's AC-5 said an absent tool is UNENFORCED by name AND that not-applicable reaches a human. Since 0506 the second half reaches them as an anonymous increment in the runner's `N skipped` rather than as a named line: a human still learns that something did not apply and no longer learns WHICH. That is strictly weaker and is recorded as a cost in `tests/unit/staged_format_guard.bats`'s clause map rather than reworded to match the build. If a named line is wanted back, it is the same information this issue is about and it belongs with it.
