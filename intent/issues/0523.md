Requested by gtools-vc on 2026-09-22, on Gtools hv's ruling "Intent verb, hold", and carried as Intent vc todo 61. Ruled by hv on 2026-09-23: "I need that fixed right now, please." It is a 3.2.1 item.

Seen: Gtools' pre-commit identifier gate refuses any added line carrying a client identifier or name, in any file a commit adds (boards, inbox views, `intent/.canon`, `intent/st`), because the text sits in the rendered views AND in its originating event file under `intent/.canon/events/`. No `intent wb` verb changes text a node has written. (gtools-vc, 2026-09-23: nothing in Gtools is blocked today; hv committed gtools-cc's todo 95 as it stood, and Gtools hv ruled engagement ids not sensitive, so the likely trigger is a client name. The next case is caught at commit time, while its event is still pending.)

Expected, two cases, both required:

1. Originating event NOT YET COMMITTED: the edit leaves no trace of the old text in anything a commit would carry. The pending event is amended before it lands, and no superseded file is left untracked beside its replacement, because nodes commit events by adding untracked event files.
2. Originating event ALREADY COMMITTED: an edit event is appended, and every later render honours it, `board.json` included. Git history is left to the repository's own publication process.

Not asked: weakening append-only history for committed events, or any gate exemption.

Rulings (vc under hv's pen, 2026-09-23, from cc's proposal and gtools-vc's answers):

- NAME: `intent wb edit <kind> <seq> <text> --node <moniker>`, facade `wb_edit`, MCP tool `intent_wb_edit` only if its row's recoverability admits it. `correct` already names `wb register --correct` (a node's name and role), and `amend` reads as git history rewriting.
- SCOPE: every free text a wb verb writes. Stage 1 (items): all six kinds, live AND archived, since `board.json` keeps an archived item's text. Stage 2: message bodies (ask and announce), addressed by recipient and anchor as `--re` is, with the sender as the only writer. Two messages to one recipient in one minute are refused with both named, and the refusal carries a remedy that lets the sender pick one, so no message is ever uneditable.
- FOCUS keeps its one door, `wb pickup --focus`: `wb.pickup` is machine-scoped, so the focus lives in no event file. Stage 2 adds a test proving the old focus is in no file.
- DECLARED OUT: `wb register --correct` records the old name and role (`held_name`, `held_role`) in its event, and the original `wb.register` event carries the old name as well. A node's name and role are participant configuration a human declares, not work text, so they are outside this verb.
- Re-serialisation: no production path rewrites a committed event file (cc's census: `backfill_event_files` skips existing paths, `init` writes a new file, `add_event_files` writes only new events and the amended draft, after git says HEAD does not hold it). The case-2 test asserts the committed file is byte-identical after the edit.

Behaviours, one line each:

- Editing an item whose originating event is uncommitted leaves the old text in no file under `intent/`, events and renders both.
- Editing an item whose originating event is committed appends an edit event, and `board.json`, the board view and `wb show` print the new text, for archived items as well as live ones.
- Only the owning node edits its own item, and only the sender edits its own message; any other node is refused with a remedy.
- An unknown kind, seq or anchor is refused with a remedy naming `intent wb show <node>`.
- The verb has its dispatch row, help and exit codes, and ic reviews that surface before each bank.

Traps: "committed" means present at HEAD, not in the index. intentd ingests disk edits and can revert the last write of a burst, so the edit is verified past the ingest. The verb reaches Gtools only after `bin/devbin build all` (decision 30), and gtools-vc is warned before and after it.

Routing: cc builds both stages, ic reviews the surface, and vc judges.
