**Nothing ran `intent doctor` between a work-package close and the release preflight, so a commit onto a red estate was accepted in silence.**

The pre-commit gate runs the guards and one code critic per declared language. Neither asks the question `doctor` asks: whether the estate's own views, threads, issues and surface still agree with the store. So an estate can accumulate findings indefinitely and every commit passes, because the only thing that reads doctor is a human typing it or the release preflight, which is far too late to be a gate.

Measured on this estate: `intent doctor` reports 284 findings, all of them `generated view is missing` for issue views, and `62d3db243` was accepted over them.

**The ruled fix** (hv, 2026-09-12, in prose, relayed by vc under the pen), three lines:

1. `lib/templates/hooks/pre-commit.sh` runs `intent doctor` through the binary the gate already resolves, after the guards, and REFUSES the commit on a non-zero exit, printing doctor's finding lines so the refusal names the fix. No opt-out flag. Fail-forward: an inherited red is the estate's to clear.
2. One bats arm in the gate's own test file, driven to both verdicts on a fixture project: a red doctor refuses the commit, a clean one passes.
3. One CHANGELOG line under 3.0.2.

The template is the one home, because the gate is the file every project installs; this repository's shim resolves its guards from this tree, so it picks the change up without an install.

**`doctor`'s exit code is the load-bearing part, and it is 1 on findings** -- measured unpiped, because `out="$(intent doctor 2>&1)"; rc=$?` and `intent doctor | tail` do not answer the same question. The first reading taken here was `rc=0` and it was `tail`'s exit code, which is the trap this very gate file warns about in a comment.

**A SEQUENCING CONSEQUENCE THE RULING DOES NOT NAME, AND IT BINDS ON THE LANDING COMMIT ITSELF.** This repository is self-hosted: `~/.intent/home` points at this working copy and the installed shim execs `lib/templates/hooks/pre-commit.sh` from it, so an edit to that file is live for the very next commit -- in every project on the machine, committed or not. While an estate stands red, its own landing commit is refused by its own new rule.

**MEASURED RATHER THAN PREDICTED, ON BOTH COUNTS.** The 284 findings above were the live evidence at filing time and were cleared at `f70441dc2`, so the estate was green before the change was built and the sequencing never bit here. The live-template half was not hypothetical: an in-progress edit to the gate in this tree refused every commit on Laksa, mid-deploy, over 27 findings of its own, until the edit was reverted. **The gate is built in a worktree from now on, and a template in this tree is not a draft.**
