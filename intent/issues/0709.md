`renumber_work_package_in_merge` (`facade.rs:12541-12546`) applies `wp.renumber` with `Subject { kind: "wp", id: <thread id> }`, and the moves appear only in the payload. Every other work package event names its package as `<thread>/<NN>`, eg `wp.new` at `facade.rs:16205`. So `intent events --subject <thread>/<NN>`, which is an exact match (`facade.rs:7138`), never finds the event that moved that package, and an event of kind `wp` names a thread.

Found by cc's census for ST0095, 2026-11-19. Not caused by ST0095.

Fix: either one event per package moved, each naming its package (the one-event-per-entity rule the fiat cascade already follows, `facade.rs:19785`), or kind `thread` if one event is meant to cover the whole thread.
