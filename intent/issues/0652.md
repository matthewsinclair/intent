## What happens

There is no way to get the estate page's URL with its token in it, so the page cannot be opened in a second browser. hv opened the page with `intent estate status --browser`, which opened it in Chrome, then copied the URL from Chrome's address bar into Safari, and the page does not work there. The page's data call, `/op`, needs intentd's token. `--browser` sends it in the URL's fragment, and the page strips the fragment with `history.replaceState` on load (vc's ruling of 2026-09-04), so the address bar holds the bare URL. That stripping is expected behaviour and stays: hv, 2026-10-26, "I know. And that is expected behaviour. Hence the need for the 'Copy URL' menu option and the --url option on the cli." Nothing in the CLI or in Intent.app gives the operator the URL `--browser` opens.

## Expected

hv, 2026-10-26, verbatim: "For the cli version, it should just emit the correct URL so that it can be copied from ther terminal." and "In the menubar app example, I'd just add "Copy URL" as the last item in the menu and it just copies the URL to the clipboard."

- `intent estate status --url` prints the URL that `--browser` opens on stdout and nothing else, so it can be copied from the terminal or piped. Like `--browser`, it refuses when no daemon is answering.
- Intent.app's intentd flyout gains `Copy URL` as its last item, after Restart, and the item puts that URL on the clipboard.

## Where it lives today (measured at 0be4376f7)

- `estate_browse()` in `native/rust/crates/intent-cli/src/render.rs` builds the URL with `served_url`, the token and a root in the fragment, and hands it to `open_url`. `served_url` refuses when no daemon answers.
- The flyout's entries are built in `native/macos/Intent/Intent/Models/DaemonMenu.swift` (Open, Start, Stop, Restart), and `IntentTests/DaemonMenuTests.swift` asserts that list. The Open item already execs `intent estate status --browser` through the `intent` the app resolves (issue 0646 (b)), so the URL has one builder.
- The URL printed and copied carries the token by design: it is the operator's explicit request for the URL that the 2026-09-04 ruling keeps out of the address bar. The fix says how that exposure is handled (the terminal's scrollback, the clipboard, any clipboard manager), and the shared menubar controls of Gtools and Menuz are read before the item is added.

## Shape (vc's order of 2026-10-26 07:23Z, on hv's split)

The split is hv's: cc builds `intent estate status --url`, and ic builds Copy URL.

The contract, vc verbatim: "`intent estate status --url` prints exactly the URL `--browser` opens (estate_browse's served_url result, with the token and root in the fragment), followed by one newline, on stdout and nothing else, and exits 0. With no daemon answering, it refuses as `--browser` does: non-zero, with the refusal on stderr. It opens no browser."

The item, vc verbatim: "Copy URL is the last item of the intentd flyout (DaemonMenu.swift, and the list DaemonMenuTests.swift asserts). It execs `intent estate status --url` through the `intent` the app resolves, the way Open execs `--browser` (0646 (b)), and puts the trimmed stdout on the general pasteboard. It is enabled exactly when Open is."

The item's remaining choices, ic's:

- A refusal is an alert, as Open's is: "Could not copy the web face's URL", carrying the CLI's own error and remedy. A run that exits 0 and prints no URL raises the same alert and leaves the clipboard as it was.
- While a lifecycle verb runs, its caption stands in for Start, Stop and Restart; Copy URL stays last and is held, as Open is.
- The token on the clipboard. The copy is for this Mac only: the pasteboard is prepared with `currentHostOnly`, so Universal Clipboard does not carry it to the operator's other devices. It is marked `org.nspasteboard.ConcealedType`, the nspasteboard.org convention by which a clipboard manager leaves an item out of its history. The app's log names the command and never the URL. Nothing clears the clipboard on a timer, because hv asked that "it just copies the URL to the clipboard", and a timed clear would take a URL the operator has not pasted yet.
- The token lives for one daemon run: intentd mints a fresh one at every start (`Token::mint_under` in intentsvcs's `daemon.rs`, called at intentd's startup). So the flyout's Restart revokes every URL copied before it, and a URL the CLI printed into a terminal's scrollback stops working at the daemon's next start.
- Gtools' and Menuz' menus were read first, and neither has a copy item in a menu. Gtools' `VerbMenu` is the flyout's shape, and its console's Copy button is the pasteboard write this item follows, with the current-host option and the concealed marker added.
