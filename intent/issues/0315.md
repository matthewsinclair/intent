**`sync --to-store` reads an unstaged deletion of a carried attachment as an edit, and then claims a refusal no gate performs.** Measured by courses-vc on the nested Courses estate, 2026-09-13, after carrying seven v2 bucket files into their threads with `st attach`, byte-verifying each against the committed original, and deleting the files from disk so the closed threads could dehydrate: a later `intent sync --to-store` printed `warning: 7 attachment(s) carry bytes no commit contains, and this run takes them into canon`, each path tagged `edited in the working tree and not staged`, then `commit them first if canon should name bytes a reader can obtain -- this run does not refuse, and the commit gate will`. HEAD held byte-identical content for every one of the seven.

**Two defects in one warning.** (1) The instrument is `sync::uncommitted`, which asks `git diff-files --name-only` (worktree against index) and labels every hit `Modified`. A tracked file deleted in the worktree and not yet staged is a diff-files hit, so a deletion is reported as an edit and the bytes are said to be in no commit when the commit that holds them is HEAD. Staging the deletion empties the list, which is the tell: the state being reported is "not staged", not "not committed". (2) The closing clause, _the commit gate will_, names an arm that does not exist: the pre-commit template runs `intent doctor` and refuses on the blocking classes alone, the attachment class is advisory, and an undeclared thread's attachments are not examined at all. The sentence sends an operator hunting for a refusal that never comes, and a warning that promises a consequence which does not follow teaches operators to read past the next one.

**Ruled under the pen, 2026-09-13:** `uncommitted` distinguishes a deleted tracked file from a modified one, reporting it as `deleted in the working tree and not staged, HEAD holds its bytes` when HEAD does; the closing clause states what the gate actually does, which is nothing on this class. One test, two arms: an unstaged deletion of a committed attachment is reported as deleted-with-bytes-in-HEAD, and an unstaged edit is still reported as modified. After the thread.
