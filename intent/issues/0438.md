`intent wb migrate <node> --drop-uncarried` keeps a board's dropped lines and loses an inbox's. vc decision 20 ruled the louder migrator on the ground that nothing is lost: the pre-migration `wip.md` is carried verbatim as a snapshot, so a unit the model cannot carry is dropped from the live board and kept in the record. That holds for `wip.md` and for nothing else.

Found by cc on 2026-09-17, driving a drop on a scratch clone of Conflab's `cc` after the all-estate trawl's first pass. A dropped `wip.md` line was absent from the store before the carry and afterwards was in `cc/.history/pre-migration/wip.md` on disk and in the store. A dropped inbox line (`cleared at fold 17, 2026-08-29`, above the first `## (...)` entry of `cc/inbox.ic.md` and `cc/inbox.dc.md`) was afterwards in no file under `intent/whiteboard/` and not in the store: only `wip.md` is snapshotted (`Project::wb_pre_migration_snapshot` names one file and `Facade::wb_migrate` writes that file's text), and the carry re-renders every inbox from the rows it wrote. The line survives only in the estate's git history, and only where it was committed.

The trawl found 105 such lines across Conflab, Lamplight and Courses, 99 of them hand-written, mostly notes that an inbox was cleared into `.history/`. hv is about to rule what is dropped, and a ruling to drop should cost the same whichever file a unit came from.

What is wanted: every hand-authored inbox that holds a line the carry would drop is kept verbatim beside the board's snapshot, on disk and in the store, by the same path the `wip.md` snapshot takes, and the carry's report names each file it kept. One arm: a drop over an inbox with a lead line leaves that line readable in the snapshot and absent from the rendered inbox.
