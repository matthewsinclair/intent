`intent doctor`'s store-stale check returns with NO finding when a store file exists and will not open. Under the D01 cache model that was defensible; under the reversed D01, where the store is the source of truth, a store that will not open is a finding.

## Where

`intentsvcs/src/doctor.rs`, `db_checks`, the store-stale comparison. Before 0454 the code and its comment read:

    // Only now compare against what is on disk. A cache that will not open is
    // not a finding worth reporting: it is deleted and rebuilt by the next
    // command, which is exactly what D01 buys.
    let Ok(store) = Store::open(&project.db_path()) else {
      return;
    };

0454 made the check return BEFORE opening when there is no store file, so `doctor` no longer creates one. It deliberately left the other branch alone, and the comment now says so: a store that EXISTS and fails to open still returns here without a finding. The same shape follows a line later: `let Ok(on_disk) = store.derived_dump() else { return; };`.

## Why it is a defect now

The reason in the old comment -- "it is deleted and rebuilt by the next command" -- is the D01 cache era's. D01 is reversed: the store is the source of truth, and its own remedies say never to delete it. So an unopenable store is not a cache awaiting a rebuild. It is the project's data being unreadable, and `doctor` is the verb whose job is to say so. Returning quietly is a swallow: silence and a healthy store read the same at this check.

## The shape of the fix

0447's `index_unreadable_without_a_facade` already shows it: when a store exists, open it, and turn a failure into a named finding that says what could not be read, rather than returning. Whether `derived_dump()` failing on an opened store is the same finding or its own is part of deciding this.

## Size

XS to S. One finding class, or a reuse of an existing one, and an arm that plants an unopenable store file and asserts the finding. Low: no harm from it has been measured. What other verbs do on the same unopenable store was not driven for this issue, and deciding the fix should drive it, because it says whether `doctor` is the ONLY verb that stays silent.
