On 2026-10-18 a node launch for one project ran in the wrong directory: `~/Dropbox/Repositories/Devel/<group>/<repo>`, the bare repository that the working copy at `~/Devel/prj/<group>/<repo>` pushes to as `local`. The two share a basename. Nothing in Intent objected:

- `intent init` (event 01M57GPQCJ7T5JV6GSKPSNW80T, 12:45:07Z) created a project inside the bare repository, writing AGENTS.md, CLAUDE.md, .gitignore, .prettierignore and an intent/ tree beside HEAD, config, objects and refs.
- `intent wb register dc` (event 01M57GPSE823KKPMZJQ9EP82CB, 12:45:09Z) registered a node in it.
- `intent claude start dc` found the new `intent/.config/config.json` through `find_project_root` in `intent/plugins/claude/bin/intent_claude_cwi`, changed into the bare repository and launched a Claude Code session there.

The session ran /in-session and a whiteboard pickup before anyone noticed. The project's dc removed the five stray items the same day; the repository's refs and objects were untouched, and git would have refused a commit there, having no work tree. The cost was a polluted remote and a node registered in a throwaway project, but every step was silent.

Repro: `git init --bare /tmp/x.git && cd /tmp/x.git && intent init` succeeds. Do not finish with `intent claude start`: it launches a real session.

Proposed fix, in as few places as possible:

1. `intent init` refuses when the target directory is a bare git repository or inside one (`git rev-parse --is-bare-repository` prints `true`), naming it and saying that a project belongs in a working copy.
2. The project-context gate refuses any command whose project root is a bare repository, so a project already initialised in one, as this one was, is inert.
3. `intent_claude_cwi` makes the same check after `find_project_root`, because it is a script outside the binary's gate.

Acceptance: in a fresh `git init --bare` directory, `intent init` exits 1 and writes nothing; in a bare repository holding an intent/ tree, `intent wb register` and `intent claude start <ws>` exit 1, the latter before launching anything.

Reported by a project's dc (DevX Claude), filed on hv's word.



## The shape

Ruled by vc on 2026-10-22, under hv's word that cc builds 0609 on vc's recommendations. Step 4 is cc's own proposal, which vc accepted.

1. **One predicate, structural, with no subprocess,** in intentsvcs. A directory is a bare repository when it holds `HEAD`, `objects/` and `refs/`, and its `config` says `[core] bare = true`. `config` is read only where all three exist. A project root is refused when it is one, or when an ancestor is, up to the first `.git` entry, file or directory, which is where git's own discovery stops. So a working copy or a linked worktree (whose `.git` is a file) inside a bare repository's directory is never refused because of that ancestor. A root directly inside a bare repository, with no `.git` between them, is refused.
2. **It runs in `Project::open`.** Discover, the general gate behind `context()`, intentd's opens and the registry therefore all refuse a bare root with one typed error. Its remedy names the path and says a project belongs in a working copy: `git clone <bare> <dir>`, then `intent init` there. intentd's handling of that refusal is driven: logged and skipped, never a crash loop.
3. **`intent init` checks its target before any write,** and writes nothing when it refuses. `init.rs` names the config path through `Project::config_path`.
4. **The `claude start` door is the one check.**
   - It resolves the project through `context()`.
   - It reads the node with the facade's `board(ws)`, the call `wb show` makes, which includes unmigrated nodes.
   - It refuses an absent node with the facade's `WbNodeNotRegistered`.
   - Otherwise it runs the launcher from the project root with the workstream and its display name.
   `intent_claude_cwi` keeps only the composing of the session's context and the exec of claude. Its walk-up, its `fm_get` header parse, its rendered-directory check, the `CWI_WB` seam and its bash copy of the refusal all go, so no shell twin of discovery or registration remains.
5. **`WbNodeNotRegistered`'s remedy carries issue 0413's ruling:** an example display name and a one-word role, not the session name, plus the `--correct` sentence. Every verb that refuses an absent node then shows it, `claude start` included. The 0413 arm in `claude_cwi_door.rs` holds the facade's text. ic reviews this wording, and the bare refusal's, before the bank.
6. **Acceptance is driven through the real verbs,** under an isolated HOME, with a fixture `claude` first on PATH that records its arguments and exits. It covers the issue's three refusals, and the success path for both a migrated and an unmigrated registered node.
