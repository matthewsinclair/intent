`Report::unclaimed_digest` (native/rust/crates/intentsvcs/src/organize.rs:1101) hashes each unclaimed path exactly as stored:

    .map(|p| p.to_string_lossy().to_string())

and the stored paths are root-prefixed: `Step.path` is cloned from a walk rooted at `Project::st_dir()` / `Project::issues_view_dir()`, both built from `self.root.join(..)`.

The renderer that prints that digest relativises only the DISPLAY -- `let show = |path: &Path| project.relative(path)` at intent-cli/src/render.rs:6965 -- while the digest is appended to the same summary line untouched (render.rs:7027-7031).

So two values on one line disagree about what a path is, and the digest changes when the project MOVES although the set it summarises has not. A digest whose job is to answer "did this set change" instead answers "did this set change, or did the tree move", and nothing on the line distinguishes the two.

COVERAGE. The one test builds the `Report` directly from relative string literals (intentsvcs/tests/organize_preview_polarity.rs:395), so it never holds a project root and cannot move a tree. It asserts membership-sensitivity and order-insensitivity only. The defect is invisible to it by construction, which is why it survived.

SIZE. `Report` carries no project root, so `unclaimed_digest(&self)` cannot relativise in place. Either a root is threaded in, or `Report` carries project-relative paths from the start so that `show` and the digest stop being two homes for one question. Every recorded digest changes exactly once, whichever is chosen.
