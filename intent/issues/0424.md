`intent wb register`, run with no moniker, reads each node's roster entry from its `wip.md` header. A board whose header lacks `node`, `name` or `role` is skipped: nothing is reported, and the verb exits 0. The roster comes out one node short, and nothing tells the operator.

Found by dc on 2026-09-16 while building the all-estate board trawl, by reading `Facade::register_roster` (`native/rust/crates/intentsvcs/src/facade.rs`). Confirmed by vc at `facade.rs:5774`: the `if let (Some(node), Some(name), Some(role))` has no else arm. The comment directly above it states the rule this breaks: "A silently skipped node is a roster that is quietly short by one, which is indistinguishable from a node nobody has created yet". The code honours that rule for an unreadable header and not for an incomplete one.

It is a defect whether or not any estate holds such a board today. The trawl can only catch one by comparing the roster before and after `register`, and a script running the verb cannot tell at all.

Fix (vc, 2026-09-16), before the release, riding the same rebuild as ic's 0423:
- `register` reads every board's header before any write.
- If any board lacks a field, it refuses with a typed error naming each such board and its missing field(s), with a remedy: add the field to that board's header, or move a directory that is not a node out of `intent/whiteboard/`. The refusal is shaped like `WbSendersNotRegistered`.
- No partial roster is written.
- One arm, red on HEAD: a whiteboard with one complete board and one board missing `role` refuses, naming the second, and registers neither.
- The variant goes through `error_remedies` and `mandatory_fields_reach_a_reader`.
- Any dispatch-row prose that claims otherwise is corrected in the same change.
