**A PROJECT WITHOUT `bin/devbin` CANNOT DECLARE ITS OWN BUILD AND TEST COMMANDS, SO ITS AGENTS.md CAN ONLY SAY THAT NONE IS DECLARED.**

**Where it comes from.** Issue 0672's fix renders AGENTS.md's build and test lines from the project's tree: `bin/devbin` where the tree has one, and otherwise a line saying the project declares no build or test commands, pointing at its README and `usage-rules.md`. The issue's recommended order had a middle step, the project's own declared commands, and that step needs something the tool does not have: `intent/.config/config.json` has no key for a project's build and test commands, and nothing sets one.

**Measured by ic on 2026-11-10.** `intent config set` is declared and unimplemented: `intent config set --help` says "Set one configuration value -- not implemented in this build (exits 2)". So declared commands need a config key, a verb that sets it (either `config set` built for this key or a verb of their own), a dispatch-table row, `intent llm guide`'s entry and tests, and the template's third case. In the fleet survey recorded on 0672, Anvil is the one project without `bin/devbin`: it declares `shell` and `elixir`, and under 0672's fix its AGENTS.md says that no build or test commands are declared.

**Why it is separate from 0672.** 0672's defect is that the contract named wrong commands, and its fix ends that for every project. This is an addition: a way for a project that builds without devbin to name its commands in the contract. vc ruled 0672 down to the devbin case on 2026-11-10, under hv's pen, and asked for this record.
