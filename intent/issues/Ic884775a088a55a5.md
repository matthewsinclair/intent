Steps: a 3.4.0 project on `main` holds ST0001 with package 01 WIP and criterion AC-01.1 unsatisfied. Branch `feat` satisfies the criterion and marks 01 done. Each branch runs `intent upgrade` on its own and commits. `git merge feat` on `main` then conflicts add/add on `intent/.canon/records/ST0001/wp/01.json` and `.../ac/AC-01.1.json`, as I84286b7 says it must.

`intent sync` then refuses with: "both sides of this merge added a work package as ST0001/01 (intent/.canon/records/ST0001/wp/01.json), and taking either side would drop the other side's", and its remedy says to abort the merge, re-create the package with `intent wp new`, carry its objective and body across, and cancel the old one with `intent wp cancel ST0001/01`.

That is wrong for this conflict. Both sides hold the SAME package, created before the branches split, in two states: neither side added a package the other lacks. Following the remedy cancels a real package and re-creates it under a new id, which loses its history and splits its record for no reason.

Expected: sync tells a package both sides added apart (different packages under one ordinal, the case the remedy was written for) from one package both sides wrote apart in the format move (same id, title and history, a different state). For the second, it names the state each side holds and how to take one, eg the side that changed it, rather than offering the re-create.
