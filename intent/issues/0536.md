Reported by gtools-vc on 2026-09-23, measured on Gtools with Intent 3.2.0 at c5cca7e26 while following up gtools-dc's critic-shell read. Reproduced by vc on Intent at 615d86a8a with the same installed pair.

**What happens.** Each shell rule selects the files it applies to by its `applies_to` globs, and the six shell rules declare `bin/*`, `**/*.sh`, `**/*.zsh` and `**/*.bash` between them. A shell script with no extension matches none of those globs unless it sits directly under `bin/`, so no rule is asked of it. The run still counts the file and prints a clean verdict. vc drove one planted script (`#!/usr/bin/env bash`, an unquoted `echo $x`, and `for f in $(ls /tmp)`) through `intent critic shell --files` under three names:

- `plant.sh`: `[CRITICAL] IN-SH-CODE-001` and `[WARNING] IN-SH-CODE-002`.
- `plant` and `.githooks/pre-commit`: `ok: no shell findings at severity >= warning across 1 file(s)`, exit 0.

All three runs print the same census headline, `2 of 6 rule(s) ASKED of this run`, although in the last two no rule was asked of the one file the run was given. Since `bin/*` does not reach below the top of `bin/`, every nested script under `bin/` is missed too.

**The population in Intent's own tree.** Two instruments agree that 200 tracked files carry a bash, zsh or sh shebang. 67 of them match no shell glob:

- the 7 tracked `.githooks/` hooks, pre-commit and pre-push among them;
- 58 scripts nested under `bin/.devbin/`;
- 2 whiteboard `.history/` archives.

Linted as `.sh` through symlinks, these 67 raise:

- three CRITICAL IN-SH-CODE-001 findings in `bin/.devbin/cmd/macos`, at lines 403, 553 and 1168, each an unquoted `$SUPPORT_PATHS`;
- two WARNING IN-SH-CODE-002 findings in the `.history/` archives.

Gtools has six tracked scripts that its gate never lints.

**What the fix has to do.**

- A file that no rule applies to is not reported as clean. The verdict counts only files a rule was asked of, and names the files no rule applied to.
- A script whose shebang names bash, zsh or sh is a shell file wherever it sits, so the shell rules reach it. The mechanism, either the runner reading the shebang or a declared form of `applies_to` that can say so, is proposed with the change. `.history/` archives stay out, because they are append-only records.
- The findings this newly reaches in Intent's own tree are fixed, or exempted with a stated reason, in the same change. Otherwise the gate starts refusing commits that touch `bin/.devbin/cmd/macos`.
