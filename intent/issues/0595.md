**ON A HOST WITHOUT RUST, `bin/int linux doctor` EXITS 127 AND PRINTS NOTHING, ON EITHER STREAM.** That is the one case doctor exists to explain: a fresh Linux machine that cannot build yet.

**What was seen.** kovacs-sysadm ran ST0081's ORDER 2 on hv's Ubuntu VM on 2026-10-14, at b38bc26bc. The clone was clean and matched the pin, and Rust was not yet installed. `bin/int linux doctor` exited 127 with empty stdout and stderr. vc reproduced it on rhadamanth the same day, with bash 5 on PATH through a shim directory and rustc unreachable: exit 127, 0 bytes of output. The control, with rustc on PATH, prints the named refusal ("bin/int linux builds on Linux and this host is aarch64-apple-darwin ...") and exits 1, so the instrument tells the two cases apart.

**What was expected.** doctor exits non-zero and lists every lack with its remedy. The comment above `lacks()` promises this ("Every lack is listed rather than the first, so one install pass readies a fresh machine"), and here the lacks are cargo, rustup with the musl target, and the rest.

**Mechanism, read from the source.** `bin/.devbin/lib/helpers:65` sets `shopt -s inherit_errexit`, and `bin/.devbin/cmd/linux` runs under `set -euo pipefail`. In `host_triple` (`cmd/linux:42`), `host="$(rustc -vV 2>/dev/null | sed -n 's/^host: //p')"` carries rustc's 127 through pipefail into the assignment. errexit then ends `$(host_triple)` there, so line 43's `die`, which names rustup, is never reached, and the `2>/dev/null` has already swallowed bash's "command not found". `cmd_doctor` calls `host_triple` first (`triple="$(host_triple)"`), so the script exits with the same 127. kovacs-sysadm's xtrace ends at `++ host=` followed by the EXIT trap.

**Design point (kovacs-sysadm's).** Even with line 42 guarded, `cmd_doctor` calls `host_triple` before `lacks()`, so a host without Rust gets one message rather than every lack. doctor needs to list the lacks without first requiring the tool whose absence it reports. One way is to take the architecture for the remedies from somewhere other than rustc when rustc is missing. That choice belongs to the fixer: `host_triple`'s comment says the triple comes from `rustc -vV` and never from `uname`, for build and package.

**The proof can run on macOS as well as Linux.** The rustc-missing path is reached before the Linux check. So a bats arm with a shim PATH (bash 5 and no rustc) is red today on the Mac, as vc's run shows, and green once the fix lands. Linux CI and kovacs run the same arm. On kovacs the arm sets PATH explicitly, eg `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`, because hv's zshrc puts `~/.cargo/bin` on PATH in every interactive shell. This body first said that rustup's `--no-modify-path` was enough, and kovacs-sysadm corrected that on 2026-10-14.

ST0081 WP-01 (`bin/int linux` is that package's script). Found by kovacs-sysadm in ORDER 2 on hv's Ubuntu VM. Fixed before the 3.2.4 push.

**The same class at a second site (cc, 2026-10-14).** `bin/.devbin/cmd/macos:226`'s `host_triple` runs `t="$(rustc -vV | sed -n 's/^host: //p')"` under the same shell options, so without rustc its `die` is never reached either. There, bash's "command not found" does reach stderr, because that line does not discard it. 0595's fix covers both sites.
