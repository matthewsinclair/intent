Two defects in the lines intentd writes to `intentd.err.log`. Both are visible in hv's Console screenshot of 2026-09-17 and both were read from the log file itself, so neither comes from the Console's merge.

1. **An ingest failure's remedy line is written twice.** The block stamped `2026-09-16T16:46:51.619Z` (and again at `16:53:18.568Z` and `16:55:02.160Z`) reads `warning: intentd: ingesting ... after an external edit failed: error: could not read the committed canon`, three `caused by:` lines, and then `remedy: fix the artefacts named above, then retry -- run intent doctor to list them` on two consecutive lines at the same stamp. The likely shape is an error chain whose outer and inner errors carry the same remedy and a printer that writes each; the builder confirms it. Those blocks were `database is locked` refusals from before issue 0420, and fixing artefacts is not the remedy for a lock, so the landing also says whether 0420 leaves that path reachable.

2. **The index-refresh notice carries no severity token.** `native/rust/crates/intentd/src/store.rs:663` writes `intentd: could not refresh the index under ...` with a `remedy:` line and no `warning:` or `error:` token. vc's decision 19 (2026-09-15, with issue 0321) ruled that every intentd notice carrying a `remedy:` line gets intentd's existing `warning:` or `error:` token, so that the Console classifies by token and never guesses. vc verified 0321's landing and missed this notice. The builder sweeps intentd's notices for any other line with a remedy and no token rather than fixing this one alone.

Size XS, one crate (intentd), at most one arm per defect.
