**THE MECHANICAL TROPE PASS GIVES DIFFERENT VERDICTS ON THE SAME FILE DEPENDING ON WHICH `grep` THE SHELL SUPPLIES, AND UNDER THE ONE THE RECIPE NAMES, FMT-02 MISSES MOST OF WHAT IT IS FOR.**

**Reported to intent-vc on 2026-11-10 by another board's vc, from a seat that hit it on a real document, and reproduced by intent-vc in Intent's tree the same day.**

**The pattern.** `intent/plugins/claude/skills/in-detrope/data/trope-catalog.md:696` gives FMT-02, bold-first-bullets, as `^\s*[-*]\s+\*\*[^*]+\*\*[:\s]`. IN-PR-STYLE-004 (`intent/plugins/claude/rules/prose/style/mechanical-trope-pass/RULE.md`) has each automated pattern applied with `LC_ALL=C.UTF-8 grep -iE`. Inside a POSIX bracket expression a backslash is literal, so under ERE `[:\s]` is the set colon, backslash and `s`, not colon or whitespace. A bold-first bullet followed by anything but a colon is missed.

**Reproduced on three lines**, one with the colon and two with a space after the bold text:

- `/usr/bin/grep -icE` (BSD grep 2.6.0-FreeBSD): 1.
- `grep -icE` as a Claude Code session on this machine has it: 3. `type grep` answers that it is a shell function from the session's shell snapshot, and it wraps ugrep, which reads `\s` inside a bracket as whitespace.
- perl: 3.

**In the field.** The reporting seat's document held eleven such lines. By its account `grep -iE` reported 0 where perl, ripgrep and GNU `grep -P` each reported 11, and it found the warnings only by reading the pattern as it was meant.

**Why it is more than one pattern.** A greppable rule's verdict is meant to be a property of the rule and the file. Here it is a property of the shell: two agents on one file get different answers, and the more permissive tool hides the defect. The reporting vc's first reproduction returned 3 and nearly became a false contradiction of the seat that had found it. Every automated trope ships its own pattern, and they were written in Perl idiom for an ERE recipe. Read and not driven: the headless runner does not spawn grep at all. It compiles each rule's pattern with the Rust regex crate (`native/rust/crates/intentsvcs/src/critic.rs`, under a comment that says ALWAYS ERE), which is a third reader with a third dialect.

**The ask.**

- FMT-02's set says what it means, eg `[:[:space:]]`.
- Every automated pattern in the catalogue is run under the engine the recipe names, on a line that should match and one that should not.
- One pattern has one reader: the recipe names the tool by absolute path or the runner applies the catalogue itself, and a recipe run under another tool says so.
