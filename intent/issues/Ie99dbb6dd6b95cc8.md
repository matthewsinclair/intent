Found by dc on 2026-11-23 in Ic884775's test fixture, a project whose config.json carries no project_id (Desk run 01M843DQNAHF125RWB2AZ9NTWA, gate rust).

`intent upgrade` mints a project_id when config.json has none (`stamp_version` in facade.rs, through `project::mint_project_id`, a fresh UUID v4). Two branches of such a project, each upgraded on its own, mint two different ids, and the merge then conflicts on intent/.config/config.json, before any record can be merged or `sync` asked.

How likely: low. Every project `intent init` has made since project_id existed carries one, and vc checked all 26 configs on rhadamanth: none lacks it. A project old enough to lack one, with branches upgraded apart, meets it.

Expected: the id an upgrade mints for an unstamped project is derived from something every branch shares, so two branches mint the same one. The repository's root commit is the natural input; with no git, a fresh id, as now.
