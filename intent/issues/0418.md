hv, 2026-09-16, on the explorer's project picker: it should have a progressive search that works like the omnibox, and more than that, it should not be a standalone screen at all. Hoist it into the explorer: `/projects` in the omnibox, and `intent explore` run outside a project, list the registered projects the way the explorer lists threads and issues, and choosing one switches to that project. The standalone picker is retired.

As built (read 2026-09-16, not changed):

- `tui/picker.rs` is its own ratatui loop with its own layout and keys (Up, Down, Enter, Esc) and no filter.
- `/projects` is `Act::Projects`, which exits the explorer with `Exit::Projects`; `render.rs` `explore()` then shows the picker, `enter()`s the chosen root (the working directory) and re-opens the explorer through `explore_here()`.
- Outside a project, `explore()` shows the picker first, because the explorer cannot open without a project's store.

So the picker is the one screen in the explorer with a different IA, different keys and no search.

What this changes:

1. A projects view on the explorer's view stack, with the collections' rows, cursor, keys and Esc-back, filtered progressively by the omnibox's own matcher. Projects are not store entities (the list is the per-user project registry, read through `intentsvcs::projects`), so this is its own view kind rendered like a collection, and the registry is not put into any project's schema.
2. Choosing a project leaves the explorer with the root to switch to; the existing enter-and-reopen loop in `render.rs` does the switch.
3. The registered projects join the omnibox's index, so typing a project's name anywhere offers it.
4. `intent explore` outside a project opens the explorer with no project, where the projects view is the only place and nothing else resolves.
5. A registered root that is no longer a project stays listed and is refused with the reason, as now.
6. `tui/picker.rs` and its loop are deleted; ST0074 WP-04's criteria and tests for the picker (AT-04.1, AT-04.2) are corrected forward to the view that replaces it.
