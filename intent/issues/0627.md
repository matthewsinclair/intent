Measured 2026-10-23 in Molt (intent 3.2.5, board@4.0). `intent wb show hv` answers `messages (0)` and `handled: 6`, and `intent/whiteboard/hv/inbox.vc.md` renders all six in full: four carried from the hand-authored era (headed `2026-09-21 15:40Z`, claimed 8 Sep) and two sent on 21 Oct. hv reads that file, not `wb show`, and asked for the cleared ones to be cleaned out. Nothing can do it:

- `wb clear` marks a message handled in the recipient's `board.json` and, by design, changes no inbox file.
- `wb archive` takes `doing|todo|decision|watchout|hold|directive`, not `message`.
- `wb edit message` changes a sent message's text and marks it `(edited)`; it removes nothing.
- A hand edit to the view is skew that `intent doctor` reports and the next render drops.

So an inbox file holds every message its sender ever sent that recipient, and since the handled state is the recipient's, the file cannot say which of them are handled either. Board-wide in Molt today, every message rendered in an inbox view but two is handled.

0322 fixed this for `wb show` and `wb pickup`, which now print the live messages and a count of the handled ones. The inbox view is the one surface it did not reach, and it is the one the human reads: `hv` has no session loop, and a project's README names a reader for `hv/inbox.*` because the file is the durable surface.

What the fix needs, its shape Intent's call: a retire the SENDER makes, so the single-writer rule and 0612's commit rule both hold. For example `intent wb archive message <anchor> --to <recipient>`, refused while the recipient still has the message live, after which the view drops it, `wb show --all` and the JSON face still list it, and the verb prints the view on its `wrote:` line for the sender to commit. A view that read the recipient's handled marks instead would re-render the sender's file on every `wb clear`, which is the cross-node commit 0612 removed. A fold could then retire everything a node sent that its recipients have handled.

Severity medium: nothing in the store is wrong, and the cost lands on the human at every read of an inbox file.
