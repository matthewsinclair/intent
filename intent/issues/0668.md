**The mechanism, read by intent-vc in Intent's tree at e449dfa2e.**

- `ask` refuses `--place-of` when the prior request has no grant, has no end, has started, or has been revoked (`native/rust/crates/intentsvcs/src/estate/slots.rs:1055-1058`). The revoke clause is explicit, so a request that was granted and revoked before its start is excluded by name.
- `revoke` ends an asked, granted or running request and frees what it held (`slots.rs:1252-1254`). A revoked request is finished (`slots.rs:393-398`), and `release` refuses any request that is not granted or running (`slots.rs:1346-1348`), so the asker cannot bring a revoked request into the state `--place-of` accepts.
- So the only hand-back that keeps a place is the asker's own release of an unrun grant, which `a_hand_back_keeps_its_place_only_from_a_request_released_unrun` pins (`slots.rs:2096`). When the controller pulls a run back before its start, nothing keeps its place.

**Why it matters.** A controller revokes before a start for the reason devbin-vc did here: the machine's load changed between the grant and the start, and a run beside it could put timing failures into evidence a cut depends on. The asker did nothing wrong and loses its place for it. The controller can still grant the fresh ask first by hand, which is the workaround devbin-vc is using, so nothing is lost but the queue's order.

**What a fix has to decide**, which is the reporter's to rule. devbin-vc recommends one of these:

- A revoke before a start keeps the request re-askable with `--place-of`, as an unrun release does.
- Or the revoke itself keeps the request's place, and the controller grants it again when the load allows.

**Ruled by hv on 2026-11-01, by selection in the TUI in devbin-vc's window, relayed by devbin-vc (received by 07:02Z on intent-vc's date -u). hv chose devbin-vc's first option, which intent-vc recommended.** `--place-of` accepts a request the controller revoked before its start, as it already accepts an unrun release. That is one clause in `ask` (`slots.rs:1055-1058`) and no new state.

**vc's reading under hv's ruling, 2026-11-01 (dc asked; the reading is vc's, not hv's).** "Revoked before its start" means granted, then revoked unrun. `--place-of` accepts a request with a grant, no start, and an end or a revoke, with the same-set check unchanged. A request revoked while still asked holds no capacity and stays refused, as do a denied one and one revoked after its start, because "as it already accepts an unrun release" needs a grant.
