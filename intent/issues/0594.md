Found on 2026-10-12 while judging a bank in a worktree named `tmp/wt-cc-clippy199`.

**The defect.** The arm "no arm in the suite skips because an armed tool is absent" (`tests/unit/armed_tool_preconditions.bats:116`) runs `grep -n 'skip' "${INTENT_PROJECT_ROOT}"/tests/unit/*.bats`. With more than one file, every output line begins with that file's full path. It then runs `grep -F -- "$tool"` over the whole line for each armed tool. So when the checkout's own path contains an armed tool's name, every `skip` line matches through its path, and the arm reports the suite's own lines, including its own lines 116 and 128, as offenders. The armed set (`armed_tools`, `tests/lib/test_helper.bash:314`) is every rule's `critic_tool` plus staged-format-guard's unenforced tools, so a clone or worktree under a directory named for clippy, shellcheck, prettier or rustfmt fails the arm for nothing.

**Driven both ways at 7851c5a09.** A clean worktree named `tmp/wt-cc-clippy-base` fails the arm (rc 1). The same tree, renamed with `git worktree move` to `tmp/wt-cc-c199-base`, passes it. A bank tree named `tmp/wt-cc-clippy199` failed it, and passed once renamed to `tmp/wt-cc-c199`.

**Fix direction.** Match the tool against the line's text after the `file:line:` prefix, for example with `grep -h` in the first grep, or by cutting the prefix before the tool grep. Keep a control: a planted skip line that names an absent armed tool must still be reported.

**Severity: low.** It is test-only and fails toward a false red in a checkout under such a directory, never toward a false green.

## Resolution

Fixed by 086e98b71 for 3.2.4: `tests/unit/armed_tool_preconditions.bats` runs its tool grep over each line's text rather than its file path, so a checkout whose path names an armed tool no longer reds it.
