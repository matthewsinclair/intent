The test `intent init on a scratch project substitutes all placeholders` in `tests/unit/claude_md_template.bats` writes `printf '{"author":"TestUser"}\n' > "$HOME/.intent/config.json"`, and its comment says HOME is the test's sandbox.

It is not. `setup_fake_home` in `tests/lib/test_helper.bash` is what redirects HOME into `$TEST_TEMP_DIR/fakehome`, and it is opt-in: a test calls it from an overridden setup() or inline. This file never calls it, and the shared `setup()` only creates `TEST_TEMP_DIR` and changes into it. So the write lands in the operator's real `~/.intent/config.json`, replacing the whole file: the real author and every explorer setting are gone.

Evidence, read 2026-09-13: hv's `~/.intent/config.json` is exactly `{"author":"TestUser"}`, last modified 2026-09-12 21:30. `grep -rn TestUser` finds this file as the only writer of that value.

Remedy: call `setup_fake_home` in this test (and `teardown_fake_home` in teardown), and sweep the other .bats files for writes under `$HOME` that do not. Restoring hv's real config is hv's call: `author` comes from `intent bootstrap`, which also repoints `~/.intent/home`.
