`intent wb migrate`'s uncarried list cannot tell a sub-heading or board lead that carries state from one that is a date, and an italic section intro carries as an item.

**Seen 2026-09-19** in Lamplight's whiteboard carry, checked by each node against its pre-migration copy:

- hv's sub-heading `### Still live from 2026-08-19 -- the two rulings that are NOT executed` was class 4 and dropped, and with it the only marker that those two rulings were unexecuted, so they read as history until re-marked by hand.
- ic's board lead held every TODO behind hv's fences; dropped, the carried TODO read as actionable until ic re-added the fence as a hold.
- dc's `todo 1`, `hold 1` and `watchout 1` were italic section intros, not items; dc archived them after the carry.

Most sub-headings are dates and safe to drop, and the plain pass names every unit it will not carry, but it names them all alike, so a node dropping them under `--drop-uncarried` has no signal that one of them holds a state the items below depend on.

**The ask:** the plain pass's uncarried list marks a sub-heading or lead whose text carries a marker word (`NOT executed`, `held`, `blocked`, `until`) or that precedes items as needing a read, and an italic-only line is reported as an intro rather than carried as an item. Sized after 0488's fix, since both touch the same classifier. S.

## Narrowed (cc, 2026-09-20, on vc's ruling, after the report was measured)

**The second ask is WITHDRAWN, and it is withdrawn because its premise was false.** It asked that an italic-only line be reported as an intro rather than carried as an item, on the understanding that a lead sentence carried as a work item went unreported. It does not go unreported. `wbmigrate.rs`'s `blocks_to_items` returns a per-item flag that is true for a bullet, the item is built with `coerced: !bullet`, and the migrate report prints a line for every coerced item: "coerced: [<kind>] <at> -- <first line>", with the reason "section prose, not a list entry, carried as one item". That line exists for exactly this case, under vc decision 20 and issue 0404, whose words are that prose carried as an item is said to be and never silently.

**So the design was already right and the change would have cost more than it bought.** Making such a block uncarried would refuse the carry unless `--drop-uncarried` is passed, and `--drop-uncarried` cannot carry selectively: a state-bearing lead under DOING would then leave the board altogether. That trades a visible, flagged item for a dropped one, which is the wrong direction for the failure this issue is about.

**What remains is one classifier serving two report lines.** The marker asked for in the first half -- a sub-heading or lead whose text carries a marker word (`NOT executed`, `held`, `blocked`, `until`), or that precedes items, is marked as needing a read -- applies to the `coerced:` line as well as to the `uncarried:` list. One classifier, both lines, so an operator reading either can tell a lead that looks state-bearing from a decorative one. **The report still decides nothing**: it marks, and the person reads.

**And the narrower case, for the record:** an italic intro under a heading the protocol does NOT name already goes to `uncarried` today, by the arm that refuses a section no `WbItemKind` carries. So the withdrawn ask only ever bit under protocol-named headings, which is where the three observed instances were.
