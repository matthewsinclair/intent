Intent 3.5.6, hv decision 118. The scope comes from ic's read of the code on 2026-11-26.

With ArcaLaunch's instance lock (ic's part, in its own issue), the running copy wins. A new copy that starts while the old copy exits hands over and quits, and then no Intent.app runs.

In `bin/.devbin/cmd/macos`, `cmd_app_run` (near line 1983) and `cmd_app_install` (near line 2060) send the quit through osascript and do not wait for the exit. This file is Intent's own: devbin's manifest lists only `bin/.devbin/lib/cmd/macos`, and says that `cmd/` belongs to the project. So the fix needs no devbin release.

The fix, size XS, owner dc: each step waits for the old copy to exit before it starts the new one.

cc has no part: `intentsvcs::macapp::stop` already waits for the exit before restart opens the app.

Proof: dc names it.

Resolution: Landed at fc33a251a (bank refs/bank/dc/i8b74/v1, patch-id 5f0f5f7b2778). Live proof at d4e0733b4 with ic's lock in place: bin/devbin macos app-run stopped the lock holder (pid 5824) before it started the new copy, and the new copy (pid 28543) runs and holds instance.lock.
