Intent 3.5.6, hv decision 118. The scope comes from ic's read of the code on 2026-11-26. ic built, ran and changed nothing for that read.

Today Intent.app has no test-host check and no instance lock. Its tests run with the app as TEST_HOST, so every xcodebuild test runs the app's launch path, with its polls that run intent.

The fix, size S, owner ic:

- Add the ArcaLaunch product of arca_swift 0.3.0 to the app target. The pin is already 0.3.0 (upToNextMinor), and the app links only ArcaMasthead today.
- Make `guard ArcaLaunch.begin(app: "Intent", log: ...)` the first line of applicationDidFinishLaunching, and `guard ArcaLaunch.launched` the first line of applicationWillTerminate.
- Add one app test that is red on today's code: the test host starts no launch path, eg no poll.
- Add a CHANGELOG line.

The app has no sandbox, so the lock file is `~/Library/Application Support/Intent/instance.lock`. Debug and Release builds share it, so only one of them runs at a time. hv accepts this (hv decision 118). The menu does not change.

Proof: one Xcode build-and-test, red on today's code and green on the bank, on a Desk slot that ic asks for through vc.

The steps that start the app must wait for the old copy to exit. That is dc's part, in its own issue.
