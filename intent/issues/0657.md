`intent install` (intentsvcs/src/install.rs, the `id.head != sha` arm) refuses whenever HEAD differs from the commit the pair was built from: "HEAD (...) has moved past the commit the pair was built from (...)". On a shared dev tree every board or doc commit moves HEAD, so a pair built moments ago is refused for a commit that cannot change a byte of it.

The fix (S, hv's ruling A, 2026-10-26): judge currency the way the pre-commit self-provenance arm and devbin's currency.lib already do. Refuse only when a commit between the built sha and HEAD touches the build-input scope, the marker's DIRT_SCOPE (native/rust, surface, docs/design, lib/templates/llm, lib/templates/prj), or a support path install copies. Name the first offending path in the refusal. A HEAD that moved only outside that scope installs, and says it did.

One scope, one declaration: read the scope from where the marker declares it, never restate it in install.rs (Highlander). Arms: HEAD past the build by a board-only commit installs; by a native/rust commit refuses naming the path; by a support-path commit refuses; an unreadable git still refuses.
