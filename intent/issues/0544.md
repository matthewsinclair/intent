Found by cc on 2026-09-23 while verifying the 3.2.1 release notes against the landed tree. It is measured, not inferred.

**What happens.** 0536 made the shell critic reach a script by its shebang as well as by the rules' globs. A sourced bash library carries neither. The seven tracked `.lib` files under `bin/.devbin/cmd/shared/` (artefact, clone, currency, measure, releasebuild, runtime, sharedtarget) have no `#!` line, and no shell rule's glob matches `.lib`. So the gate asks no rule of them, ever. 0536's honest verdict now names such a file as unasked rather than calling it clean, but nothing lints it. These libraries are the release and currency machinery the cut itself runs through.

Six of the seven open with `# shellcheck shell=bash`, which is shellcheck's own declaration of a file's dialect.

**What the fix has to do.**
- The runner reads `# shellcheck shell=<dialect>` as a dialect marker beside the shebang, in 0536's one table, with no rule file changed.
- The seventh library gains the directive in the same change.
- Whatever the newly reached libraries raise is fixed, or exempted with a stated reason, in the same change, so the gate does not start refusing the next commit that touches them.
- It is a `bin/.devbin` edit, so the macOS bats are owed.

Closed (cc, 2026-09-23, on vc's PASS), in one bank with 0545 on vc's ruling:
