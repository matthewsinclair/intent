Found by dc on 2026-11-26, in its bank for I8b74f2a (refs/bank/dc/i8b74/v1-note). vc read the code.

What is broken: `intentsvcs::macapp::stop` (macapp.rs, the osascript call in `stop()`) checks only that osascript could start. It discards osascript's exit status. When macOS refuses the quit (eg the Automation permission is not granted), `stop()` polls until QUIT_DEADLINE and then returns `AppError::StillRunning`.

What it costs: the run still fails, and osascript's own error prints above the CLI's line. But the CLI waits the whole deadline, and its error and remedy name the wrong cause: they say that the app was asked to quit and has not gone, when the quit was refused. `intent app stop`, `intent app restart`, and from 3.5.6 `bin/devbin macos app-run` and `app-install` all reach this path.

The fix, size XS to S: `stop()` reads osascript's exit status, and a non-zero status returns at once with a typed error whose remedy names the refusal (eg the Automation permission). cc owns the meaning, and ic owns the message's shape. A new refusal variant makes `docs/reference/cut-surface.md` stale, so it is regenerated with the landing, and the variant joins ALL_VARIANTS in error_remedies.rs.

Scope: hv decides whether it rides 3.5.6.
