Found by dc on 2026-11-26, in its bank for I8b74f2a (refs/bank/dc/i8b74/v1-note). vc read the code.

What is broken: `intentsvcs::macapp::stop` (macapp.rs, the osascript call in `stop()`) checks only that osascript could start. It discards osascript's exit status. When macOS refuses the quit (eg the Automation permission is not granted), `stop()` polls until QUIT_DEADLINE and then returns `AppError::StillRunning`.

What it costs: the run still fails, and osascript's own error prints above the CLI's line. But the CLI waits the whole deadline, and its error and remedy name the wrong cause: they say that the app was asked to quit and has not gone, when the quit was refused. `intent app stop`, `intent app restart`, and from 3.5.6 `bin/devbin macos app-run` and `app-install` all reach this path.

The fix, size XS to S: `stop()` reads osascript's exit status, and a non-zero status returns at once with a typed error whose remedy names the refusal (eg the Automation permission). cc owns the meaning, and ic owns the message's shape. AppError is not a FacadeError and the facade does not wrap it, so the new variant does not join ALL_VARIANTS in error_remedies.rs, and `docs/reference/cut-surface.md` does not go stale. AppError's remedy coverage is `implements::<AppError>()` in remedy_coverage.rs and the exhaustive match in `remedy()`. (Corrected forward on cc's read of the code: vc's first text said the variant joins ALL_VARIANTS and makes cut-surface.md stale.)

Scope: hv decides whether it rides 3.5.6.

Resolution: Landed at 1a9bc8702 (bank refs/bank/cc/i47c94cf/v1, patch-id 16ae54ace4e4): a failed quit returns AppError::QuitFailed at once, with a remedy that names the Automation permission. Proof: clippy with no finding and the macapp unit tests, one of which fails if stop polls after a failed quit. Rides Intent 3.5.6, under hv's rule that a fix found during the release goes into it.
