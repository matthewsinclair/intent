`src_sections.name_parts` is never filled, so the words inside a CamelCase name are not searchable.

ST0069's design (T1) and the `src_sections` DDL say a `name_parts` column makes the words inside a camel-cased name searchable. The only producer of a `src_sections` row, `index::source::whole_file` (`intentsvcs/src/index/source.rs:47-60`), leaves `kind`, `name` and `name_parts` empty, and T2's symbol rows went to the separate `symbols` table rather than into `src_sections`.

So the column is empty in every store: `Removal` does not find `SkipRemoval`, only the prefix form reaches a CamelCase name from its start, and the measured inner-fragment recall on CamelCase (none, under `unicode61`) stands with no mitigation.

Remedy: fill `name_parts`, eg per file from the names the `symbols` rows for that file define; or rule the column unused and drop the claim from the design and the DDL comment.

Found by the as-written against as-built audit of ST0069, 2026-09-13.
