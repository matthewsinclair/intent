This repository had THREE behaviours for one situation -- a suite arm whose subject is an armed tool that is not installed -- and the worst of them was the default.

**Found by a red CI run on 2026-09-22**, run 35739715195, sha 940e07ee8, both legs identically. Two arms of `tests/unit/staged_format_guard.bats` failed: 624 "unformatted staged Markdown is refused" and 627 "prettier judges the blob under the config the file's OWN path resolves". The guard was working exactly as designed. Neither GitHub runner ships prettier, `tests.yml` did not install it, and `staged-format-guard.sh:197` correctly reports `UNENFORCED -- markdown(prettier)` and returns 0 -- while both arms assert status 1. **An arm asserting a REFUSAL requires the tool to be PRESENT, and that is a precondition on the environment that no local run can expose**, because the dev machine has prettier from Homebrew.

## The three behaviours

1. **PANIC.** `require_prettier()` in the Rust suite aborts deliberately when prettier is absent. Its own reason, quoted in `rust.yml:89-93`: "a skip here is a green that means nothing, on a criterion about instruments that pass without measuring."
2. **SKIP.** An existing bats arm degrades silently. Visible in the very run that went red: `ok 160 a fmt sweep leaves every fenced root markdown byte-identical # skip prettier unavailable offline`. It reports `ok`.
3. **ASSERT AND FAIL UNINTELLIGIBLY.** The new guard arms, which say only that `[ "$status" -eq 1 ]` failed. A reader of that output cannot tell a broken guard from a missing tool.

**Three homes for one question is the Highlander shape**, and the three disagreed about whether a missing tool is fatal, invisible, or a test failure.

- The source lines were **still present** at `f80d5a9ea`: `tests/unit/devbin_fmt_md.bats:72,74`, a `command -v npx || skip` followed by an `npx --no-install prettier --version || skip`.
- What changed between the two runs is not the file. `e0f030bb0` installed prettier, so the arm now gets PAST the tool probe and reaches a DIFFERENT skip fifty-three lines later, over the corpus.

**So installing the tool did not remove the skip; it hid it.** The arm would emit the same line again on the first runner that lacks prettier. That is this issue's own thesis arriving one level down: a fix aimed at the case that was reported, leaving the hazard that was found.

## THE MEASURED SHAPE IS THREE CLASSES, NOT THREE BEHAVIOURS (vc's census, 2026-09-22)

"Three behaviours" was a framing taken from one instance. A census of every skip in the green run 35743714571 -- eleven per leg -- finds three CLASSES, with a spelling problem inside one of them. Counts are across both legs; halve for one leg:

```
8  # skip elixir not on PATH
8  # skip elixir not installed
2  # skip Elixir not installed
2  # skip no root fence currently holds content prettier would reformat ...
2  # skip /bin/bash is 5.x -- these controls describe 3.2 behaviour and cannot be driven here
```

The three classes, which are not one problem and must not get one fix:

- **ARMED TOOL ABSENT.** The arm's subject is an instrument's own verdict and the instrument is not there. Nothing to report; this is the panic case.
- **NO WITNESS.** The corpus holds no member the claim could be shown on, so the arm cannot fail whatever the code does. Vacuous. A tag is the marker, not the fix -- the honest answers are to plant a witness or delete the arm.
- **OTHER SYSTEM.** The arm describes a system this machine is not: a 3.2 `/bin/bash` on a 5.x host, or a fixture PATH the host cannot supply. A skip here can be correct.

**NINE ARMS PER LEG SKIP BECAUSE ELIXIR IS ABSENT, IN THREE SPELLINGS, TWO OF WHICH DIFFER ONLY IN CAPITALISATION.** As originally filed this issue named prettier and nothing else, so it understated its own class by an order of magnitude.

**AND ALL THREE PRINTED `# skip` AND READ AS `ok`, WHICH IS HOW THE ONE THAT IS A DEFECT HID BEHIND THE TWO THAT ARE NOT.**

## THE ELIXIR FORK, MEASURED AND NOT DECIDED HERE

One correction to the census's framing, because it changes which argument applies. **No elixir rule declares `critic_tool:`.** Driven with PATH scrubbed to `/usr/bin:/bin`: `intent critic elixir` asked 8 of 19 rules and returned rc=0 without refusing, because those 8 are armed on PROXIES rather than on the elixir binary. So elixir is **not** armed in the sense shellcheck and prettier are, and the fail-closed argument that carries those two does not reach it.

What the nine arms actually need is the elixir **runtime**: five in `test_autopsy.bats` drive `autopsy.exs`, four in `rule_pack_elixir_runnable.bats` execute each rule's `good.exs`. Neither workflow installs elixir -- `grep -c 'elixir\|erlang\|beam'` returns 0 for both files. The consequence is identical to the armed case even though the reason differs: nine arms per leg report `ok` having measured nothing, and have never run in CI.

**The fork, with the cost on each side, for vc and hv:**

- **Install elixir in CI** (`erlef/setup-beam`, roughly 30-60s per leg). Nine arms per leg start running, including the whole of the autopsy detector's behaviour -- a shipped script with a measured precision story and no CI coverage at all today. Cost: two more install steps and their maintenance, on a suite that is otherwise toolchain-light.
- **Declare them environment-gated.** They become `OTHER SYSTEM` skips with an honest reason, cost nothing, and the autopsy detector keeps its zero CI coverage.

**ic recommends installing it**, on the same ground that already carries prettier and shellcheck: both have install steps precisely because something depends on them, and the autopsy arms are the only coverage a shipped script has. But this is a real fork with a real cost and it is recorded rather than taken.

## What was owed, and what landed

The bats suite needed the PANIC form: a `require_prettier` equivalent that fails with the tool NAMED, so a missing tool reads as a missing tool rather than as a guard that stopped refusing.

- **`require_tool <tool> <subject>`** in `tests/lib/test_helper.bash`. Fails the arm, names the tool, names what went unmeasured, names the install and the waiver. It cannot share CODE with the Rust `require_prettier` -- different language -- so the two are bound by VOCABULARY: both honour `INTENT_ALLOW_MISSING_<TOOL>`, so one env var serves both suites. That is the part that would silently diverge, so that is the part made identical.
- **`armed_tools()`**, discovered from two declaring surfaces rather than listed: the rule library's `critic_tool:` frontmatter and `staged-format-guard.sh`'s own `UNENFORCED <lang>(<tool>)` lines. Today: clippy, mix, prettier, rustfmt, shellcheck.
- **`skip_no_witness` and `skip_other_system`**, so the other two classes are tellable apart in the CI log itself. The output now reads `# skip NO WITNESS: ...` and `# skip OTHER SYSTEM: ...`.
- **`build_no_tool_path`** moved from `critic_arming_census.bats` into the shared helper and generalised past shellcheck, with its reasoning. A second copy would have been the exact shape this change exists to remove.
- **`tests/unit/armed_tool_preconditions.bats`**, six arms: the discovery premise, `require_tool` driven to BOTH verdicts under a constructed absence of a real armed tool, the waiver proved to say NOT MEASURED rather than to pass, and two censuses -- no arm skips on a missing armed tool, and every skip declares its class. The elixir nine are on a named exception list so the open fork stays visible and cannot quietly grow a tenth member.

**NINE OF THE TWELVE ARMS IN `staged_format_guard.bats` CARRIED AN UNDECLARED TOOL PRECONDITION, NOT TWO.** Four on prettier, five on rustfmt. The two CI named are the two that asserted a REFUSAL; the others assert an ABSENCE, which a missing tool satisfies for free. Measured in the same red run:

```
not ok 624  unformatted staged Markdown is refused        <- red, unintelligibly
not ok 627  prettier judges the blob under the config     <- red, unintelligibly
ok     620  a staged deletion passes                      <- GREEN, VACUOUSLY
ok     621  a staged binary blob is skipped               <- GREEN, VACUOUSLY
```

With prettier absent the markdown branch never iterates a file at all, so 620 and 621 held for a reason unrelated to anything either arm is about. **An arm asserting the absence of an output is the one a missing tool satisfies for free.**

## A SECOND UNDECLARED DEPENDENCY, FOUND BY THE SAME QUESTION

`tests.yml` uses `dtolnay/rust-toolchain@stable` at **two** sites, `test-linux` and `test-macos`, and neither carried `components:` -- while `rust.yml:75-77` has always carried `components: rustfmt, clippy`, three lines under a comment in `tests.yml` claiming "Same toolchain and cache setup as `rust.yml`".

**The evidence is that arms 617 and 626 PASSED, which proves rustfmt is PRESENT and proves nothing about anything DECLARING it.** 617 asserts a refusal and 626 asserts the verdict names rustfmt's default edition; neither can pass with rustfmt absent. What supplies it is the runner image, which this repository does not control.

The argument against leaving it is already written in this repo, at `rust.yml:92-97`, refusing a `rust-toolchain.toml`: *"a pin that does not bind is worse than no pin: it does not refuse, and it misleads."* This is that argument's mirror image -- a dependency not declared at all, satisfied from outside the repository. The day an image drops rustfmt, those arms go red pointing at THEMSELVES, and whoever reads it starts by suspecting the arms, because nothing in the workflow ever said rustfmt was required. Declared at both sites.

## Why it survived, which is the part worth keeping

**The lesson was already written in this repository, as a prediction, in the neighbouring file.** `.github/workflows/rust.yml:96-99`: "NEITHER RUNNER SHIPS PRETTIER ... Without this step the prettier arms fail on BOTH legs while passing locally: the primary dev machine has prettier from Homebrew, so a local green does not show the runners lack it."

That is this incident's postmortem, written weeks in advance, naming both legs, naming Homebrew, and naming the false local green. It was not consulted. vc read all three workflow files the same morning while measuring an unrelated question about `paths-ignore` and did not connect it.

**And the judging failed the same way.** vc judged 0505's twelve arms and did not take dc's log -- it re-ran the suite itself and got 12/12. That felt like verification and was not: the same instrument on the same box, which adds confidence and no information. The question that would have caught it is not "do these arms pass" but **"where could these arms fail"**, which for an arm asserting a refusal is answered by naming what must be installed for a refusal to be possible at all.

**That question is what found everything above** -- the seven further undeclared preconditions, the two undeclared toolchain components, and the nine elixir arms -- so it is recorded as the acceptance test for this class and not only as this incident's lesson.

**ONE MORE WORKED EXAMPLE OF THE SAME SHAPE, from devbin-vc, unprompted.** Its first fix here added a bare `npm install -g prettier@3` copied from `rust.yml`, which passed on macOS and went EACCES on Ubuntu -- because `tests.yml` PREPENDS `/usr/local/bin` to PATH on the Ubuntu leg and APPENDS it on macOS, so a different npm with a root-owned prefix won. **A step depending on ambient PATH ORDERING fails differently per platform, which is the same shape as an arm depending on an ambient TOOL.** Its own `--version` check is what made it fail loudly and in the right place.
