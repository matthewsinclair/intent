After the first merged, the forge could merge none of the other four: each conflicts with main in `intent/.intentfiles`, `intent/st/steel_threads.md` and `intent/todo.md`, because every branch that starts a thread appends to all three at the same place. A forge runs no hook and cannot run `intent sync`, so each author updates the branch by hand before each merge, once per merge request, in sequence.

ST0095 takes the id collisions out of this flow and leaves this as the hand step in it.

It needs a ruling before a fix: whether the two aggregate views stay tracked (they are generated, and any clone regenerates them), and whether realisation stays one shared manifest or becomes a fact each record carries. Put to hv in ST0095's design, "For hv", point 4.
