Found by vc on 2026-09-23 while checking the 3.2.1 cut against 0518. Measured by driving the verdict function in a scratch clone, not by running the release step.

**What happens.** 0518 (aba799696) made the pre-push runner refuse a push when the delivered pair under `native/rust/target/release` is behind HEAD in the build-input scope. `bin/devbin build release` commits the version bump, which changes `native/rust/Cargo.toml` and `Cargo.lock`, tags it, asks for confirmation, and then pushes `main` and the tag to both remotes. It builds only debug binaries, the stamp CLI and the cargo gate, and never rebuilds `native/rust/target/release`. So at its push the pair still names the commit before the release commit, `artefact_currency_verdict` refuses, and the release step stops with the release commit and the tag made locally and nothing pushed.

The drive, in a scratch clone of 361090227, with `artefact_currency_verdict` read over this machine's pair at 9dac092ea:

- at the clone's HEAD it printed `ok`;
- after one commit changing the workspace `version` line in `native/rust/Cargo.toml` from 3.2.0 to 3.2.1, it printed `refuse:1 non-test file(s) under native/rust, surface, docs/design, lib/templates/llm, lib/templates/prj changed since 9dac092ea236 -- this binary is behind HEAD`.

`--dry-run` cannot see this because it does not push, and no test drives a release push through the pre-push hook. 3.2.1 is the first cut since 0518 landed.

**Workaround, until the fix lands.** When the release step asks to push, run `bin/devbin build all` in a second terminal first, so the pair is built at the tag, then confirm.

**What the fix has to do.**

- The release step's push passes the pre-push check without anyone running a second command, or the release step refuses before it stamps anything and names the order.
- The pre-push check keeps refusing a stale pair on every other push.
- A test drives a release push through the pre-push hook.
- `intent/docs/releasing.md` steps 3 and 4 say what the release step now does, including whether step 4 still opens with `build all`.
