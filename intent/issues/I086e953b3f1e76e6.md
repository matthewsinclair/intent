Three facade reads of the manifest (`intent/.intentfiles`) turn an unreadable file into "no manifest" with `.ok()`, so an I/O or permission error is swallowed instead of refused with a remedy (IN-AG-NO-SILENT-001). A fourth treats an unreadable file as "differs" and rewrites it rather than reporting it.

Found by critic-rust on ST1c2db93 U2 (cc, 2026-11-23), whose `read_manifest` is the read that raises `ManifestUnreadable`; these sites are not yet routed through it. Line numbers are as of U2's tree:

- `native/rust/crates/intentsvcs/src/facade.rs` ~18404, `set_thread_status_fiat`: the rollback snapshot reads `std::fs::read_to_string(&manifest).ok()`.
- facade.rs ~21971, `issue_add`: `std::fs::read_to_string(self.project.intentfiles_path()).ok()`.
- facade.rs ~22235, `set_issue_status`: the same read.
- facade.rs ~23391, `restore_manifest`: `read_to_string(&manifest).ok().as_deref() != Some(..)` rewrites the file instead of reporting that it could not be read.

`repin` (~14939) also reads inline but raises `ManifestUnreadable`, so it is not a swallow.

Fix: route each through `read_manifest` (or its error), and keep a snapshot's "there was no file" distinct from "the file could not be read".
