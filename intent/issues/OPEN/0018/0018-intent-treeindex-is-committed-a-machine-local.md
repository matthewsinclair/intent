# 0018: intent/.treeindex/** is committed: a machine-local derived cache is tracked as project state, and nothing ignores it

## Tags

treeindex, hygiene, gitignore, portability, derived-state

## Summary

`intent treeindex` writes its directory summaries into a shadow tree at `intent/.treeindex/`, and that tree is committed: 88 tracked files in this repository, none of them ignored by any `.gitignore` at any level. The cache is derived state (each file carries a `fingerprint:`/`generated:` stamp and is regenerated by the tool), it is machine-flavoured (multiple cache files embed `/Users/...` absolute paths -- 11 in one file -- the exact class issue 0016 removed from `settings.json`, live in a public repository), and it goes stale silently (the sampled `bin/.treeindex` is dated 2026-04-23 and still describes an `intent audit` command that was retired in v2.11.12). It is also why the issue-0016 guard could not sweep the whole repo and had to scope itself to `.claude/` -- the tracked cache was the known source of absolute paths.

Filed by vc on a direct hv ruling (2026-08-13): "I have no idea why any of that is checked in. It shouldn't be. It's local dev-x optimisation, not project memory."

## Reproduction

```
$ git ls-files | grep -c '^intent/\.treeindex/'
88
$ git check-ignore intent/.treeindex/bin/.treeindex; echo $?
1                                    # nothing ignores it
$ grep -c '/Users/' intent/.treeindex/examples/v1.2.0-project/.treeindex
11                                   # machine-local absolute paths, tracked, public
$ head -1 intent/.treeindex/bin/.treeindex
<!-- treeindex v1 fingerprint:2a019cca generated:2026-04-23T16:15:53Z -->
```

## Root Cause

The treeindex feature shipped with an _indexing_ exclusion mechanism (`.treeindexignore`, templated at `lib/templates/_treeindexignore`, whose own patterns exclude `.treeindex/` from being indexed) but no _git_ exclusion anywhere: not in this repo's `.gitignore`, not in `intent/.gitignore`, not in any template (the tool ships no `.gitignore` template at all), and not in the gitignore-normalisation seam `intent claude upgrade --apply` already runs for `.claude/settings.local.json`. The cache was committed by default because nothing said otherwise, and every consumer project inherits the same default.

## Impact

- A machine-local cache with absolute home-directory paths is published in a public repository (the 0016 class, at ~88-file scale).
- The tracked copy goes stale without any signal -- the committed `bin/.treeindex` describes commands that no longer exist -- so the "project memory" it appears to be is wrong, which is worse than absent.
- Diff noise: regenerating locally dirties the tree with content-free churn, and different machines regenerate different bytes.
- The 0016 guard (`no_absolute_home_paths.bats`) had to exclude the whole area, leaving the repo's absolute-path invariant enforced only for `.claude/`.
- Fleet-wide: consumer projects (Utilz, Lamplight, Baize) inherit the same default and likely track their own caches.

## Proposed Fix

1. **This repo:** `git rm -r --cached intent/.treeindex/` and add `intent/.treeindex/` to the root `.gitignore`. Everything under the directory goes: the summaries are regenerated by the tool, and `.treeindexignore` + `README.md` are re-laid-down from `lib/templates/` (hv's "any of that" reading -- nothing under the shadow tree is project memory).
2. **Tool/template:** upsert `intent/.treeindex/` into the consumer's `.gitignore` via the existing gitignore-normalisation seam in `intent claude upgrade --apply` (the same mechanism that maintains the `.claude/settings.local.json` line), so the fleet converges on its next `intent upgrade` -- the v2.18.0 reach lesson. The upgrade must not run `git rm` in a consumer repo; where it detects tracked `.treeindex` files it should PRINT the one-line command for the human to run.
3. **Guard:** extend or twin `no_absolute_home_paths.bats` with the tracked-cache assertion (`git ls-files intent/.treeindex` is empty), which also lets the absolute-path guard drop its treeindex carve-out.
