**UNDER `brew services`, INTENTD'S LOG GOES ONLY TO BREW'S `log_path`, AND `intent daemon logs` READS A FILE NOTHING IS WRITING.**

**Measured by gyges-sysadm on gyges on 2026-10-31, on Intent 3.2.8 from the tap.** After `brew services start matthewsinclair/intent/intent`, the brew-started daemon's `intentd listening on .../intentd.sock and 127.0.0.1:51737` line (10:42:04.060Z) appeared only in `/opt/homebrew/var/log/intentd.log`. `~/.local/state/intent/intentd.log` ended at the detached daemon's `intentd stopping: asked over the wire` (10:42:03.594Z) with nothing after it, so `intent daemon logs` and the state log went quiet. Once gyges was switched to `intent daemon start --at-login`, the log came back to `~/.local/state/intent/intentd.log` (`12:43:29Z intentd listening`).

**The mechanism, read by intent-vc in Intent's tree at d664d44fa.**

- intentd writes every log line to its own stdout and stderr (`native/rust/crates/intentd/src/daemon_log.rs:1-2`), and whatever launches it decides where those go.
- `intent daemon start` and the LaunchAgent plist send them to D19's location under the user's state dir. That is the only place `intent daemon logs` reads (`daemon_logs`, `native/rust/crates/intent-cli/src/render.rs:11895`, through `userstate::daemon_log_under`).
- The formula's `service do` block, rendered from `bin/.devbin/cmd/shared/brew.lib:587-592`, sends both streams to `var/"log/intentd.log"`, which is brew's file.
- The comment above that block (`brew.lib:580-586`) says "intentd writes its own structured log under the user's state dir; these capture stdout and stderr" and "The brew log and the daemon's log are different files with different subjects". The measurement and the code both say otherwise: under `brew services` they are one stream, and it goes only to brew's file.

**Why it matters now.** hv ruled on 2026-10-31 that the Macs use `intent daemon start --at-login` and Linux uses `brew services` alone, never both. So on every Linux machine the daemon's log lands in brew's `var/log`, where `intent daemon logs` does not look.

**What a fix has to decide**, which is the reporter's to rule:

- Point the formula's `log_path` and `error_log_path` at D19's files, so that one place holds the log under every route, which is the rule stated in `daemon_start`'s own doc comment (`render.rs:12011-12015`).
- Or teach `intent daemon logs`, and doctor, to read brew's file when `brew services` runs the daemon.

Either way, brew.lib's comment gets corrected to say the streams are one and where they go. devbin-vc recommends the first option, because the second would give one log a second home. If ST0091's WP-03 moves the formula onto devbin's built-in renderer, the service block's fix moves with it.

**Ruled by hv on 2026-10-31, first-hand in intent-vc's session (read by 14:11Z on intent-vc's date -u): "Go with devbin-vc's recommendation on 0667".** The formula's service block points `log_path` and `error_log_path` at D19's files under the user's state dir, `intentd.log` for stdout and `intentd.err.log` for stderr, which are the files `intent daemon logs` reads, so one place holds the log under every route. The comment over the block says intentd writes every line to stdout or stderr and names where each goes. The fix rides with ST0091's WP-03, which retires `brew.lib` and moves Intent's formula into a template of Intent's own that devbin's built-in formula renders, and ST0091's AC-03.3 carries it there.

**RESOLVED FOR 3.3.0 in abe9d2773 (the red) and abee517c5 (the fix).** dc built them and vc judged them green on tree 8d8a0ccce362. The ruled formula fix had already landed with ST0091 WP-03 (f18bd6945): the service block's `log_path` and `error_log_path` name D19's two files under the user's state dir, and AT-03.3 checks them. What was left is fixed here.

- **The directory.** The service manager opens those files before intentd runs, so a missing directory fails the job at spawn, and on the brew route nothing made it. `intent daemon start` and the LaunchAgent writer each make their own. `intent bootstrap`, the one step the formula's caveat asks for, now makes it too, and reports it beside its other writes. It makes the default directory always, because a service's environment carries no `XDG_STATE_HOME`. Where `XDG_STATE_HOME` resolves elsewhere it makes that directory as well, the one `intent daemon logs` reads.
- **The prose.** The caveat says where `brew services` logs and to run `intent bootstrap` before the first `brew services start`. `docs/install.md` no longer sends the reader to Homebrew's `var/log`: it names `intentd.log` and `intentd.err.log` under `~/.local/state/intent`, and says that a shell's `XDG_STATE_HOME` moves where `daemon logs` reads but not where the service writes.
