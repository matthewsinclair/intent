## What happens

hv's rule is that Intent's own project-management state (thread, work package, criterion and issue numbers) never reaches Intent's output. `no_pm_state_in_output.rs` guards it over four surfaces: the schema faces, every declared command's `--help`, string literals in shipped Rust source and build support, and the installed payload under `lib/templates` and the plugins. `intent llm guide` prints text it reads at run time from `surface/dispatch-table.json`, including every invariant's rule (INV-04 among them) and row text, and none of the four surfaces reaches that file. A tracker citation added to an invariant's rule therefore ships into every project's agent guide unseen. One did, in a draft bank on 2026-10-25, caught by hand before its judge.

Measured the same day on the installed pair: the guide's live output carries no tracker id except `ST0000`, the one id every project has, so nothing leaks today.

## Expected

The guard reads what the guide prints. Either `intent llm guide`'s rendered output becomes a fifth surface, driven through the binary like the help text, or the dispatch table's text fields are scanned with the same referent rule.
