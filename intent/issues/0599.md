## What was seen

On hv's Ubuntu VM (kovacs), 2026-10-15, ORDER 3 of ST0081 WP-01 ran `bin/int linux build --jobs 1` from a clean clone at 11017d7bd. The build's own version step, which runs the staged `intentd --version` to read the binary it just built, printed, in order:

```
note: moved skills to /home/matts/.local/share/intent/skills, agents to /home/matts/.local/share/intent/agents out of /home/matts/.intent into the XDG layout, and removed it
intentd 3.2.3 (11017d7bd...) dev
```

The user's real `~/.intent/`, a legacy 3.0.1-layout home dated 2026-03-08, was moved into the XDG layout and removed, by a build step, from a version read. Nothing was lost: `~/.local/share/intent/{skills,agents}/installed-*.json` hold the moved files. The operator (kovacs-sysadm) read the line and flagged it; nobody asked for a migration, and the pre-migration state of that machine is gone, so a rehearsal that wanted to meet a legacy home now has to recreate one.

## What was expected

A read verb reads. `intent --version` and `intentd --version` answer a question about the binary and should write nothing anywhere, least of all in the user's home. The migration of `~/.intent/` into XDG (ST0074 WP-05, hv decision 17) is intended behaviour; its trigger site is the defect.

## The mechanism (read, not run)

`native/rust/crates/intent-cli/src/main.rs:17` runs `userstate::dirs().and_then(|dirs| userstate::migrate_legacy(&dirs))` at process start, before any argument is parsed, so every invocation of the `intent` binary migrates: `--version`, `--help`, `info`, a hook, a build's version read. `intentd`'s main has no such call (the index lists `migrate_legacy`'s one caller outside its own tests as `main.rs:17`), so the note under the build came from the `intent --version` read beside `intentd --version`. `userstate.rs:453` `migrate_legacy` moves what Intent owns and removes `~/.intent/` when empty (`:450`), and prints the note (`:410`).

## The fix, as vc would shape it

Run `migrate_legacy` from the verbs that read or write user state (`bootstrap`, `claude skills`, `claude subagents`, the daemon's start) and never from `main` before dispatch; `--version`, `--help` and `info` touch nothing. Size S. A test: `intent --version` and `intentd --version` under a HOME carrying a legacy `~/.intent/` leave it byte for byte, and `intent bootstrap` under the same HOME migrates it and prints the note.

## Where it belongs

Found before 3.2.4's cut, on the Linux proof that gates it; filed by vc from kovacs-sysadm's report, which is the artefact. hv rules the release.

## Resolution

Fixed at ff266c7a9 (issue 0599, banked as refs/bank/dc/324b/0599, patch-id 386f382abcfc, judged by vc as part of 3.2.4's second train), on hv's ruling of 2026-10-16 that the five open issues ride 3.2.4.

`userstate::migrate_legacy` no longer runs from `main` before the arguments are parsed. It runs at the head of `render::run` (`migrate_user_state`), after `spine::parse` and before the verb, so `--version` and `--help`, which the parse answers, never reach it. It is also skipped by name for `info`, `version`, `help`, every family's `help` and `claude hook`, and for `bootstrap --check`, which now names the legacy home it would move ("note: <home>/.intent is a legacy home; the next intent verb that does work moves it into the XDG layout") instead of moving it. `intentd`'s main never called it and is unchanged.

The shape is a list of what skips the move, not of what triggers it, and that is deliberate: the move relocates `config.json` and the install pointer as well as skills, subagents, agents and ext, and nearly every verb reads one of them, so a list of verbs that migrate would leave every other verb reading a 3.0.1 home at its old path. `claude hook` is skipped because it runs in every Claude session, its stdout reaches the session, and it resolves its script from the executable alone.

The arm is `intent-cli/tests/a_read_verb_leaves_a_legacy_home.rs`. Under a fixture HOME carrying a legacy `~/.intent`, `--version`, `--help`, `info`, `st help`, `claude hook session-finish` and `bootstrap --check` leave it byte for byte with no note and no XDG skills directory. `bootstrap --quiet` moves each entry byte for byte and prints the note. `bootstrap --check` names the home. It was red at base on the read and check arms and green with the fix. The skip list is declared in `command_rosters_are_derived_or_declared.rs`; it goes when the dispatch table declares per row whether a verb reads user state.
