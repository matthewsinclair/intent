## What happened

The explorer's search pane is meant to put a note on its info row when the pane opens (ST0069 AC-21.1). The note says that the answer is partial or that files moved since they were indexed. When nothing is partial, it names the level that answered and what each language's references leave out (ST0076 AC-04.2). No frame has ever drawn it. ic found this on 2026-09-17 by driving `/search is_local` in a pty: the answer carried symbol hits, and the info row showed only the key hints.

## Mechanism

In `tui/run.rs`, the event loop's view-change block re-reads the rows, sets `app.notice` from `source.note(view)`, runs `arrive(..)`, and then runs `app.notice.clear()`. The draw happens at the top of the next iteration, so every note is wiped before any frame shows it.

- `354e2136e` (2026-08-30, AC-17.10) added the clear after a view change, so no stale notice survives one.
- `598cf71b9` (2026-09-12, ST0069 WP-21) set the pane's note in the same block, before that clear.

The AC-21.x arms and ST0076's pane arm test `views::freshness_note` as a pure function. They stayed green while the loop dropped its value, and the defect shipped in v3.0.3.

## Evidence

The drive ran in a pty through a terminal emulator (pyte), on a worktree of the Intent tree under an isolated HOME. Before the fix, `/search is_local` drew `address.rs:678  def method in Address` and the `ref call` rows, and the info row read `OMNI  1/86  ↑↓ browse · / menu · ⌫ back · type to find`. With the fix, the same drive draws `OMNI  level 1: read from the file's syntax and matched by name, never resolved to the definition it names; ...`.

## Fix

The fix is built in ST0076 WP-04, on vc's ruling of 2026-09-17. `arrive` becomes the one place a view's notice is set or cleared: it takes the view's note and sets `app.notice` to it or clears it, and the trailing clear goes. The pane arm asserts the note on `run::screen_for(..).hint`, which is the screen rather than the pure function, and asserts that a view with no note clears it. This issue closes with WP-04's landing.
