**Triage**, by intent-vc on 2026-11-06, which hv asked for: severity raised from medium to high. The `swift` lines are wrong in nine of the ten projects that declare `swift`, and `bats -r tests/` finds no test file in 11 of the 17 projects whose AGENTS.md lists it. The contract is imported into every session in those projects and the overrides are not. The one correction found, Trellis's, is reverted by the next sync. Following a line is an unbooked heavy run under the estate's slot rule. It is not critical: it corrupts no data and blocks no release.

**Where it comes from.** `lib/templates/llm/_AGENTS.md` carries a fixed block per language (`[[#lang <lang>]]`), each holding that language's default prerequisites and build and test commands, and its only substitutions are `[[PROJECT_NAME]]` and `[[INTENT_VERSION]]`. `intent/.config/config.json` has no key for a project's own build and test commands. A hand edit cannot hold: in-essentials forbids it, the next `intent agents sync` overwrites it, and Ccusage's `.claude/settings.json` denies `Edit(/AGENTS.md)`.

**Fix options**, from ccusage-vc's report and hv's framing that in this estate devbin is how projects build and test, not Intent:

1. When the project has `bin/devbin`, the template points at it for building and testing.
2. A project declares its own build and test commands, and the template renders them.
3. The template drops the language-default commands, since it cannot know a project's own.

intent-vc's recommendation: render the build and test lines from what the project declares, in that order of preference: `bin/devbin` when the tree has one, else declared commands, else no build or test lines at all. A language default is right only by coincidence. Every project above and every project in the survey that declares `swift` has `bin/devbin`, so the first option alone would correct each of those cases, which is webber-dc's point, measured. It is not the whole fix: Anvil declares `shell` and `elixir` and has no `bin/devbin`, so the rest of the order is what reaches it. Pointing at `bin/devbin` corrects the command, not the booking: Webber's usage-rules.md says its vendored devbin asks for no slot itself, so the contract would still have to say that a heavy run is booked with the estate's controller.
