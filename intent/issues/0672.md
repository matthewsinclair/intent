**`intent agents sync` WRITES EACH DECLARED LANGUAGE'S DEFAULT BUILD AND TEST COMMANDS INTO AGENTS.md, AND NOTHING A PROJECT DECLARES CAN CHANGE THEM, SO A PROJECT THAT BUILDS OR TESTS ANOTHER WAY GETS A CONTRACT THAT NAMES THE WRONG COMMANDS.**

**Seen in three projects.**

- **Ccusage**, raised by ccusage-vc at hv's request on 2026-11-03. Ccusage declares `rust` and `shell`. After `intent agents sync` under 3.2.8 (Ccusage 80179a5), its AGENTS.md lists "Bats testing framework" as a prerequisite, `cargo test` and `bats -r tests/` as its test commands, and `cargo build` as its build. Ccusage has no Bats tests: its shell test is `sh tests/release.sh`, and every cargo command its checks run takes `--locked`. Its workaround (41eb982) points usage-rules.md at README's Development section and docs/releasing.md, and says that AGENTS.md's Bats and unlocked cargo lines are Intent's generic text. Ccusage vendors devbin 0.1.19 since 2026-11-03, and declaring its own commands is Ccusage ISSUE:0006.
- **Trellis**, raised by trellis-vc on hv's word ("That's a bug. Raise it with devbin-vc and we'll sort it out over there"), received before 2026-11-01 14:00Z by date -u and carried to intent-vc on devbin-vc's board (Devbin todo 192). Trellis declares `swift` and `content`. With `swift` declared, the template renders a `Package.swift` prerequisite and `swift build` and `swift test`, but Trellis's Swift is one Xcode project, `native/ios/Trellis.xcodeproj`, built through `bin/devbin build` and tested with `xcodebuild test`. Trellis carries a hand correction (6f9200f) that its next `intent agents sync` will revert.
- **Intent itself**, measured by intent-vc on 2026-11-03. Intent declares `elixir`, `author`, `content`, `rust`, `shell` and `swift`, and its AGENTS.md names `mix.exs` and `Package.swift` as where the toolchain versions live and lists `mix deps.get`, `mix compile`, `mix test`, `cargo build`, `cargo test`, `swift build`, `swift test` and `bats -r tests/`. The tree has no `mix.exs`, `Package.swift` or `Cargo.toml` at its root. The Rust workspace is `native/rust/Cargo.toml`, the Swift is the Xcode project `native/macos/Intent/Intent.xcodeproj`, and the Linux preflight, which mirrors CI, builds with `cargo build --release --manifest-path native/rust/Cargo.toml` and tests with `cd tests && ./run_tests.sh`.

**Where it comes from.** `lib/templates/llm/_AGENTS.md` carries a fixed block per language (`[[#lang <lang>]]`), each holding that language's default prerequisites and build and test commands, and its only substitutions are `[[PROJECT_NAME]]` and `[[INTENT_VERSION]]`. `intent/.config/config.json` has no key for a project's own build and test commands. A hand edit cannot hold: in-essentials forbids it, the next `intent agents sync` overwrites it, and Ccusage's `.claude/settings.json` denies `Edit(/AGENTS.md)`.

**Fix options**, from ccusage-vc's report and hv's framing that in this estate devbin is how projects build and test, not Intent:

1. When the project has `bin/devbin`, the template points at it for building and testing.
2. A project declares its own build and test commands, and the template renders them.
3. The template drops the language-default commands, since it cannot know a project's own.

intent-vc's recommendation: render the build and test lines from what the project declares, in that order of preference: `bin/devbin` when the tree has one, else declared commands, else no build or test lines at all. A language default is right only by coincidence. All three projects above have `bin/devbin`, so the first option alone would correct all three.

**Recorded only.** hv's word, relayed by ccusage-vc on 2026-11-03, is that this is not fixed today; the filing is on hv's go, relayed the same way.
