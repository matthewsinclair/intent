Found by dc on 2026-09-18 while driving 0443 Q2/Q3 on a scratch project (worktree build at 47e269483, SQLite 3.53.2). When the store's fts5 `doc_sections` table is damaged in a way that breaks the READ of it (dc replaced it with a plain table), every search, a malformed `(hello` included, fails before the classifier is reached, in `Facade::open`'s ingest, with `could not read the committed canon` and the remedy `fix the artefacts named above, then retry -- run intent doctor to list them`. No artefact is named, because none is at fault: the canon is intact and the store is damaged.

## The defect

The same class as 0443 on a different door: a store fault reported as something the reader can fix, with a remedy that cannot deliver. The open-time ingest treats a store read failure as a canon refusal.

## The fix (XS to S)

`Facade::open`'s ingest separates a store read failure from a canon refusal, and the store side gets 0443's remedy shape: the artefacts are not at fault, `intent index rebuild` (or the store's own remedy for the failing table) is the door. Pinned by one test that damages the table the way dc did.
