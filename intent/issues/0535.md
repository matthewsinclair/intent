**What happens.** A store that does not exist yet is warmed from canon on its first open: `ingest::load_fresh` calls `resync_inner(.., Load::WarmIfCold)`, which calls `Store::warm_if_cold`, and that warm carries threads and issues only. Boards reach the store only through an unscoped `Load::Restore`, which is `intent sync --to-store` (ingest.rs: "ONLY AN UNSCOPED `Restore` CARRIES BOARDS FROM DISK INTO THE STORE"). So every fresh clone and every fresh worktree opens with a store holding every thread and every issue and no whiteboard at all, while each node's `board.json` is committed beside it. `load_fresh`'s own comment states the rule this breaks: a cold store is warmed with `Scope::All` because "a partial store looks exactly like a small project".

**What the fix has to do.**

- The cold warm carries the boards. Under the same write lock as the thread and issue warm, a store found cold takes each `board.json` from disk, as an unscoped `sync --to-store` does. The reason the Ingest arm carries no boards (intentd's pass must not outvote a store holding a board write whose extract has not been projected yet) does not apply to a store that holds nothing. Whether "cold" also counts board rows, so that an estate with boards and no threads or issues still warms, is part of the change.
- `intent wb migrate <node>` refuses a node whose `board.json` on disk records it as migrated. That board is a generated view with its extract beside it, not hand-authored markdown, and carrying the render drops everything the render does not show: archived items, handled state, and every other node's rows.
- While the store holds no node and `board.json` files sit on disk, the `wb` reads name `intent sync --to-store`, not `intent wb register`.

**THE FIX.**

- (a) `Store::warm_if_cold` takes the boards and restores them in the transaction that warms the threads and issues. A store holding a thread, an issue or a node row is left exactly as it is. `load_fresh` counts the store's boards as content, so a store holding only boards takes the warm path and is not read again at every open. The one reader of `board.json` is `ingest::boards_on_disk`, which `read` and the refusals share.
- (b) `model::boards_the_store_lacks(held, on_disk)` is pure. It names each node whose `board.json` records `migrated_at` while the store holds no migrated node of that name, whether the node is absent or is the unmigrated empty row that `wb register` leaves. `wb migrate` and `register_roster` refuse if any node is lacking, and `wb register <node>` refuses if that node is. `sync --to-disk` refuses under any scope, because its projection writes every board whatever the thread scope. Each refusal is `WbBoardsNotInTheStore`, whose remedy is `BOARDS_NOT_IN_THE_STORE_REMEDY`, naming `intent sync --to-store`.
- (c) `Facade::wb_status` refuses an empty roster beside such boards, and the CLI's `wb status` and MCP's tool both read it. `board`, `require_registered` and `require_migrated` name the same refusal for a lacking node, so `wb show`, `wb pickup` and every board write name `sync --to-store` rather than `wb register` or `wb migrate`.
- (d) Doctor reports a store holding threads, issues or nodes and not a migrated board on disk as one uncounted StoreStale finding, with the same remedy constant. That node is left out of the stale-board finding, whose remedy, a re-render, is the write that would empty the board.

**THE ARMS.** intentsvcs `a_fresh_clone_takes_its_boards.rs` has seven arms. (a) A fresh clone (`clone_extract`) opens holding every board, archived items and messages included, and its egest rewrites no whiteboard byte. A store holding a board and no thread is not warmed again from an older `board.json`, and a cold warm under the lock leaves a board a peer registered first. (b) In a store warmed as before 0535, the four writes refuse and no whiteboard file changes. (c) The reads name `sync --to-store`, an unknown moniker is still only unregistered, and the restore carries every board. (d) Doctor names the state once, is silent on the estate's own store and on a cold clone, and clears after the restore. The second symptom: a cold clone's hand-skewed inbox is rendered back by `sync --to-disk`, and doctor reads it clean.
