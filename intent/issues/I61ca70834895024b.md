## What is broken

On macOS, Finder writes a `.DS_Store` file into a directory when a window shows that directory. With such a file under `intent/`, `intent doctor` reports "residue: unknown-file-shape", with the note that the file is not valid UTF-8. The pre-commit gate then refuses the commit with "the estate disagrees with the store". It was seen in `intent/`, in `intent/.canon/`, and in `intent/whiteboard/`.

## What it costs

Every commit in that checkout is refused until the file is removed, and Finder writes the file again while its window is open. The user's global git ignore file lists `.DS_Store`, so `git status` does not show the file, and the cause is not in view.

In Cybri on 2026-11-27 it refused three commits in ten minutes. Each session there now runs `find intent -name .DS_Store -delete` before each commit.

## What fixes it

Doctor skips `.DS_Store` when it reads the store's directories. A wider rule is also possible: doctor skips each file that git ignores.
