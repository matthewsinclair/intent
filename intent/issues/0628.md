The release commit 2e0e9215d passed the same arm an hour earlier. The macOS leg is skipped on a push.

`bin/.devbin/cmd/canon:177` ran `first_both="$(comm -12 <(…) <(…) | head -1)"` under `set -euo pipefail`. comm's output was about 6 KB, so GNU comm flushed a 4 KiB stdio buffer and then wrote the rest at exit. When `head -1` had already printed its line and exited, that second write got EPIPE. GitHub's runners start steps with SIGPIPE ignored, so comm printed the error and exited 1 rather than dying of the signal. pipefail failed the substitution and `set -e` ended the script. Scheduling decided whether it fired, which is why the tag passed and the next two pushes did not.

Made deterministic, with comm writing 84500 bytes (`refs/bank/dc/canon-pipe/canon-race.sh`, log `canon-race.log`): the base canon exits 141 with SIGPIPE at default, so macOS fails too once the output outruns the pipe, and exits 1 with `comm: stdout: Broken pipe` with SIGPIPE ignored. The fixed canon exits 0 both ways. canon's own fix is `refs/bank/dc/canon-pipe/fix`, banked on its own.

## The class

An early-exit reader on a pipe (`| head`, `| grep -q`, `| sed -n Nq`, `| awk '{…; exit}'`), inside a script that sets pipefail, fails the pipeline whenever its writer still has a write to make after the reader exits. With SIGPIPE at default the writer dies with 141; with it ignored the writer gets EPIPE and usually exits 1. Either way pipefail reports the pipeline as failed. What that does depends on where the pipeline sits:

- **As a statement, or as the right side of an assignment, under `set -e`:** the script ends.
- **As an `if`, `elif` or `&&` condition:** it silently takes the other branch. A match that `grep -q` found reads as no match.
- **Behind `|| true`:** harmless.

It is the shell twin of issue 0613, where a Rust verb whose reader stopped reading panicked with exit 101.

## Expected

No early-exit reader sits on a pipe in a pipefail script where its failure can end the script or turn a branch. Each site either reads all of its input (`sed -n 1p`, `awk 'NR == 1'`), takes the first line by parameter expansion from a value already held, or reads a here-string or a file instead of a pipe. A site behind `|| true` is left as it is and says why. A shell rule in the critic with a greppable detection then keeps the class out of new code, so the commit gate refuses it rather than a CI runner finding it.
