## What was seen

On hv's Ubuntu VM (kovacs), 2026-10-15, cleaning up after ST0081's AC-07.1 drive with the 3.2.3 package binary (11017d7bd), `intent claude skills uninstall in-session` printed `removed: SKILL.md, scripts/release-gate.sh` and exited 0, and left an EMPTY `~/.claude/skills/in-session/` directory behind, which kovacs-sysadm removed by hand. Reproduced on the dev pair (3.2.3 dev at 701c4d98b) under an isolated `HOME`: `install in-session` writes `SKILL.md` and `scripts/`, `uninstall in-session` reports `ok: 1 changed`, and `ls -la $HOME/.claude/skills/` then shows `in-session` as an empty directory.

## What was expected

An uninstall leaves no shell of the thing it removed: the skill's directory goes with its files, as a reader of `~/.claude/skills/` would expect, and as `install` created it.

## The fix, as vc would shape it

After removing a skill's files, remove the skill's directory when it is empty, and only then; a directory holding anything the manifest does not name is left and named, since it is the user's. Size XS. The same read applies to `subagents uninstall` if it writes a directory per unit. A test: install then uninstall under an isolated `HOME` leaves no entry under `~/.claude/skills/`.

## Where it belongs

Found by kovacs-sysadm, reproduced by vc; hv rules the release.

## Resolution (cc, 2026-10-16)

Landed at 35f173b28 (patch-id 68ae361ae86c), judged by vc as part of the 3.2.4 composition. hv reversed the 2026-09-09 ruling on 0218 for the empty shell alone (vc decision 64): after removing a skill's files, `uninstall` removes the skill's directory when it is empty; a file the manifest does not name stays, keeps the directory, and is named under `left`. Subagents install one file each, so nothing changed there.

Driven on the built binary under a temp `HOME`: install then uninstall `in-debug` leaves `~/.claude/skills/` empty; a second uninstall reports `not installed` and `ok: 0 changed, 1 already settled`, which resolves the `docs/known-defects.md` entry on a second uninstall reporting a change that did not happen (the entry is removed); with a file planted in the skill's directory, uninstall reports `left 1 this build did not install: notes.md` and keeps the directory.
