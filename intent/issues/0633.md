Reported 2026-10-23 by rhadamanth-sysadm and, at hv's request, by gyges-sysadm, during the gyges move (Molt ST0006 WP04). Filed by vc from their reports.

## What

`intent claude upgrade --apply` appends three single-`*` `.prettierignore` patterns to a file whose existing `**` patterns already cover them, so every run dirties the tree. Reproduced in `~/Devel/prj/Molt` at e9e37f8 from a clean tree, on gyges with Homebrew's intent 3.2.5 (2e0e9215d) and 3.2.4 (f89b8285) before it, and on rhadamanth with 3.2.5 from `~/.local/bin` as a dry run:

```
intent claude upgrade
would exclude: intent/st/*/info.md in .prettierignore
would exclude: intent/st/*/acceptance.md in .prettierignore
would exclude: intent/st/*/WP/*/info.md in .prettierignore
dry run: 0 would be written, 12 already canonical, 2 preserved, 0 held, 0 skipped.
```

With `--apply` it reports `ok: 0 written, 12 already canonical, 2 preserved, 0 held, 0 skipped.` and `excluded:` for the same three, and `git status` then shows ` M .prettierignore`: after the existing `intent/whiteboard/*/inbox.*.md` line it appends a blank line, the three-line comment headed "Generated views have ONE writer, and it is the renderer", and the three patterns. On the next run it appends them again.

## Why it is wrong

Molt's `.prettierignore` already carries `intent/st/**/info.md` and `intent/st/**/acceptance.md` (lines 29 and 30), under its own comment (lines 26 to 28): "`**` IS LOAD-BEARING: in .prettierignore a single `*` does not cross a `/`, so `intent/st/*/info.md` matches a flat layout and misses every thread under a status directory." The upgrade's coverage check does not count a `**` pattern as covering the single-`*` one it would add, so it adds the narrower, redundant lines on every run.

## Cost

A dirty Molt checkout stops `molt upgrade` before it runs (WP04 runbook P4). Workaround on gyges: `git checkout -- .prettierignore` after each upgrade; nothing is committed.

## Spec (vc, 2026-10-23)

LANE: ic, S, after 0623's close; rides 3.2.6 if its run fits before the cut, else the next patch. SHAPE: the upgrade's `.prettierignore` step judges coverage by what a pattern matches, not by the line's text: a pattern already in the file that matches every path the canon pattern matches covers it, so `intent/st/**/info.md` covers `intent/st/*/info.md` and nothing is appended; the step keeps adding a pattern a file lacks. The lane also measures whether the canon's own single-`*` patterns miss a layout Intent supports (a thread realised under a status directory); if they do, the canon emits the `**` form and says so in the CHANGELOG line. PROOF: an arm with a scratch project whose `.prettierignore` carries Molt's three `**` lines: the dry run prints no `would exclude`, `--apply` writes nothing and the tree stays clean, red on the base; the existing arm that adds the patterns to a file lacking them stays green; one arm per form the coverage reads (`*`, `**`, a literal path).
