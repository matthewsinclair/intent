`~/.local/bin/intent` is a symlink straight into the release directory, so the route every node and every estate on this machine actually types has NO currency check on the pair it runs.

**THE CHECK EXISTS AND IS REACHED BY A DIFFERENT DOOR.** `bin/devbin cli` runs the self-provenance currency verdict and REFUSES a pair that is behind HEAD. The pre-commit gate's `self-provenance` arm reports the same verdict, diagnostically, and its own text says so: "This line is the only place a stale delivered pair is currently reported." Nothing on the symlink path consults either.

**MEASURED 2026-09-22, WITH REAL CONSEQUENCE RATHER THAN A HYPOTHETICAL.** Issues 0509 and 0513 were both banked, judged, landed at their judged patch-ids, and closed. Their three source files -- `intentsvcs/src/organize.rs`, `intent-cli/src/render.rs`, `intent-cli/src/mcp.rs` -- were not in the delivered pair. The pair named `36143de45`, a whiteboard commit predating all of it, built at 09:47:46Z. So for the rest of that day `organize`'s unclaimed digest still hashed absolute paths and the MCP organize door still emitted them, **in every estate on the machine, with both fixes committed and judged**. Nobody noticed until an unrelated commit's gate printed `currency REFUSING`.

**WHY THIS IS A DEFECT AND NOT THE DESIGN WORKING.** That a rebuild is required is the design and is correct -- `native/rust/` is not live-on-save. What is wrong is that the required step has no reminder at the point of use, so the gap between "landed" and "deployed" is invisible from every ordinary invocation. A stale pair behaves exactly like a current one until it does not, and the difference surfaces as a mystery in whatever the stale code path touches, arbitrarily later, in an estate that has no idea a fix was supposed to have arrived.

**THE CLASS IT BELONGS TO.** An instrument that cannot produce the answer, whose silence therefore reads as a pass. Five other faces of this landed on 2026-09-22 alone: a `.bats` file no rule's `applies_to` admits, reported `ok: no shell findings`; a linter that stopped at a malformed directive, reporting two parse errors and hiding a CRITICAL; a process counter matching a name the instrument never prints; an rc read off a pipe's tail; and a path list rebuilt from a truncated `--stat` display. This is the same shape arriving through a DELIVERY PATH.

**AND THE MIRROR, WHICH IS WHY THE PAIR IS WORTH FILING TOGETHER (see 0517).** One repository, two directories, opposite deployment semantics, and the verb "landed" distinguishes neither:

- `lib/templates/` -- the author's SAVE is the deployment. The install root pointer `~/.local/share/intent/home` is a regular file containing this tree's path, so a worktree save is live for every estate immediately, and a commit changes nothing about effect. That is 0517.
- `native/rust/` -- neither a save nor a commit deploys anything. It takes an explicit `bin/devbin build all`.

A landing is a claim about the RECORD. Whether it is also a claim about BEHAVIOUR depends on which directory it touched, and nothing in the word says which.

**WHAT IS OWED, and it is a design question rather than a patch.** Some check at the point of use: the symlink could route through a wrapper that runs the same verdict `devbin cli` runs, or the pair could refuse itself when its embedded commit is not an ancestor of the checkout's HEAD, or -- cheapest and weakest -- the verdict could be printed rather than enforced. Each has a cost: a wrapper adds latency to every invocation across every estate, self-refusal turns a stale pair into an outage, and a printed warning is one more line nobody reads. **NOT proposed here.** ST0058 completed on 2026-09-11 and the gate cites it beside this exact sentence, so the observation is old; what is new is a measured instance where two judged fixes sat undeployed for hours.

**PROVENANCE.** Found by vc on 2026-09-22 in the `self-provenance` output of an unrelated closing commit, at `8437e56a2`, and driven: the three moved files named, the pair's embedded commit read, its build time read, and the two affected behaviours traced to the estates that were still running the old ones.


## RESOLVED (cc, 2026-09-22, on hv decision 30)

**THE DESIGN QUESTION WAS RULED BY hv, NOT BY THIS FIX.** Decision 30 (committed 7ebe998fc) put the refusal at PUSH, and rejected refusing at COMMIT and a WRAPPER on the symlink. The report form this issue lists as "cheapest and weakest" had already been tried, and it failed on the day this was filed.

**THE FIX, aba799696 (`bin/.devbin/cmd/prepush`, +68 -1):** the pre-push runner takes `artefact_currency_verdict` from `currency.lib`, with its required sources, over `RELEASE_DIR`. It is the same verdict `bin/devbin cli` refuses on and the pre-commit `self-provenance` arm reports, so it is not a second staleness test. The verdict runs BEFORE the path trigger's early exit. `ok` is silent. `refuse:` blocks the push with the verdict's own reason and `remedy: bin/devbin build all`. `warn:` passes and is printed: a `dirty-` marker over a source-clean range could only be cleared by a rebuild from a tree clean under the whole dirt scope, which this shared checkout almost never is. Banked at blob 0d7961226, judged by vc, and landed at the judged patch-id 5132ae0cc.

**DRIVEN BOTH WAYS before landing**, in a detached worktree against a scratch bare remote, with the same pair bytes in both runs. Marker 36143de45 over a range touching ten build inputs: a whiteboard-only push gave rc=1, BLOCKED, and the remote did not move. With the build inputs returned to that commit: rc=0, and the remote moved. The WARN row was NOT driven, because no dirty-marked pair was to hand.

**DEPLOYED, and the question this issue asked now has an answer.** hv ran `bin/devbin build all` at the terminal, finishing at 18:20Z. `intent --version` prints `intent 3.2.0 (6995df34798f2dbe6aeade4aa49af74bacbb9867)`, `artefact_pair_marker` returns that commit for both binaries, `bin/int local status` reads `currency ok`, and `artefact_currency_verdict` returns `ok` on the real tree. That is the current-pair arm driven on the tree it guards. 0509's and 0513's fixes are ancestors of 6995df347, so the two fixes this issue found undeployed are now running. The sha was announced to the roster so each node can check `intent --version` against it.

**WHAT THIS DOES NOT DO, stated rather than implied.** Between a Rust landing and the next push, a stale pair still runs silently: the refusal fires at the batch boundary, not at the point of use. That was the ruled trade-off. The `self-provenance` line at pre-commit is still the only reporter inside that window.
