Found in Lamplight on 2026-09-28 under v3.2.3, when critic-prose's mechanical pass returned 15 FMT-03 (unicode-decoration) hits on two files that are pure ASCII, every one a straight quote or apostrophe. FMT-03's Regex at intent/plugins/claude/skills/in-detrope/data/trope-catalog.md:801 is a single character class, and by code point its four quote characters are U+0022 U+0022 U+0027 U+0027: straight quotes where U+201C U+201D U+2018 U+2019 were meant. So the rule matches every straight quote and apostrophe and misses every curly one, which is the inverse of what it is for. Measured with Python's re, the class copied byte for byte from the file: `don't say "yes"` matches; the same text written with U+2019, U+201C and U+201D does not; a string holding U+2192 matches, as the control that the class works at all. Five more rules carry the same flattening in a two-character class `['']` that repeats U+0027 where the second character was evidently meant to be U+2019: TN-04 (:2040), TN-01 (:2176), TN-07 (:2376), TN-05 (:2444) and TN-02 (:2508). So TN-01 matches `Here's the thing` and misses the same phrase typed with U+2019. No curly character has ever been in the file's history (`git log --follow -S` finds none), so it was flattened before it first landed at 88ee47b8a (2026-03-28). The installed copy at ~/.claude/skills/in-detrope/data/trope-catalog.md is byte-identical, so every consumer runs it. Possibly by design rather than the same defect: the other apostrophe-bearing rules use a bare `'?` (ASR-01, ASR-02, ASR-03, CMP-01, NAR-01, NAR-02, SS-01, SS-04) and NAR-04 keys on a straight `"`, so none of them match typeset prose either. Fix direction: restore the four curly characters in FMT-03 and U+2019 in the five classes, written as \u escapes so no quote normaliser can flatten them again, and add a catalogue test that runs each automated regex against a curly-quoted positive and a straight-quoted negative.

**Scope as ruled on 2026-10-12, before the fix was banked** (vc's rulings, on dc's and vc's measurements):

- **The form is the literal UTF-8 character, not a backslash-u escape.** The catalogue's consumer is `grep -iE` (IN-PR-STYLE-004's Detection, critic-prose's agent.md), and no grep measured honours a backslash-u escape. BSD grep 2.6.0, GNU grep 3.12 and the ugrep Claude Code bundles on macOS, and GNU grep 3.11 on Ubuntu 24.04, all read a bracket holding backslash-u-2019 as the literal set of a backslash, u, 2, 0, 1 and 9, under both `C` and `C.UTF-8`. So FMT-03 written with escapes would flag almost every line, and the apostrophe classes would still miss U+2019. ripgrep and Python's `re` do honour the escape, which is why the measurement above, made with Python, pointed that way. Literal characters already sit in FMT-01's and FMT-03's classes, and the guard against a normaliser flattening them again is the test below, which goes red if one does.
- **The nine other quote-bearing rules are in scope.** In ASR-01, ASR-02, ASR-03, CMP-01, NAR-01, NAR-02, SS-01 and SS-04 the bare `'?` becomes a class holding the ASCII apostrophe and U+2019. In NAR-04 the straight `"` before a dialog tag becomes a class holding it and U+201D.
- **The locale is in scope.** Plain BSD and GNU grep under `LC_ALL=C` read a multibyte character in a class byte by byte, so they miss a curly apostrophe inside a pattern and flag any character that shares a byte with the class. IN-PR-STYLE-004's Detection and critic-prose's agent.md therefore name `LC_ALL=C.UTF-8 grep -iE`, which is right for every grep. Inside Claude Code the shell's `grep` is the bundled ugrep, which matched under `C` as well, so critic-prose there was not blind; scripts, hooks, CI and terminals are.
- **The test** is `tests/unit/trope_catalog_regex.bats`. It reads each regex from the catalogue by rule id and runs it with `LC_ALL=C.UTF-8 grep -iE`, as the consumer does. FMT-03 must flag each of U+201C, U+201D, U+2018 and U+2019 and leave ASCII quotes alone, and every apostrophe or quote class must match its phrase typed both with the curly form and with the straight form.
- **Out of this fix:** llm-tropes, the vendor source, and Utilz's `indicators.txt` carry their own copies and are vc's to route. The test turns a re-flattening vendor pull red.
