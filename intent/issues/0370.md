A search over an index holding skipped files answers `complete: true` with an empty `skipped` list.

ST0069's design (S5) and AC-19.3 say `complete` is false when anything was skipped or is stale, and the terminal prints a note per skipped path before the hits. `IndexFreshness::complete` is `skipped.is_empty() && stale.is_empty()`, but `mark_skipped` (`intentsvcs/src/search.rs:174`) has no caller anywhere in the workspace: `Facade::search_all` (`intentsvcs/src/facade.rs:3177-3345`) calls only `mark_stale`.

The skip rows exist. `index_file` holds each binary, over-cap, symlinked or unreadable file with its `skipped_reason`, and only `intent index status` reads them. So a search for something inside a skipped file is a confident miss, and the per-skip note never prints.

Remedy: have `search_all` fill `skipped` from the `index_file` rows carrying a `skipped_reason`, scoped by the answer's filters as staleness is; or change the design's rule by ruling.
