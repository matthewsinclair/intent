Found on 2026-09-24 by vc's subagent auditing `intent/docs/working-with-llms.md` for the 3.2.1 doc audit, driven on the pair at `4c687eaad`.

Seen: `intent claude upgrade --apply` seeds `.intent_critic.yml` from `lib/templates/_intent_critic.yml` through `rootfiles::substitute` (`canon.rs:568`, `rootfiles.rs:142-146`), whose `fill_empty_sections` (`rootfiles.rs:180-208`) treats every YAML `#` comment as an empty Markdown heading and appends `_Not configured for this project._` after it. Driven on a fresh project (`init`, then `claude upgrade --apply --skip-settings`): 25 injected lines; PyYAML raises a ParserError at line 6, and Ruby's YAML reads the file as one string. Intent's own readers are line-based (`pre-commit.sh:499-509`, `critic.rs:627`), so the gate still works, but the critic subagents fall back to defaults on a malformed file, dropping the project's `disabled` list and threshold. `--force` writes the corrupted seed over a good existing file. Introduced by `15c3be955` (issue 0336), shipped in 3.1.0 and 3.2.0.

Found independently by dc the same day, driven on a fresh `intent init` project: `upgrade --apply` printed "written: .intent_critic.yml", the file holds 84 lines against the template's 34, and Ruby's YAML loader reads it as the single string "_Not configured for this project._" where the template loads as `{severity_min: warning, disabled: [], post_tool_use_advisory: false}`.

Not affected: measured by vc at 10:15Z, every estate in hv's fleet already holds its own `.intent_critic.yml` and none carries the injected line, and the seed is written only where the file is absent, so the fleet sweep after the 3.2.1 cut, which runs `intent claude upgrade --apply` in every estate, writes no corrupted copy.
