Swap out the bespoke logging console functionality and use the macOS Console app as the visual log viewer for the menubar app. See how this is done in the Utilz menuz menubar app (hv, 17 Oct 2026: "one thing that menuz does that I really like that would simplify Intent, Conflab and Gtools").

How menuz does it (Utilz, `native/macos/Menuz`): every run appends to one log file, `${XDG_STATE_HOME:-~/.local/state}/menuz/menuz.log`, and the menu's `Open Log` item opens that file with `/usr/bin/open` (`MenuzApp.openLog`, a failure logged and never dropped), which hands a `.log` file to the macOS Console app: search, filtering, live follow and a window are Console's, not the app's. `utilz menuz log` tails the same file in a terminal, and the app's own messages go to OSLog (`Logger`), which Console also shows. There is no console window controller, no tailing view, no log model and no log buffer in the app.

The change here: drop the app's own console window and the code that tails and renders the log behind it, and put one item in the menu that opens the log file (or the daemon's log file) in Console. Keep the CLI's `log`/tail verb for the terminal. Measure what the current console shows that a plain log file would not (eg a daemon's log that is not a file, or coloured levels) before removing it, and route that into the file or OSLog first.
