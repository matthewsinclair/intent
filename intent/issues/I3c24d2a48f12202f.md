hv found this on kovacs (Ubuntu ARM64, brew 3.5.3), and devbin-vc relayed it.

On Linux, `intent app status` prints "error: Intent.app is not built or installed on this machine -- looked in /Applications". Its remedy says `brew install --cask matthewsinclair/intent/intent-app`. A cask cannot install on Linux, and Intent.app is macOS only. So the error and its remedy are both wrong on Linux.

`intent app start` and `intent app restart` have the same fault: they find no bundle on Linux, so they give the same error and the same cask remedy. `intent app stop` prints "ok: Intent.app is not running" and exits 0, which is true, so it stays as it is.

Fix: on a platform other than macOS, `intent app status` says that Intent.app does not apply to this platform. It exits 0 and gives no remedy. `intent app start` and `intent app restart` refuse with an error that says Intent.app runs on macOS only. They exit non-zero, and their remedy names the `intent` CLI and never an install. Put the platform check in one place in the library, and keep the CLI a thin coordinator. Add one test arm for status and one for start, which also covers restart.

Resolution: Shipped in v3.5.4 (tag at 0eb2295119a0): da0a9ed61 and 5c9d3fd32. intent app says that Intent.app is macOS only on another OS.
