**A SEAT RUNS `intent wb pickup` AT BOOT AND THEN HOLDS THAT READ AS CURRENT FOR HOURS, AND NOTHING SAYS SO.**

**Seen on 2026-11-10 on one four-seat board in its first day, and reported to intent-vc by that board's vc and by one of the seats.** One seat quoted a roster it had read three hours earlier and asked whether what it described was the new format, when the board had been corrected half an hour after that read and written to three times since. A second seat sat on a heartbeat hours old with two unread messages. The first seat also held a message telling it to load its language skills again, unread for hours: it had picked up at boot and never again, and it loaded them only when the board's vc told it, in its own window, to pick up.

**Why a message cannot fix it.** A message reaches a seat at its next pickup, and a seat that is working has no reason to run one. The seat that booted on stale state is the seat that stops looking. One of the seats put it this way: anything a seat is told once, at boot, needs a way to go stale loudly.

**The ask.** `intent wb pickup` and `intent wb status` print the age of the acting node's own last pickup, and each peer's row says how many messages have been sent to that peer since its last pickup. Both read fields the board already holds.

**Lane.** This is the code ST0092's WP-06 reworks, what a pickup prints, so cc builds it with that package (intent-vc, 2026-11-10, under hv's pen). It rides 3.3.0 unless hv holds it back.

ITS SHAPE RULED (intent-vc, 2026-11-10, under hv's pen, on cc's design note). The ask above says both readings come from fields the board already holds. They do not: a pickup's own event is machine-scoped and never reaches the board's canon, and the heartbeat is moved by a touch as well as by a pickup. So:

- `intent wb pickup` prints how long ago the acting node last picked up on this machine, read from the store's own `wb.pickup` events before this pickup writes its own. `intent wb status` has no acting node, so it prints the same age on the row of every seat a session drives.
- Where the store holds no pickup of the node, as on a fresh clone, the line says so and prints no age. One arm pins what a store ingested fresh from canon prints.
- Each peer's line gives the number of live messages addressed to that peer, labelled live. A count since the peer's own last pickup would need that same machine-scoped event, and a live message is the one a peer has not handled, which is what the reader needs to know.

It is built with ST0092's WP-06, whose body carries the same three lines.
