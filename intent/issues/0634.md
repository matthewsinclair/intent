Proposed 2026-10-23 by rhadamanth-sysadm, with hv's agreement relayed by it (not yet hv's ruling in this record), during the gyges move (Molt ST0006 WP04). Filed by vc behind the line, as new surface for hv to rule on.

## What

Intent.app has no Homebrew cask. `brew install matthewsinclair/intent/intent` gives `intent` and `intentd`; `intent app start` then says Intent.app is not installed and its remedy is a manual download of `Intent.app.zip` from the release. The tap holds `Formula/intent.rb` and no `Casks/`. So every sleeve installs the app by hand and `brew upgrade intent` leaves it on the old version: rhadamanth's copy was hand-installed on 8 September and is 3.2.5, signed Developer ID Geodica Pty Ltd (76BQL8L47U) and notarized; gyges takes 3.2.5 from the release zip, checked with `spctl` before it goes into /Applications.

## The proposal

An `intent-app` cask in the matthewsinclair/intent tap, so Intent.app installs and upgrades through Homebrew like the CLI. What a cask needs is mostly there: the release ships `Intent.app.zip` (about 1.4 MB at 3.2.5), signed and notarized. What is missing is a published checksum: releases publish none today, and the cask's sha256 would come from the release process, which would also give a manual install something to check against. ST0081's D55, in build in Devbin on 2026-10-23, attaches one SHA256SUMS over every release asset, which is where that checksum would come from.

## For hv to rule

Whether the cask is built and in which cut; whether `intent app start`'s remedy then names `brew install --cask matthewsinclair/intent/intent-app`; and where in `intent/docs/releasing.md`'s cut sequence the cask's sha256 is written and pushed (beside `int brew formula --push`, which already pushes the formula). No lane until hv rules.
