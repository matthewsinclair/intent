**A v2 THREAD THAT SITS OUTSIDE v2's STATUS BUCKETS KEEPS ITS v2 `info.md` AFTER `intent upgrade`, SO `intent doctor` EXITS 1 ON THE FRESHLY CONVERTED ESTATE AND THE NEXT UPGRADE PRINTS A REFUSAL BEFORE ITS `ok:`.** v2 has no hold bucket, so a v2 On Hold thread sits at the flat path, and so does any closed thread v2 never moved into its bucket.

**What was seen.** dc's drive of 2026-10-14 (the setup is in 0596), in the layouts with an On Hold thread flat and with a Completed thread flat. v3's default manifest declares WIP only, so the thread is left undeclared, and its v2 info.md (192 bytes in one drive, 194 in another) stays at its v3 view path. `intent doctor` exits 1 with view-skew, before and after the migration commit, and its remedy, `intent st hydrate --overwrite`, pins the held thread in .intentfiles. The second `intent upgrade` prints "error: refusing to dehydrate .../info.md: the file on disk (192 byte(s)) differs from what the store renders", with a remedy to delete it and re-run, then `ok:` at exit 0. docs/migrating-from-v2.md:18's "the upgrade removes it and names each path" is false for that file.

**Mechanism.** Three causes together. The prune's population is rooted at the bucket names and nowhere else (`legacy::leftovers`, `native/rust/crates/intentsvcs/src/legacy.rs`, whose comment cites ST0069 AC-02.3), so a flat thread's v2 file is never v2 source to it. 0596 skips the dehydration on a first conversion. And when the dehydration does run, organize's gate refuses the file because it is not the render, which is right: the gate removes only a byte-identical view.

**Fix (S), and it needs a ruling first.** The v2 info.md of a flat thread that the conversion leaves undeclared, and whose content canon holds, becomes removable v2 source in `legacy::leftovers`, which facade.rs:4483 makes the one derivation of "may this go?" for both doors, the upgrade and `organize --apply`. That widens the prune's ruled population (ST0069 AC-02.2, read through AC-02.3), while AC-02.3's protected case, a tool tree such as `ST0056/parity/tools/`, stays protected. Arm: the On Hold-flat fixture, red at the base (doctor exits 1, and the refusal) and green with the fix. The page's prune sentence is corrected and a CHANGELOG line goes under 3.2.4. If the widening is not ruled, the page says instead that a held v2 thread's info.md is left for the operator to delete.
