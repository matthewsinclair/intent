Found on 2026-10-27, landing ST0087's 0087-hermetic (9109e59eb). cc read the cause, and vc confirmed it in bin/.devbin/cmd/prepush and bin/.devbin/cmd/shared/currency.lib.

The currency verdict counts the files changed under DIRT_SCOPE since the delivered pair's marker, minus the UNSHIPPED pathspecs in native/rust/build-support/source_commit.rs. Those pathspecs exclude only `native/rust/crates/*/tests/**` and `native/rust/crates/*/benches/**`. `testkit` is a whole crate that intentsvcs, intent-cli and intentd take only as a dev-dependency, so no shipped binary contains it. Its `src/` is still counted.

9109e59eb changed `native/rust/crates/testkit/src/lib.rs` alone outside the tests. That was enough to put the delivered pair at f06241f83b56 behind HEAD, although no shipped source had moved. Three consequences were measured or read:
- `intent install` refuses: "publishes only a pair built from HEAD's build inputs", measured by vc at 15:56Z by date -u.
- Intent's pre-push hook refuses a push, a board-only push included, until `bin/devbin build all` at HEAD. That is the currency verdict in prepush, from issue 0518 and hv decision 30.
- `bin/devbin cli` refuses that pair too (cc's read).

THE ASK: a crate that only dev-dependencies reach counts as unshipped, as tests and benches already do, so that a test-support change leaves the pair current. Name it in UNSHIPPED with an `exclude` pathspec, or derive it from the manifests, so that it cannot drift from Cargo.toml. Either way, a guard should catch a crate that becomes a normal dependency while it is still listed as unshipped. The change is itself a build input, so it takes effect only from the next `build all`.

Low: it costs one rebuild when a dev-only crate changes, and it refuses rather than passes, which is the safe direction.
