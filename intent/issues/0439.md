`intent wb migrate` reads an inbox that Intent itself already rendered as a hand-authored one, and refuses the carry on Intent's own footer.

Found by cc on 2026-09-17 in the all-estate trawl's first pass, on a scratch clone of Courses. Courses registered `hv` at its cutover (`50ec2ed`) without carrying the board, so `hv`'s three inbox files are already rendered views: the routing header, the empty sentinel, then the footer every generated view carries (`---` and `_Generated by Intent v3.0.3 from the whiteboard model ..._`). Migrate names those two footer lines of each file as uncarried units (`above the first ## (...) entry ... this line belongs to no message`) and refuses the node on six units, none of which anybody wrote. A drop carried the board's two items and dropped exactly those six lines, so the refusal is spurious from end to end.

What is wanted: migrate recognises a rendered inbox view by the footer the renderer writes (one home for that text, the renderer's) and offers none of a rendered view's lines as units, so a node whose inboxes were rendered before its board was carried migrates on its board alone. One arm: a registered node with rendered empty inboxes and a hand-authored `wip.md` carries without a refusal and without a drop flag.
