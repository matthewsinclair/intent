## What is broken

`testkit::assert_no_orphan_suite_members` (native/rust/crates/testkit/src/lib.rs) passes over a test file that no target compiles, in two cases.

1. A `#[path]` line with no `mod` item after it. `declared_suite_paths` takes every trimmed line of the form `#[path = "<name>"]` as a declaration. It does not check that a `mod <ident>;` item follows. When the `mod` line is removed or commented out and the attribute line stays, nothing compiles the file, and the guard still counts it as declared.
2. A directory test. The guard lists only the regular files directly in `tests/`. With `autotests = false`, nothing compiles a `tests/<dir>/main.rs` that no `[[test]]` target declares, and the guard does not see it.

## What it costs

The tests in such a file never run, and nothing reports it. That is the failure that the guard exists to stop (IN-RS-TEST-003).

## What fixes it

1. Count a `#[path = "<name>"]` line as a declaration only when a `mod <ident>;` item follows it. Blank lines, comment lines, and other attribute lines can come between the two.
2. List `tests/<dir>/main.rs` too, and report it as an orphan unless a `[[test]]` target in the manifest declares it.
3. Add a negative control for each case.

One limit stays after these fixes: a `#[path]` and `mod` pair inside a block comment still passes, because the guard reads lines and has no lexer.
