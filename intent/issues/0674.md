**testkit's `sweep_abandoned_fixtures` CAN DELETE A LIVE FIXTURE: ONE WHOSE PROCESS WAS BORN AFTER THE SWEEP READ THE LIVE SET AND PLANTED IT BEFORE THE SWEEP LISTED `/tmp`.**

**Found by reading the source on 2026-11-01** (intent-dc, while fixing the race in `a_run_leaves_no_corpse_of_its_own_behind`; read again by intent-vc). `crates/testkit/src/lib.rs:420-446` takes `live_pids()`, one `ps -Ao pid=` snapshot, first, and calls `read_dir("/tmp")` second. A process born between the two is missing from the snapshot, so a fixture it creates before the listing reaches that entry names a pid the sweep reads as dead, and the sweep removes it while its process runs. The doc's guarantee at `:408-411`, that pid reuse "can only make this KEEP an abandoned directory ... never delete a live one -- a live fixture's own process is alive by construction", holds only for processes older than the snapshot.

**Where it can bite.** Every `/tmp` fixture creation site, seven files across intent-cli's and intentd's tests, calls `sweep_once` at start, and testkit's own suite sweeps on its test threads, so a suite that starts while another sweeps can lose a fixture it creates in its first milliseconds. The window is the sweep's `ps` call plus its listing, a few milliseconds, wider under load.

**The fix, assigned by intent-vc under hv's word that obvious bug fixes are not new code (vc decision 106):** list the candidates first and take the live-pid snapshot second. A fixture that exists when the listing reads it was created by a process born before the snapshot, so if that process still lives the snapshot names it; a reused pid only keeps an abandoned fixture one more round, which errs safe. The proof is a seam between the two steps through which a live child's fixture is planted: the base sweeps it every time and the fix keeps it every time. testkit is unshipped, so no CHANGELOG entry.
