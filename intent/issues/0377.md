title: the canon watcher's file-ID cache walks the intent tree on every event, so a commit costs the daemon about ten seconds of system time

On the delivered pair 4c172d260 (daemon 16233, the 0355 fixes live and the store at schema 26), one two-line board commit costs the daemon about 13 s of CPU, most of it system time on the canon registration's `notify-rs fsevents loop` thread (8.1 s sys and 0.95 s user across the commit, `ps -M` before and after), with the store thread at 1.7 s user and 1.8 s sys. A `sample` taken while the daemon was hot during that commit puts the working samples in `__open_nocancel`, `stat` and `__getdirentries64` under the debouncer lock (`__psynch_mutexwait`), with sha256 a distant fourth: a directory walk, not store work. That is the `FileIdMap` cache the canon registration keeps (root non-recursive plus `intent/` recursive, kept byte-for-byte by decision 9 of 2026-09-12 when the index registration moved to `NoCache` under 0355): every Create event under `intent/` and every rescan re-walks what the event names with a stat per entry, before any ignore rule applies, and a commit's gate and ingest produce a burst of exactly those events (view rewrites, `intent/.cache/intent.db` and its WAL, `.git` is not under it). Six board and issue commits in seven minutes after the daemon's open (12:09Z to 12:16Z) cost it 94 s user and 110 s system in total, against roughly 8 s and 11 s for three commits on the previous pair, so the per-commit figure is the same order and the flood adds up; 81 s of that user time sits on one thread that the two listings (`ps -M` rows against `sample`'s thread order) place either on the store thread or the registry watcher's loop, and it is not attributed. The daemon idles between events on this pair (a few hundred syscalls per four seconds) and a single in-scope touch costs 0.21 s, so this is a bounded cost per commit, not a spin.

Remedy candidates, none ruled: `NoCache` on the canon registration too, with the tests that pin its shape updated to the events it then emits (a rename arrives as Remove plus Create, which canon ingest already handles as a vanished path and a leaf); or a cache whose walk honours the corpus's ignore rules. Evidence in vc's scratchpad: intentd-16233-commit-sample.txt, psM-16233-c.txt and psM-16233-d.txt.
