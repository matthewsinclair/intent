Found on 2026-11-12, when hv looked for ST0090 WP-02's second line (AC-02.4) on the installed 3.3.0 app. The Intent in the menu bar was not that app. It was a 3.2.6 Debug build of 8c77b10e6, built 2026-10-26 at `~/.local/state/intent/build/macos/Build/Products/Debug/Intent.app`, which predates WP-02, so its Rebuild Search Index row had no second line. The login item started it at the reboot of 2026-11-11 20:30:00Z (the app at 20:31:55Z), and `/Applications/Intent.app` (3.3.0, its executable written at 17:32Z) had not run since.

The cause is in `AppDelegate.applicationDidFinishLaunching` (`native/macos/Intent/Intent/IntentApp.swift`). On a launch where the `FirstRunDone` default is unset, the app sets it and registers itself as the login item through `SMAppService.mainApp`. A Debug build and the release build share the bundle identifier `com.matthewsinclair.intent.macos`, so they share that default and that login item. Whichever runs first registers its own bundle, and the other never registers. A Debug build run once from a dev tree therefore keeps the login item, and every reboot starts it in place of the installed app.

The fix, on vc's ruling of 2026-11-12: a Debug build neither registers the login item nor marks the first run done, so only a release build's first run registers, and a Debug run never uses it up. The decision is a pure function the tests ask directly. The registration already on hv's machine is swapped by hand in System Settings > General > Login Items, which vc has put to hv.


## Resolution

Fixed for the release after 3.3.0, in the commit that carries this resolution, banked as `refs/bank/dc/0687/fix-proven-on-594422fb4` and landed by vc. `AppDelegate.registersLoginItem(debugBuild:firstRunDone:)` is the decision, a pure function: only a release build's first run registers the login item and marks `FirstRunDone`, so a Debug build neither takes the login item nor uses up the first run. `LoginItemTests` asks it directly.

Proved on gyges on 2026-11-12, in a clone of rhadamanth's main at 594422fb4 carried there as a git bundle, with `bin/devbin macos app-test`. With the tests alone, on the code as it was, the test target did not compile: `type 'AppDelegate' has no member 'registersLoginItem'` at `LoginShellTests.swift:120`, 124, 125 and 129, and `xcodebuild test` exited 65 (10:13:35Z to 10:13:58Z by gyges's `date -u`). With the fix: 82 tests, 82 passed, 0 failed, in 9 suites, `LoginItemTests` (3) and `LoginShellTests` (8) among them (10:14:12Z to 10:14:28Z). The fix's patch on 594422fb4 is the same blob as the one banked on 7f9064cc3, `f7909ebd7`.

The login item already registered on hv's machine, the Debug build's, is replaced by hand in System Settings > General > Login Items, on the steps vc put to hv.
