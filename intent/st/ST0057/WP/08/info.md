# WP-08: The mutation surface: write-by-address and the missing verbs

## Objective

Make every state mutation reachable through a typed, addressed interface -- and close the verbs that do not exist.

## The write path (hv, 2026-08-18)

**DB first, then canon ALWAYS, then views IF MARKED.** Not "disk if marked" -- that collapses canon into views and leaves a dehydrated artefact inside a gitignored database, absent from a fresh clone.

## Create splits by id origin

- **Caller-assigned** (`AC-10.11`, `AT-10.11`) -- `PUT` to the entity address, idempotent.
- **Server-assigned** (threads, issues, WP seq) -- `POST` to the COLLECTION address, which returns the new address. You cannot address `ST0058` before the tool has decided it is `ST0058`.

## The mutation format IS the interchange format

`GET ?format=json`, modify, `PUT` the same shape back. **This gives AC-02.6 a second job: a field that does not round-trip is a field that cannot be WRITTEN**, so the lossless 1-1 mapping becomes the completeness guarantee for the whole mutation surface, not only a durability guarantee at the clone boundary.

**`PUT` accepts `json` only.** Markdown-in would promote a stale rendering into canon, which 5.1b forbids. The one exception is not an exception: an ATTACHMENT is authored on disk, so for attachments authority runs the other way and text-in is correct.

## Also in scope

- **`intent at green|red|na` DESTROYS the row's authored note** (issue 0033) -- a verb that mutates one field and silently clobbers an adjacent one is the opposite of type-checked.
- **A bare family invocation reaches a mutation**: `intent backup` with no subcommand creates a snapshot, PRUNES an existing one under an unconsulted retention policy, and rewrites the store file.
- **`st edit` is unimplemented while its `--help` fully describes behaviour** it does not have.
