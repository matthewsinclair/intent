# WP-03: Attachment canon: opaque as file, and the naming gate

## Objective

Give opaque attachments a canon home so they can dehydrate, and put a naming gate in front of every new attachment.

## Deliverables

- **Text attachments** stay inline as `Attachment.text`.
- **Opaque attachments** stored as FILES at `intent/.canon/st/<ID>/<path>`.
- The naming gate: improperly-named NEW attachments are REFUSED at ingest.
- `sha256` drift detection on the working copy, surfaced through `doctor`.

## Why the canon file is what makes dehydration legal (D57-7)

D57-3 permits removal only of a file `organize` can regenerate **from a source sitting beside it in the same commit**. It does not say the source must be JSON. The canon copy IS a source, it IS in the same commit, and regeneration is a byte copy.

**The rejected first answer was "opaque attachments never dehydrate."** Measured, that pins 240 non-md/json files to disk permanently -- 196 of them `.tap` baselines under `ST0056/parity/tools/tap-baseline` outliving ST0056 forever -- which is the exact condition `.intentfiles` exists to end.

**`intent/.cache/` is refused as a home.** It is gitignored, holds only the store, has 0 tracked files, and its ignore rule is D29's precondition. And `cache` naming an unregenerable file fails in the dangerous direction: `rm -rf intent/.cache` is a reasonable thing to do to a cache.

## Rejection is NOT retroactive

The estate already carries a violator -- a `.webloc` with SPACES in its name, which split into eight fragments under `xargs` while the run still printed a plausible four-digit total. Existing violators are reported by `organize` as UNCLAIMED under its fifth row and **never silently removed**.

## Known hazard for whoever takes this

cc's collection verifier carries a SECOND, deliberately independent copy of the classifier's eligibility rules, so that it can disagree. **When the opaque-attachment form lands, that copy goes stale silently unless it is deleted or promoted to a real test.** It has a shelf life and cc has written that into it.
