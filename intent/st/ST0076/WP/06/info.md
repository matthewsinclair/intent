# WP-06: Elixir resolved references through the compiler's tracer, on an explicit verb

## Objective

Resolve Elixir references to the definitions they name with the compiler's own tracer, on an explicit verb, into the level-3 core both languages share. A Mix project at the project root compiles, in the `dev` environment whatever the shell holds, into a build of Intent's own under `intent/.cache/resolve/elixir/dev`, seeded from the project's `_build` and never writing it, forced when the build is made and on the first run and `--full`, and incremental otherwise. A call the compiler resolved joins the written reference on its file, line and name as `Module.name/arity`, a module reference as the module, and a directive such as `use` resolves to the module it names; expansion is kept out by the events the tracer records and by the column a written reference carries. A failed compile is recorded with the file and line Mix names rather than stored. The search envelope's level-3 facts and `--target` are WP-07's.

## Measured first (dc, 2026-09-17)

On a scratch copy of Laksa (Elixir 1.20.4, OTP 29, 537 `.ex` files; source, `deps/` with their `.git` directories, and `_build/dev` copied; the live estate untouched). The tracer was a module loaded with `elixir -r` and passed as `mix compile --tracer`, writing one row per event.

- **A full forced compile** took 69 s, exited 0 and recompiled no dependency. It produced 383,641 events (40 MB): `remote_function` 195,535, `alias_reference` 70,754, `remote_macro` 53,840, `imported_macro` 22,549, `require` 10,423, `import` 8,236, `local_function` 6,475, `imported_function` 5,441, then `alias_expansion`, `struct_expansion`, `alias`, `on_module`, `defmodule`, `start` and `stop` (537 each), `imported_quoted` and `compile_env`.
- **Most events are compiler expansion, not written references.** The top `remote_function` targets are `:erlang` 45,644, `Module` 39,458, `:elixir_def` 18,758 and `:elixir_quote` 9,752, generated by `use Ash.Resource` and similar and attributed to the `use` line. No field this first tracer recorded separated written from expanded; the compiler's own `:column` does (below). 21,664 rows are exact duplicates, 10,718 have no line, and 19 "files" are not project files (`@builtin`, `@component`, `@plugs`, `@prototype_schema`, and paths inside Elixir's own `lib/`).
- **The module distinction exists.** `get` arrives as `Access.get/2` 1,822, `Process.get/2` 852, `Map.get/2` 428, `Map.get/3` 313 and `Keyword.get/3` 254.
- **A tracer that raises aborts the project's compile.** The first tracer did, on the bare-atom events `:start` and `:stop`.
- **An incremental compile sees only what it recompiles.** Mix digests content, so `touch` alone compiled nothing and traced 0 events. Restoring a changed file compiled that 1 file and traced 90 events.
- **A failed compile leaves a plausible partial trace.** A forced full compile with one leaf file broken exited 1 after 16 s, with a `MismatchedDelimiterError` naming file, line and column. By then it had traced 244,414 events from 340 of 537 files, with 340 `:start` and 263 `:stop`. The gap between the 69 s and 16 s runs is unexplained on this host's load, so no timing claim is made beyond tens of seconds.
- **A written reference carries a column and an expansion does not** (dc, on a probe Mix project, Elixir 1.20.4 / OTP 29). Every written kind carried `:column` in its meta: remote, imported and local calls, remote and local captures, pipe targets, `__MODULE__` calls, the directives and module references. Generated events carried none: a written `to_string(total)` traced `Kernel.to_string/1` with a column and its expansion `String.Chars.to_string/1` without one, on the same line under the same name, so the join alone would have stored both. A syntax error fails before any `:start`, and an undefined function runs from `:start` to `:stop` and still exits 1, so the exit status is what names a failed compile.

## Rulings (vc, under the pen, 2026-09-17)

1. **A resolved row always resolves a written reference.** Level 3 never adds a reference that level 2's syntax does not have. It joins a tracer event to the WP-03 syntax reference in the same project file, on the same line, with the same name, and records on that row the module, name and arity the compiler resolved. An event with no matching written reference is compiler expansion and is not stored as a reference. The written `use Ash.Resource` is itself a reference and resolves to that module. Events with no line, and events from files outside the project, are dropped, and duplicates collapse onto the one row. **Nothing is dropped silently:** `intent index status` counts events matched, expanded-unmatched and dropped per language, so a join that stopped matching shows. WP-05 applies the same join to SCIP occurrences, so both languages mean one thing by level 3. **Expansion is kept out twice** (vc decision 27): the tracer records only call and module-reference events, and a call or module event whose meta carries no column is counted as `expansion` and never joined, because a macro's expansion can share the written line and name. A forced compile whose reference events carry no column at all fails the run (vc decision 29, correcting decision 27 forward: every `defmodule` traces a call with no column, so an incremental compile of a file holding no written reference records only columnless events and is not a failure). The test cannot see a macro that reuses a written node's meta for a call it generates, and that call is treated as written.
2. **The tracer never raises.** It catches everything around each event. A tracer fault is a failed run under 3, never an aborted project compile.
3. **A failed run stores nothing.** On a non-zero exit, or any file with `:start` and no `:stop`, nothing from that run is stored, and the envelope names the failure (file, line, message) beside the syntactic answer. Earlier good level-3 rows are kept, each carrying the content hash of its file at trace time. A file whose bytes have changed since then answers with its level-3 rows marked stale, never as current.
4. **Stored per file, replaced per file, in a build of Intent's own.** A run replaces exactly the files it compiled from `:start` to `:stop` whose bytes hashed the same before the compile and after it. The compile builds the `dev` environment into Intent's own cache under `intent/.cache/resolve/elixir/dev`, seeded from the project's `_build/dev/lib` with its relative symlinks re-pointed, and re-seeded when `mix.lock` differs from the hash kept beside the seed. A run that seeds or re-seeds forces the compile, the first run and `--full` force it, and every other run is incremental. The project's `_build` is never written. The reader reads no environment variable: the compile is given `MIX_ENV=dev` whatever the shell holds, so code only another environment compiles, such as `test/support` under `elixirc_paths(:test)`, is not traced (vc, 2026-09-17, on AC-11.3's census; this narrows decision 27's `<env>`). It reads a Mix project at the project root only, and a project with no `mix.exs` there is not applicable: the reader's manifest is `mix.exs` at the root and nowhere below it, the one rule WP-07's search answers read as well. It runs on an explicit verb only, never from intentd. _This ruling first had the compile run in the project's own `_build`; vc replaced it at 06e046a89, in AC-06.1's text, after dc measured a shared build missing a file the user had compiled._
5. **Proof, in Laksa:** the callers of `Map.get/2`, without `Access.get/2`, `Process.get/2` or `Keyword.get/3`. The design's Proof section is edited to match after WP-01's vocabulary lands.

## Measured on the landing's tree (dc, 2026-09-17)

The same scratch copy of Laksa, its index kept, resolved by an `intent` built from 1a25373a6 with this work package's bank as it then stood (patch-id c4b326db). The landing's patch differs from it only in building `dev` whatever `MIX_ENV` holds, and the drive ran with `MIX_ENV` unset, so it built `dev` too. A script that mirrors the reader's parse and the core's join over the saved trace and a copy of the store reproduces every count below, so the attributions are the run's own.

- **The first run** forced the compile into `intent/.cache/resolve/elixir/dev` in 13.6 s and recorded Elixir `current`: 30,856 matched, 17,538 unmatched, and 326,308 dropped (`expansion` 316,167, `operator` 9,399, `quoted` 29, `unread` 713), with 27 keys naming two targets, over 30,224 stored rows. Nothing was written outside `intent/.cache`, and `_build` was not touched. A second run compiled nothing, traced nothing and stayed `current`, and the stored rows stayed.
- **The column test.** Keys (file, line, name) in the project's `.ex` files naming two or more targets: 5,001 of 116,156 over every event, 27 of 46,943 over the events with a column. Of the written references in the files the run read, 30,197 have an event with a column and join; 8,037 have no event at all, among them typespecs such as `String.t` and field accesses such as `.id`; and 6 are dropped because their only events have no column, all `is_nil` inside an Ash expression, four in `expr(...)` and two in `Ash.Query.filter(...)`, whose macros emit the call with no column.
- **What `unread` is** (vc's note): the 713 events carry a template's path, 696 a `.heex` file's and 17 an `.eex` file's, which the index holds with no language and the run never reads, so the join names them `unread` before it asks whether they are indexed.
- **Module mentions through an alias** (vc's note): the tracer names a module in full, and 11,266 mentions matched, 2,594 of them written short through the file's own `alias`, which the index stores expanded (WP-03). 94 are unmatched: 23 name a nested module by the short name its `defmodule` makes, 22 in struct literals such as `%Action{}` and one as `__MODULE__.Live`, which the index does not expand; and 71 have no written row on their line, the modules of a multi-alias brace (39), a protocol named by `defimpl` (10) and 22 more, such as a nested `defmodule`'s own name.
- **What is unmatched** is almost all calls, 17,444, that the compiler sees and nobody wrote as a call: `Module.compile_definition_attributes/6` 5,810, `Kernel.defp/2` 3,521, `Kernel.to_string/1` from interpolation 2,407, `Kernel.def/2` 1,559, `Phoenix.Component.Declarative.__on_definition__/6` 714, `Kernel.if/2` 504 and `Access.get/2` from bracket access 437. They are counted and not stored (hv decision 22).
- **A known limit of the key** (vc, 2026-09-17, for ST0077): a reference only the compiler sees joins a written reference on the same line under the same name, so a bracket access beside a written `Map.get(...)` stores `Access.get/2` beside `Map.get/2`, and an interpolation around a written `Integer.to_string(...)` stores `Kernel.to_string/1` beside it (17 of the 27 keys naming two targets on Laksa; the other 10 are two written calls of one name on one line, as `DateTime.new!(Date.new!(...))`); such a key answers at its syntax level with its candidates, and the door reads it as one of two.
- **A target's place is the one it had when the reference's file was joined** (vc, 2026-09-17, for ST0077): the reader carries no target location, so the core places each target through the index at the join, and a file an incremental compile leaves alone keeps the definition line its target had then, while `stale` reads none once the target's own file is joined again; a Rust run clears it because every Rust run is full, and ST0077's roster of targets is where placement would refresh on every run.
