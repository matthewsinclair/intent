## 1. `AGENTS.md` -- the primary contract never arrives. **MISGUIDED**

**What it is:** the tool-agnostic contract. Generated by `intent agents sync`; `NotByInit` (correctly -- seeding a generated file teaches the operator it is theirs to edit).

**The defect.** `CLAUDE.md` line 3: _"The primary config file for AI coding agents is `AGENTS.md` at the project root -- **read that first**."_ Nothing executes that instruction. No `@`-import exists in `CLAUDE.md`, `~/.claude/CLAUDE.md` or `AGENTS.md`. `/in-session` -> `/in-standards` step 1 names CLAUDE.md, MODULES.md and DECISION_TREE.md, and **does not name AGENTS.md**. This session booted by the canonical path and never read it.

**Scope, stated precisely because the obvious reading is wrong.** AGENTS.md is the cross-tool convention and other agents do load it automatically; it is not dead weight. The finding is narrower: **within Claude Code, the tool-agnostic contract is the one document that reliably does not arrive**, and the agent is told it is holding the secondary overlay with no way to notice the primary never came.

**Compounding it -- the four rules.** `_CLAUDE.md` deliberately omits Highlander / PFIC / Thin Coordinator / No Silent Errors, and says why: _"a second copy would be a Highlander violation in the document that defines the rule."_ The reasoning is impeccable as document design and wrong as context design -- **Highlander governs a single source of truth, not a single source of delivery.** Measured: `IN-AG-` appears 4x in AGENTS.md (never loaded), 8x in `in-standards` (loaded every session), 2x in CLAUDE.md. So the rules do arrive -- via the skill, not the canon -- and **the duplication the comment was avoiding already exists between AGENTS.md and in-standards.** The document reasoned itself out of carrying them on grounds that do not describe where the copies actually are.

**Verdict: MISGUIDED.** Not because the file is wrong -- it is the best-organised document in the set -- but because the canon asserts a loading order that no mechanism implements, and an agent that trusts CLAUDE.md line 3 believes it has read a contract it has not.

**Coordination:** ST0067 AC-00.4 (cc, hv-ruled 14:38Z) adds a pointer line here to `intent llm guide`. Correct and worth building; it closes the loop for tools that load AGENTS.md and not for Claude Code. Flagged to cc 14:43Z. **I have not touched the template.**

## 2. `intent/llm/MODULES.md` -- the retirement reached the file and not the instruction. **MISGUIDED**

**What it is:** the Highlander registry. `init.rs` retired it on 2026-08-24 -- `NotByInit("a hand-maintained index of a tree the store already indexes")` -- with the reason stated in the source comment: _"an instruction nobody can follow."_

**Driven, not inferred.** A fresh `intent init` in a scratch dir: **`intent/llm/MODULES.md` ABSENT**, and that same fresh project's generated **`CLAUDE.md:21` still says "Highlander registry; check before creating new modules."**

**Four documents still issue the instruction; three ship to every project:**

| Site                                                  | Reaches                                 |
| ----------------------------------------------------- | --------------------------------------- |
| `lib/templates/llm/_CLAUDE.md:21`                     | every project's CLAUDE.md (auto-loaded) |
| `lib/templates/llm/_AGENTS.md:262`                    | every generated AGENTS.md               |
| `in-standards` SKILL.md:14 -- "Re-read project rules" | **auto-loaded into every session**      |
| `in-standards` SKILL.md:56 -- Red Flags row           | same                                    |

**Size.** Intent's own copy is **571769 bytes (~143k tokens)**. `CLAUDE.md` states "~354KB across ~367 rows" -- **stale by 62%**, and it is the figure the file uses to argue the read is impossible.

**Verdict: MISGUIDED.** A fresh v3 project receives four instructions to consult a registry its own `init` deliberately refused to create. The fix landed on the laydown path and not on the instruction path -- the same shape as the shim-carrier class (a repair aimed at one layer while another still carries the old contract).

## 5. `intent/wip.md` template -- 2025 chat-era advice. **RETIRE (body) / MISGUIDED (the LLM section)**

**What it is:** `lib/templates/prj/_wip.md`, 1090 bytes, `verblock: "06 Mar 2025:v0.1: Matthew Sinclair - Initial version"` -- the oldest thing in the set, and the only canon template that carries a `verblock:` frontmatter field at all. (`_AGENTS.md` matches a grep for the word because it _prescribes_ verblocks at line 145; it does not carry one. Checked, because the two are different claims.)

**Contents:** placeholder scaffolding (`**002: [Brief description of the current development focus 2]**`, listed above `001`), a `## Notes` stub, then a `## Context for LLM` section instructing: _"When beginning work with an LLM assistant, **start by sharing this document**"_, followed by `### How to use this document`, four numbered steps addressed to the human.

**Two defects.**

**(a) It is the exact anti-pattern the good templates name.** `_RULES.md` and `_ARCHITECTURE.md` both ship deliberately empty and both argue the case: _"a heading waiting to be filled reads as a commitment the project has not made"_; _"a skeleton of headings and placeholder trees reads as a specification the project never committed to, which is worse than nothing."_ `_wip.md` is that skeleton. **Two templates in one directory holding opposite philosophies, and the better one has already written the argument against the worse.**

**(b) `## Context for LLM` teaches a workflow the tool replaced.** "Start by sharing this document" is March-2025 copy-paste-into-chat practice. Under Claude Code the equivalent is a session hook and `/in-session`, both of which this project ships. An operator following it does something unnecessary; an LLM reading it infers a mode of use that is not how it is being run.

**Verdict: RETIRE the placeholder body; MISGUIDED for `## Context for LLM`.** Strongest candidate in the set for deletion rather than repair.
