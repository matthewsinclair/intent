Its answer was a collision check in `vault set`, which was **structurally blind** -- stores are per-project, those three references live in three different stores, and the check had no jurisdiction where the collision happens. **It could not have been repaired either: a correct cross-store scan must open every store, which needs the identity, which fails under `Locked` and breaks R10.** The check is deleted and the grammar carries it: `_` is forbidden inside segments, so a single `_` in the derived name can only be a `-` and `__` can only be a separator. -- satisfied: no (computed)

That is the right failure (typed, never a wrong answer) and it is still platform-divergent behaviour that R2 as written does not permit, so this criterion asserts one code path **in the default posture** and asserts the exception's boundary in the hardened one.
