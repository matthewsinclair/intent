# ST0079: Add 'outs[tanding]' verb to show all outstanding items from a single verb

## Objective

`intent outstanding`, with the alias `intent outs`, prints everything open and in progress in one table: the steel threads bare `intent st list` shows, the work packages in progress under any thread, and the issues bare `intent issues` shows. One row each, the kind (ST, WP or Issue) in the leftmost column, then the ID, status and title all three kinds carry. `--show` narrows the table to the kinds it names.

## Context

hv's ask (2026-09-21, relayed by vc): a snapshot of what is open takes three commands today -- `intent st list && echo " " && intent issues`, plus `intent wp list` per thread for the packages -- and should take one, `intent outs[tanding] --show=[st,wp,is[sue],all]`: a single table with a type column at the far left, then the columns that work for ST, WP and Issue.

It is a merge of three row lists the list verbs already produce, rendered through the output layer they already share (`--format`, `--width`, `--markdown`), so it adds no second classifier and no second renderer. What counts as outstanding is the sibling verbs' own defaults: a thread at WIP (bare `st list`), an issue OPEN (bare `issues`), and a work package at WIP. Those defaults live in the CLI's renderer today; they move into intentsvcs as one definition that `st list`, `issues` and `outstanding` all read, so the new verb and its siblings cannot disagree about what is open.
