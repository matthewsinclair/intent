# WP-02: Intent.app's Rebuild Search Index row copies Gtools' Refresh Search row

## Objective

Intent.app's Rebuild Search Index row tells the operator what happened the way Gtools' Refresh Search row does: its second line says how long ago the index was reconciled, a rebuild that fails raises an alert, and a rebuild no longer opens the log by itself.

## The model is Gtools' row, file for file

hv's rule of 2026-10-22 holds: the menubar apps use one set of controls the same way, and no row is bespoke. Gtools' Refresh Search row is the model (gtools#0066, gtools#0108), in `~/Devel/prj/Gtools/native/macos/Gtools`:

- `CmsStatus.refreshTitle(refreshing:)` gives the title, and the busy caption while the verb runs (`Gtools/Models/CmsStatus.swift`).
- `CmsStatus.refreshSubtitle(status:now:)` gives the second line, `built <age> ago` from the daemon's `built_at`, in `uptimeText`'s words (12s, 5m, 2h 3m, 1d 4h), and nil when the daemon names no time.
- `GtoolsApp.refreshItem()` sets that line as the item's `subtitle`, and `refreshSearch()` raises the alert `Refresh failed` with the error when the verb throws.
- `CmsService.refresh()` runs the CLI and logs to OSLog. Nothing opens a console; only Gtools' doctor shows one.
- `GtoolsTests/CmsStatusTests.swift` pins the title, the caption, and the second line at a set age and with no time.

## What moves in Intent.app

- **The second line.** The Rebuild Search Index item, built by `commandItem` in `IntentApp.swift`, gets a `subtitle`: `reconciled <age> ago`, in Gtools' age words, from the `reconciled_at` that `intent index status --json` names once WP-01 lands, and none when the CLI names none. The verb is the index's own rather than Gtools' `built`, because intentd's watcher stamps the same column after every source edit (`Facade::index_refresh`), so `built` would claim a rebuild that did not happen. The age comes from the CLI's stamp, never from the app's own record of its runs.
- **Where the stamp is read.** At launch, after each rebuild, and on the poll the app already runs if that read can carry it without a second process per poll. The choice is ic's, and the bank names it.
- **A failure.** A rebuild that exits non-zero, or cannot be run, raises an alert titled `Rebuild failed`, as Gtools' `Refresh failed` does, carrying the CLI's own `error:` and `remedy:` lines. Today `runLogged` throws only when the process cannot be spawned, so the exit code has to reach the caller.
- **The log.** Every run is still one block in Intent.app.log, as issue 0607 made it, and the Log item still opens the log. A rebuild no longer opens it by itself, as Gtools' refresh opens nothing. Run Doctor keeps opening it, as Gtools' doctor shows its console, and the comment in `rebuildMenu` that says why stays true.
- The item's title and busy caption do not change.
