# ST0068: Update Intent's docs for v3

## Objective

Replace Intent's documentation, which describes v2 and has not been updated in a long time, with a complete end-to-end set for v3 as shipped -- and ship it WITH v3.0.1 rather than after it. Three deliverables: the v2 material archived as a historical record rather than updated; a new public documentation set covering install, concepts, the command surface and migration; and a standalone one-page site at intent.laksa.io that links to the Homebrew install and the repository.

## Context

**The release is held for this thread, which makes the ordering a constraint rather than a preference.** hv ruled that the v3 docs go out with v3.0.1 and not afterwards. That ruling is what makes ST0056's AC-12.3 -- release docs written BEFORE the cut so the tag carries them -- satisfiable at all; it was self-contradictory while the docs were going to follow the release.

**Documentation must be written against the CUT, never against `main`, and this is the deciding constraint on the whole thread.** The published v3.0.0 tag `80d8b2ca` carries none of the `ac`/`at` edit work, so a page written from the register at `main` would document `ac edit` and `at edit` -- verbs no installed tool has -- and would describe `ac new` as refusing when the shipped one destructively replaces. The command reference is therefore GENERATED against a named revision rather than written by hand, because a hand-typed list beside the register is a transcribed copy of a measured mapping and drifts from it.

Criteria authored unsatisfied-with-evidence lost their evidence silently on ingest. And `st repair` shipped in v3.0.0 and is retired at HEAD, so it works in the release people are on and vanishes at the next.
