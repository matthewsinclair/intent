# WP-01: The estate record and its doors: directory, versioned record, one reader, the estate verbs, MCP exposure, the reap rule

## Objective

One reader in `intentsvcs::estate` returns the host's estate as one serialisable value (schema `intent/estate-status@1`), and three verbs reach it: `intent estate status [--json]`, `intent estate wip "<line>"` (or `--clear`) and `intent estate prune`. Every renderer works from that value: the verb, intentd's `/op` (WP-02) and the TUI (WP-03).

The reader reads Claude Code's own `<claude dir>/sessions/<pid>.json` files and never writes them. A test pins the fields it relies on (pid, procStart, sessionId, cwd, name, status, startedAt, updatedAt) against a scrubbed real fixture. A file that lacks one of those fields is listed as unreadable, with the field named, never dropped. Claude Code's status is kept as found. A row's state is derived in this order: gone (a dead pid, or a pid whose start time is not the file's procStart, read with one `ps` call under the C locale and UTC) > paused > heavy > busy (any status but idle) > idle. A failed `ps` is reported as unreadable, never as every session gone. Liveness was measured on macOS; Linux is unmeasured until a kovacs session file is read.

The reader joins the project, node, focus and claims rather than storing them. The project is the one whose tree holds the session's cwd. A cwd in a git worktree folds to the main checkout through the git common dir, read-only, and the row says it is a worktree. Node, focus, claims and paused come from a narrow read of the node header of the board whose session id matches, under board schema @3.0 or @4.0, without opening any store; a board in another schema is unreadable, named.

Intent writes only what nothing else holds: `~/.local/state/intent/estate/<session-id>.json` (schema `intent/estate-session@1`), a WIP line for a session with no board. It is written whole by atomic rename, by that session alone. `prune` removes only those records for gone sessions, and never touches Claude Code's files.

Every error is typed and carries a remedy. `status` and `wip` are on MCP; `prune` is not.

The split: cc builds the intentsvcs side, ic the verbs' dispatch rows, help, exit codes and MCP rows.
