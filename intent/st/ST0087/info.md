# ST0087: Intent conforms to the dev, opt and brew contract

## Objective

Intent follows the one dev, opt and brew contract every tool released through Homebrew follows (devbin's `docs/dev-opt-brew.md`, landed at Devbin commit aeed31e4 and amended by devbin issues 0213 and 0216), so that a maintainer moves between the checkout, a published working copy and the Homebrew keg with one switch, every tree names itself the same way, and a user's `brew install` keeps working without ever running the switch.

Concretely:

1. One function in intentsvcs names the running tree, brew, opt, dev or unknown, from the manifest and git, and every caller asks it; `intent --version`, `intent version` and doctor print the contract's one line, `intent <version> (<tree>, <sha12>[+dirty]) <provenance>`, with the sha the commit the running pair was built from.
2. `intent install [--prefix <dir>] [--force] [--managed-by brew]` publishes the runtime set from dev into a prefix and writes the manifest `<root>/.intent-install` in the contract's exact form; a dirty runtime set, a prefix another tool wrote, and any tree but dev are refused by name.
3. `intent use [dev|opt|brew]` points the per-user link set, `intent` and `intentd` in `~/.local/bin`, at one tree as a pair, removes it for brew, reports the tree each link serves when bare, and ends in `intent daemon restart`; doctor and bare `use` fail the shadow check.
4. The formula installs the signed release assets as today and writes the same manifest with `managed_by: brew`; the keg stays linked, `releasing.md` no longer unlinks and pins it, and a maintainer's path is `intent use`.
5. The proof runs on this machine through dev, opt and brew in turn, and with brew alone on kovacs, each tree printing its line with doctor and the shadow check clean, and devbin's switch proven in this checkout.

## Context

On 2026-10-24 hv ruled that Intent, Molt, Utilz and devbin use one identical approach to dev, opt and brew trees, that the spec has one home in devbin's docs, and that the user's links come first on PATH (option B: formulae keep linking into Homebrew's bin, Molt-matts puts `~/.local/bin` ahead of Homebrew's bin on every sleeve, `<tool> use` switches the link set, no link means brew). All four estates said SAME to the contract's draft v0.4 that day, Intent at 06:58Z, with Intent's column measured at e6b784790 (vc, `contract-intent-column.md`, carried into the design attachment here). hv placed this thread third in 3.2.7, after issue 0635 and the devbin v0.1.14 re-vendor (vc decision 71), both now on main; devbin itself conformed in its 0213.

Today Intent's brew keg is unlinked and pinned so that the dev pair symlinked into `~/.local/bin` is the one `intent` on PATH, `intent --version` prints `intent <version> (<sha40>) <provenance>`, there is no manifest, no `install` and no `use`, and the support set is listed once in `bin/.devbin/cmd/shared/support.lib`. The design attachment records each of the contract's ten sections against Intent as measured, the deltas, and the hazards the switch cannot see (a launchd-spawned process whose PATH lacks `~/.local/bin` runs brew's copy for Claude Code's hooks and MCP server). ST0081, Intent from Homebrew on Linux and macOS, is the thread this one builds on: its formula and release assets are the brew tree this contract names.
