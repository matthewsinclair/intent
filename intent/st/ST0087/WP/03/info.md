# WP-03: intent use and the shadow check

## Objective

`intent use [dev|opt|brew]` is the one verb that points the per-user link set, `~/.local/bin/intent` and `~/.local/bin/intentd`, declared in one function and moved as one because the CLI finds the daemon only beside its own executable. `use dev` and `use opt` point both links at that tree's pair and refuse a tree that is not there, naming the step that makes it (`bin/devbin build all` for dev, `intent install` for opt); `use brew` removes both links and nothing else, so Homebrew's own links answer, and no link means brew; bare `use` reports the tree each link serves and changes nothing, reporting brew when no link is left and the first `intent` on PATH resolves into the keg. Every `use dev|opt` ends with the version line and `intent daemon restart`, so the old tree's daemon does not keep serving. The shadow check, in doctor and in bare `use`, fails when a link in the set exists but is not the first hit on PATH, or when the set is split across trees, naming what shadows or splits it, comparing resolved directories and never path strings. A test-only option names the link directory, defaulting to `~/.local/bin`. The switch governs login shells only: a process started without the login PATH (a launchd-spawned app, cron, Claude Code's hooks and MCP server under the desktop app) may run brew's copy while the maintainer is on dev or opt, and the docs say so; nothing else of Intent's repoints or removes a link. Arms: each of the three switches over a scratch link directory and scratch trees; the bare report; both shadow failures; the refusal naming the missing tree's step.
