# ST0073: intentd owns its own lifetime: a lifeline instead of an assumed supervisor

## Objective

Give `intentd` a lifetime it can observe, so a daemon whose owner dies stops instead of running forever. Today its lifetime is delegated entirely to a supervisor: `launchd` in production, and NOBODY in the test path. The daemon cannot tell the difference, so every abnormal exit of a test binary deposits a permanent process.

## Context

**MEASURED 2026-09-10, NOT RECALLED.** 64 orphaned `intentd` processes were reaped from this machine, 33 of them holding the live store, having burned 64.9 CPU-hours. `0284` filed the same class on 2026-09-08 with 27 orphans, was cleared on hv's order, and rebuilt to 64 in two days -- **because a reap treats the deposit and the deposit rate is a function of how often a run is interrupted.**
