# WP-02: The v2 tree survives migration and disagrees with the store: ingest bucket files as attachments, then remove the bucket

## Objective

**The migration leaves the v2 tree in place, and it disagrees with the store.** A migrated estate carries `intent/st/COMPLETED|CANCELLED|NOT-STARTED/<ID>/` beside the flat v3 tree, the two copies of a thread's views drift apart, and the v2 path answers greps first because it is the one that existed for a year. The store does NOT hold the bucket's content: the migrator's reach is a filename allowlist, `info.md` and `acceptance.md`, and every other file in a thread directory is left behind entirely (Devbin, measured 2026-08-26: 34 of 54 bucket files carry content the store does not hold). `organize` already reports these paths as `unclaimed`, deliberately never prunable.

**Ruled under the pen on 2026-09-12, with hv's authority and overrulable with a line: ingest, then prune, in that order, and the prune refuses while the ingest is incomplete.** Three layers. (1) Ingest: every bucket-only file under a v2 thread directory becomes an attachment of its thread, the naming gate permitting, and the v2 `acceptance.md` preamble's authored lines go into `preamble`; verified PER FILE by a content probe, because a thread-level check passes on a half-migrated thread and `ok` at rc 0 has been printed over nothing before (issue 0097). (2) Prune: the buckets, the v2 `issues/OPEN|CLOSED/` directories and `.treeindex` are removed under the fail-forward ruling of 2026-08-19, at migration for a new conversion and under `organize --apply` for an already-migrated estate; a prune that ingested nothing removes nothing, by refusal and not by discipline. (3) Pointers: authored files naming a bucket path are reported as a worklist and never rewritten; the readable form of a closed thread's file is `intent://` or `intent edit <ID> <file>`.

**A tool tree beside the threads is not a thread archive.** The Intent estate's own unclaimed paths are `ST0056/parity/tools/` and the like: a file under a thread directory is an attachment candidate, a tree beside the threads is neither ingested nor pruned.

**This WP ships the mechanism and prunes no estate but the fixtures it drives.** The fleet prune is hv's, per estate, after `at-accounting.sh` has run there, because the v2 bucket is that instrument's only source surface.
