# WP-24: The LLM boundary: the harness's own search becomes a door into the index

## Objective

Move the boundary between the model's own search tools and Intent's index so that the index is the first call for a code question: the MCP server configured in every project by canon, tool descriptions the model matches on, outline and context verbs that answer in units with spans, the skills and guide routing the question, and a post-tool hook, off by default for a project to switch on, that annotates a grep for one symbol with the index's structural answer without ever blocking or lying.

Design: design.md, "The LLM boundary". hv, 2026-09-12: "how we get to a point where the LLM is using intent's tree-sitter based index of the source code instead of using grep ... That's the boundary that I want lifted and made high-performant and next gen." Five join points, in order of leverage: answers grep cannot give (`intent search --outline <path>`, `--context <name>` and `--kind def <name>`, each one facade call and one call of the `search` MCP tool); zero-cost reach (`.mcp.json` naming `intent mcp` seeded by `claude upgrade --apply`, in-process queries, descriptions generated from the register that say when to use the tool and when not); the canon routing the question (CLAUDE.md, the skills, the generated guide); the PostToolUse hook served by the install that appends the index's answer to a grep whose pattern is one symbol, appends nothing when the index cannot answer for the paths in its own answer, and ships off by default for a project to opt into from `.claude/settings.local.json`; and the PreToolUse redirect, specified with its safety condition and not built until hv rules. Stretch: a symbol hit names the thread and criterion that introduced it, through the commit references the store and git already hold. Depends on WP-20.
