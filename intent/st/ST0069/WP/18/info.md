# WP-18: The corpus: the gitignore-aware repository, two staleness policies, the widened watcher

## Objective

Widen the index scope from Intent's own prose to the gitignore-aware repository, with every exclusion a named row, two staleness policies for the two corpora, and one scope object read by both the scanner and the widened watcher.

Design: design.md, the corpus (S1). Corpus assignment is by kind: the store's entities stay the canon corpus; a markdown or text file on disk joins the prose table through the heading splitter with owner_type file; a code file joins the source table; rendered views, the canon extract and the documents the store carries as attachments (`design.md`, `impl.md`, `tasks.md`) are not in the disk corpus, so a document is indexed once, from the store (issue 0304). Binaries, files over the size cap, unreadable files and symlinks get an `index_file` row with `skipped_reason` (built as a table of its own rather than columns on `file_index`, whose writer deletes every row its scan did not produce) and are listed by `intent index status`. Canon hashes always; source is stat-then-hash. As built (vc, 2026-09-12) the watcher is two registrations rather than one widened one: the canon watch is unchanged, and a second recursive watch from the root, filtered by `Scanned::in_repository`, reaches `Work::IndexRefresh` and nothing else. An event naming the bare root refreshes the root's own files and never descends, and any other path refreshes its subtree alone (`index::reconcile::changed_under`). The FSEvents volume was measured (AC-18.6); the inotify leg is neither built per directory nor measured. Largest single change in the thread; the one that makes intentd load-bearing.
