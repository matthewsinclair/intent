## The instrument, its controls, and its five caught defects

The hand-read this row budgeted M for was replaced by a **syn-based scanner** (`armscan`, a scratchpad instrument, not shipped): it parses `render.rs`, finds every `.subcommand()` match transitively from `run`, and resolves each arm's TRANSITIVE facade reach through local helper fns — `impl Facade`'s public methods only. The root cause that made three hand-rolled span finders fail is the criterion's own recorded sentence: naive brace matching cannot find an arm body, because `format!` braces are indistinguishable from block braces without a lexer. `syn` is the lexer.

**Positive controls on every run, asserted rather than eyeballed:** `st list → st_list` [1], `fc → ac_fc/at_fc/st_fc/wp_fc` [4], `version → []` [0], `at green → at_set` [1], `todo → todo_buckets` (the bare-alias case). A run whose controls fail produces no partition.

**The controls caught five instrument defects before any number left the scanner — a reader should trust the partition _because_ it survived them, not because it came out clean:**

1. `pub fn` on sibling types scored as facade doors (`as_str` on 60 arms) — narrowed to `impl Facade`.
2. Or-pattern arm literals dropped (`state @ ("green"|"red"|"na")`) — 6 of the first 26 unresolved.
3. Top-level or-arms dropped (`Some(("list", _)) | None`).
4. An auxiliary `match m.subcommand()` inside a leaf arm (todo's flag probe) read as a deeper family — a nested match counts as dispatch only if some arm of it spells a path.
5. A family's bare `None` arm — the family path's own behaviour (`surface`) — was recorded nowhere.

**Population note (vc):** the walker's population is `surface/dispatch-table.json` — authored canon — and `render.rs` source, not a store view, so it inherits no store/disk lag.

## Errata 2 (2026-08-30, same day) — building the serving match drove the field, and four values were reach, not doors

3. - 4. **`agents generate` / `agents validate`** — the value was `project` (reach); the serving functions were in the SERVICES crate all along (`rootfiles::render`; the validate checks extracted beside it). **vc's ruling (c): these are facade GAPS closed by ADDING methods** (`agents_generate`, `agents_validate`), never by composing in the tier and never by a face-side spelling.

**The `face:` vocabulary this document reserved for vc is STRUCK, not pending: the population is empty once each candidate was measured, and each was empty for a DIFFERENT reason** — `llm guide`/`surface` narrowed on need; the agents pair had their functions in `intentsvcs` all along. A vocabulary reserved for an empty population is an invitation the next ill-fitting row would take.

**`st sync`'s preview half is an explicit FACADE GAP entry, added here so a temporary refusal cannot become the permanent shape by nobody revisiting it:** the no-write half of the CLI arm renders the thread table (byte-identical to `st list --status all`); the declared facade `sync_to_disk` is only the write half. The MCP tool REFUSES without `write=true` (composing the preview in the tier is forbidden) — the refusal's remedy names the read tools, and this entry names the missing door.

**A LIMIT, RULED (vc, 2026-08-30), RECORDED WITH ITS DISCHARGE CONDITION: for 3.0.0 the MCP tier serves IN-PROCESS ONLY.** `AC-08.2`'s in-process-and-daemon-agree property does NOT extend to the MCP face — a running daemon cannot serve it, and that is a stated limit, not a gap: the same sequencing decision as declining (b), seen from the other side. **This becomes false when the tier routes through the op dispatch (`dispatch(op)`), which is the recorded 3.x destination.**

**And one instrument defect the serving work exposed in the DATA tier it rides on:** `schema()` skipped flags by `disposition == "drop"`, and the table's vocabulary contains no `drop` (keep 106 / retire 15 / intrinsic 10) — the filter matched zero flags since the tier landed, so published schemas carried retire and intrinsic flags (`intent_doctor` advertised both `fix` and `help`).
