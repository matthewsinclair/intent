## What this is

The flag-level half of the parity contract: for every command in `../parity.md`'s command-level table, the subcommand set, the flag grammar, and the observed stdout / stderr / exit-code behaviour. One file per command.

## Cross-cutting findings

**1. `intent organize` and `intent st organize` are two different implementations, and MODULES.md registers both.** Row 15 gives `bin/intent_st` an `organize` verb; row 31 gives `bin/intent_organize` the same job. Against one steel thread in a fresh project they print different things and share no output: the top-level form reports `ok: moved 0, kept 0` plus per-directory counts (117B), the `st` form reports `Already organized: ST0001 in intent/st/NOT-STARTED` (73B). A Highlander violation recorded in the registry that exists to prevent it. **v3 must implement one of them; which one is an hv decision, not a port-time coin toss.** **Resolved (hv, 2026-08-14): both v2 faces retire, and v3's `intent organize` is a new-surface verb that reconciles the tree with `.intentfiles`.**

**2. About a fifth of v2's failure paths write to the wrong stream.** Across 108 probes, failing invocations split **45 stderr-only, 12 stdout-only, 2 both**. This is the same class as the already-queued ruling on the three plugin bins writing `Error:` to stdout, and it is larger than that ruling's three known sites. An error on stdout interleaves with captured command output, which is how a voice becomes data.

**3. `--help` reports failure on 10 of 27 commands.** Two shapes: usage printed to **stdout with exit 1** (`init`, `st`, `wp`, `todo`, `treeindex`, `fileindex`), and an error to stderr (`ac`, `at`, `help`, `claude`). `intent at --help` is parsed as an unknown verb. `intent help --help` fails outright. Asking for help and being told you failed is a defect in v2 and a decision for v3: reproduce faithfully, or deviate.

**4. Three commands accept an unknown flag silently with exit 0.** `intent info --zzz-not-a-flag`, `intent config --zzz-not-a-flag` (zero output) and `intent version --zzz-not-a-flag` all succeed. **This one cannot be reproduced by accident**: clap rejects unrecognised arguments by default and exits 2, so v3 will diverge here on day one whether or not anyone decides to. It needs a ratified deviation before WP-05, not a triage note during it. **Ratified as `corrected` (hv, 2026-08-14): `parity.md`'s `Corrected` class covers `INV-08`, `info` and `version`.**

**5. The project-context gate is uniform; the plugin bypass is not.** Fourteen commands refuse outside a project with exactly `error: not in an Intent project directory` (`bin/intent:205` at `69d42a7`). Two do not: `claude` never reaches the gate because plugin commands exec before the project check (`bin/intent:188-191`), and `upgrade` supplies its own message. `agents` runs outside a project for the same plugin-bypass reason despite not being in `GLOBAL_COMMANDS`.

**6. Observed exit codes are 0, 1 and 2 only**, and the only 2 observed in the shipped surface came from `intent critic` (`intent_critic:89,95`). `bin/release` also uses 2 but is out of parity scope. `intent claude hook` propagates a hook's own exit code, including 2, by design.

**7. `intent claude rules index` writes into `INTENT_HOME`, not the project.** It modified a tracked file (`intent/plugins/claude/rules/index.json`) in the worktree under test. A command that reads as a query mutates the installation.

**8. Seventeen of 26 commands have no help file at all.** `ac`, `at`, `bootstrap`, `config`, `critic`, `doctor`, `help`, `info`, `init`, `issues`, `llm`, `organize`, `st`, `st_zero`, `todo`, `treeindex`, `upgrade`. Naming drift too: `stzero.help.md` against `bin/intent_st_zero`, and `rules.help.md` documents a `claude` subcommand rather than a top-level one. WP-05 generates help from the dispatch table, which retires this whole class -- but it means **`lib/help/` cannot be used as the v2 spec to port from**.

**9. The per-command files are named `cmd-<command>.md`, not `<command>.md`.** Two command names collide with filenames the toolchain treats as special, and macOS matches case-insensitively: a generated `claude.md` is loaded as this directory's `CLAUDE.md` and injected into every subsequent session as instructions (observed, not theorised -- it happened here), and `agents.md` shadows the `AGENTS.md` convention the same way. The prefix makes the collision unconstructible instead of special-casing two known names. **Worth carrying into v3**: any generated-view filename derived from user or command data can land on a reserved name, and the v3 view renderer will generate far more files than this.

## Contract gaps for vc

**All three gaps are closed.** Gap 1: hv ruled both `organize` faces vestigial on 2026-08-14, and both retire. Gaps 2 and 3: hv ratified the `corrected` class on 2026-08-14 for exactly this, and `parity.md` lists it with its members beside the later `undefined` class.

Per the work order, these fit no ratified deviation class and are flagged rather than judged here:

1. **The two `organize` implementations** (finding 1). Not a deviation class -- a v2 defect the port must resolve. Needs an hv ruling on which survives.
2. **Silent acceptance of unknown flags** (finding 4). Guaranteed divergence under clap. Needs its own ratified class; "file layout" and the other three classes do not cover a _voice and exit-code_ change.
3. **`--help` exiting non-zero** (finding 3). Same shape: a deliberate, ratified deviation is the honest option, but the register has no class for "v2 behaviour we are fixing rather than porting".

Gaps 2 and 3 pointed at the same hole: the four ratified classes in `parity.md` then all described **layout and workflow** changes. There was no class for **a v2 behaviour that is simply wrong and will be corrected**, which is what the stream, exit-code and unknown-flag findings all need. Proposed name: **`corrected`** -- distinct from `deviate` in that `deviate` is a design consequence and `corrected` is a bug fix, and both must carry a ratification reference.

## Re-running

```
WT=<detached worktree at 69d42a7> bash intent/st/ST0056/parity/tools/gen_inventory.sh
```

Run it from the repository root. `OUTDIR` defaults to this directory and the probe data to the committed `probes/toplevel.tsv`, so set `SP` or `TSV` only for a fresh probe run. `tools/probe_toplevel.sh` captures that runtime matrix into `probes/toplevel.tsv`, rebuilding its sandbox and sourcing `tools/probe.sh`, and both refuse without a v2 `bin/intent` in the worktree or a project in the sandbox. `tools/extract_verbs.sh` and `tools/extract_flags.sh` do the static passes over one script and check nothing themselves; `gen_inventory.sh` refuses a missing extractor or missing probe data rather than emitting a uniform empty surface that reads like data.
