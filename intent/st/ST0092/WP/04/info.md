# WP-04: A seat can be retired, and a board can change its profile

## Objective

Intent has had no way to take a node off a roster, so a roster only grows. One supervisor hub's roster says so twice in prose and keeps a `vc` it calls paused and retired beside the `sc` that replaced it, and on 2026-11-10 the vc that relayed hv's ask registered four of the five seats hv declared and left `ac` out because a registration could not be undone. This package adds retirement as a state, never a deletion, and with it the move from one base profile to another, which is the other half of hv's reinit.

## Builder and judge

cc builds this package and claims `ST0092/04` in the same chain as `intent wp start ST0092/04`. vc judges it and claims nothing.

## What is built

- **`intent wb retire <moniker> --reason "<why>"`**, a roster act like `register`. Retired is a state on the roster, as archived is a state on a board. A retired node keeps its board, its items and every message it sent or received, all readable with `--all`. It is no longer a recipient: an ask to it is refused and names the retirement, and an announce skips it. `intent wb status` lists it only with `--all`, and a profile is reconciled against the roster without it.
- **Claims stop a retirement.** A node that holds a claim on a thread, a work package or an issue is refused, with each claim named: a node cannot take its claims with it.
- **Live messages do not stop it; they are reported.** A message the leaver sent stays in its recipient's inbox until the recipient handles it, and that pair's view is dropped only when it holds nothing live. A message addressed to the leaver that it never handled is named in the retirement's report and at its sender's next pickup, and the sender, who is that message's one writer, sends it on to another node or archives it: `intent wb archive message` no longer refuses when the recipient is retired. Nobody acts as the retired node.
- **The mediator is not retired** while it is the mediator. It goes only in a change of profile that names another.
- **Reinstatement** is `register` again: the same moniker comes back as the same node with its board, and a second node is never made.
- **`intent wb init <base> --change [--apply]`** moves a board from one base to another, eg from `solo` to `team` when a project grows. It registers the new base's seats and retires the seats of the old base that the new one does not declare, under the rules above, and its dry run lists both. It is the only way `wb init` retires anything: a plain re-apply reports a node outside the profile and leaves it.
- **The surface row** for `wb retire`, read by ic. vc's proposal for ic's row: a roster act is done because someone was asked, so it is not offered on MCP.

## Why retire and not rename

`register --correct` changes a node's name and role and keeps its moniker. A moniker is a routing key, a directory and a field in every message and event that names the node, so renaming one rewrites history across every board. Retiring the old seat and registering its successor changes no record: a hub's `vc` that became `sc`, and Riffle's and Prodinfra's `cc` if hv rules those boards solo at the sweep.

## Open for hv's review

These four are vc's design calls on the points the relaying vc raised on 2026-11-10, and each is cheap to change before the package is built: live messages are reported and do not refuse; claims refuse; a re-apply never retires without `--change`; and the verb is kept off MCP.

## Rulings since this package was written, 2026-11-10

These are vc's rulings under the pen, made on ic's read of the dispatch rows and cc's read as builder, and written here once hv ratified the terms. Where one disagrees with the text above, it stands and the text above gives way.

`wb retire` is reversible by `register`, CLI only, and `--reason` is required. An unknown moniker is a typed refusal on exit 1 naming the registered seats. The human seat is refused, because a human seat is only ever registered, as the terms say since hv ratified them. A seat already retired is a no-op that says so and exits 0. `wb status --all` is a new flag with its own row, MCP included. The help for `wb ask`, `wb announce` and `wb archive message` names the retired-node behaviour.
