# The silent-deletion sweep, 2026-09-12

hv, on reading that `intent organise --apply` had removed hand-authored attachments and named them only afterwards: _"This cannot be released publicly with that kind of bug. THEY NEED IDENTIFYING, TRIAGING, AND FIXING, AS A MATTER OF URGENCY."_ This is the identification, read from source with a file and line for every claim, and the triage vc made from it. The fixes are batch 4 of v3.0.2; their record is their commits.

**The class:** a code path that removes or overwrites bytes on the user's disk where the user was not told, before the bytes went, exactly which paths would go.

**The standard already in the tree:** `intent sync --to-store` (`render.rs` near 4174) prints `warning: replacing the store from the extract OVERWRITES:` and one line per subject before it writes, and the `--apply` flag's own ruling text in `surface/dispatch-table.json` (near 8452) promises that shape for organize: _the destructive direction states what it will overwrite BEFORE it costs it, because a summary afterwards is a receipt for a loss the operator needed one moment earlier._ Nothing in the apply path honours it.

**The shared mechanism, and who bypasses it:** `organize.rs` has the one plan-then-apply split (`Mode::Preview` and `Mode::Apply`, `Plan::run`), and its own docstring says the preview is the act with three things withheld. But preview is a mode of the engine, not a stage any verb must pass through: `Facade::hydration` (`st hydrate`, and the realiser `edit` reaches), `Facade::dehydrate` and `Facade::organize` each go straight to `Mode::Apply`, and the CLI renders the report after the facade returns. `payload.rs` and `canon.rs` each carry their own separate preview. `init`, `agents sync`, `backup` retention and the view projection on every mutation have no plan stage at all.

**No gate holds the class.** The nearest tests are narrower: a verb that would empty a population must refuse or name it (`egest_refuses_to_empty_the_estate.rs`); organize's dehydration gate refuses and names on refusal, and says nothing about the accepted path; `organize_preview_polarity.rs` proves preview and run agree, not that the preview was shown; `organize_verbosity.rs` proves `removed:` lines survive at the default verbosity, not that they precede the removal. A gate belongs in `intent-cli/tests/`, registered in `suite.rs`, in the shape of `error_literal_shape.rs` for the walk and `organize_verbosity.rs` for the fixture and its vacuity control.

**Read and found not in the class:** `sync --to-store` (the reference), `intent ingest` (writes nothing and says so), intentd's disk ingest (an on-disk deletion never propagates as a detach, pinned by `an_ingest_never_reverts_a_newer_store_write.rs`), `intent upgrade` (deletes nothing; the write set has no remove, stated twice as a bound), `intent backup` retention (pruning is in the verb's own help and paths print after), `agents sync` (one file, named before, generated by definition), the pre-commit hooks (no `rm`), `bin/devbin` and `bin/int` (the one `rm -rf` on a shared path is behind the path, a size, a warning and a prompt; the rest are build artefacts and temp dirs), `intent ext` (no dispatch arm), and the daemon's socket and pid unlinks (compare-and-unlink, reasoned in place).

**Recoverability, for the record:** a removed generated view comes back from the store; a removed text attachment comes back from `intent/.canon/st/<ID>.json`, which carries its full text and hash; an opaque attachment cannot be removed at all, the gate refuses on it; an overwritten hand edit comes back from git only, and a fresh directory may have no git. The organize and dehydrate runs record their paths as `disk.organize` and `disk.dehydrate` events; the realiser's removals are not recorded.

**The witness for why "before" matters** (ic, the same hour): the organize run removed a file a ratified ruling cites as its record, and the way it surfaced was the rulings gate refusing an unrelated commit by a different node. A silent deletion does not stay local; it becomes a gate refusal on whichever node commits next.
