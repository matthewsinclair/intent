## Route to hv

hv is reached through the mediator, `vc` (Validation Claude), the one reader of hv's inbox. What the profile asks of every other seat:

You reach hv through the mediator, and only through it: send your request to the mediator and never write to hv's inbox yourself. hv may speak to you directly, and when hv rules to you directly you pass the ruling to the mediator, who records it. If you disagree with what the mediator has put to hv, say so to the mediator, who puts it to hv in your words. No seat waits idle on hv: hold only the work that depends on the answer, and carry on with the rest.

## Intent's own notes

### Where each remit lands in this tree

- `vc`: the check of landed and claimed work against hv's ask, the briefs each seat works to, and the route to hv.
- `cc`: the engine: `native/rust/crates/`, `intent/plugins/`, `lib/templates/`, the rule library and the skills.
- `ic`: the dispatch table and everything rendered from it (the command surface, help, voice, exit codes, the MCP tool list and `intent llm`), and Intent.app and the TUI.
- `dc`: dev-x and the build environment, so that `cc` concentrates on functionality for the CLI and the daemon (hv's words, 2026-08-15).

hv has not ruled the line between `dc` and `cc`. vc's working test for a disputed file: a change to what the tool does is `cc`'s, and a change to how it is built or shipped is `dc`'s.

### Layout and the single-writer rule

```
intent/whiteboard/
  README.md                 # this file: the roster and these notes
  <node>/
    board.json              # the node's canon: its items, the messages it sent, its handled marks
    wip.md                  # the node's board, rendered from the store
    inbox.<sender>.md       # the messages FROM <sender>, rendered from <sender>/board.json
```

- `<node>/wip.md` changes only through `intent wb --node <node>`. A hand edit is skew, and `intent doctor` reports it.
- `<node>/inbox.<sender>.md` is written only by `<sender>`. `<node>` reads it and clears it by a mark in its own `board.json`.
- A node commits what its verbs printed on `wrote:` lines. A `re-rendered:` line names another node's file (issue 0612).
- A `wip.md` header is a line-oriented `key: value` block, not YAML: never escape a quote in it.

The `/in-whiteboard` skill has the invariants and each verb's procedure.
