The published page's sixth defect -- _a cited file must carry the row's own literal id_ -- **was only reachable by fixing the fifth and running again.** Drive to green, then **count the passes: the count is the claim.** Sibling of W15's asymmetry, in the forward direction.

- **W20 -- A BOOLEAN PROBE HIDES ITS EVIDENCE.** A `yes/no` cannot be argued with. **When two runs of one probe disagree, NEITHER is evidence until you know why.** Print what the probe saw.
- **W21 -- WHEN EACH FIX FINDS ANOTHER DEFECT, THE METHOD IS THE DEFECT, NOT THE ENTRIES.** Patching entry by entry leaves a thing that is true only where you happened to look.
- **W22 -- A COUNT OF DIFFERENCES IS NOT A COUNT OF DAMAGE**, and a count of FILES is not a count of THREADS. Two spellings of one value differ. **Read the PAIRS before reporting the number.**
- **W23 -- NAME THE TREE / THE BINARY / THE DENOMINATOR, OR THE CLAIM CANNOT BE DISAGREED WITH.** The general form of W20: **omitting the thing a reader needs in order to tell you that you are wrong.**
- **W24 -- A GREP OVER A SERIALISATION ANSWERS A QUESTION ABOUT TEXT WHEN THE QUESTION WAS ABOUT STRUCTURE.** `grep legacy` over canon JSON returns 10; the structured query returns 0.
- **W25 -- AN EDIT THAT REPLACES A LINE RANGE DELETES WHAT IT DID NOT READ.** My own 15:09Z board edit destroyed W20 and W21 four hours after writing them -- a hand edit doing what a fold keyed on dated does. **Inventory the classes before and after any range replacement.**

- **W26 -- A PARTITION BUILT FROM THE DIRECTION YOU EXPECT THE DRIFT TO RUN HAS NO BUCKET FOR THE OPPOSITE DIRECTION, AND THE UNNAMED CASE SORTS TO THE WRONG ONE IN SILENCE** (vc's rule, corrected by my drive and adopted by them verbatim). Two dispositions were both keyed on the OLD build failing, so _new build fails where the old one passed_ had no home and defaulted to _the docs are stale_ -- which would have filed a regression in the release candidate as a documentation lag. **THE THREE CLASSES: old fails / new passes = the docs are ahead, note it. Both fail = the docs are wrong, file it. OLD PASSES / NEW FAILS = THE TREE BROKE WHAT THE TAG HAD RIGHT, and it outranks both.** General form: **before trusting a partition, name the case it has no bucket for and check where that case lands.**
- **W27 -- A FIGURE WITH NO HOME THAT DERIVES IT SURVIVES ON RESTATEMENT, AND EACH RESTATEMENT MAKES IT LOOK BETTER SOURCED.** vc corrected an issue NUMBER I had handed on; checking it found the FIGURE wrong too -- _twenty-one_ was not reproducible from anything in the estate, the durable record derived TEN, and the manifest carried no verdict column so it was never derivable there. It had walked across from an unrelated _21 of 56_. **A number that lives on a board and in a handover and in no instrument is not evidence.** Same family as the handover rule -- hand over PROPERTIES, re-measure, never trust a ledger -- arriving through repetition rather than through age. **Cure: state the figure with the command that produces it, so the next reader re-derives instead of inheriting.**

- **W28 -- THE INSTRUMENT ITSELF CAN GO ABSENT, AND ITS ABSENCE READS AS AN EMPTY ANSWER** (vc broadcast it; it cost me a write). The dev `intent` is a SYMLINK INTO A BUILD OUTPUT, so a rebuild deletes it mid-session and every call returns **rc=127 with nothing on stdout** -- indistinguishable from a verb that ran and found nothing. **Read the EXIT CODE, never the output, and never put `2>/dev/null` in a harness that drives it.** The keg is a real file and is unaffected, which is the second half of the rule: **know which of your instruments is a symlink.** **AND IT POINTS THE OTHER WAY TOO** (cc, 2026-08-31, measured on their own rebuild): the running `intentd` was started at 15:52Z on `553ac304` and **holds the DELETED INODE**, so it serves code that no longer exists on disk while `daemon status` answers live. **The artefact is absent and the thing depending on it reports healthy** -- so absence is invisible from BOTH ends, and a restart is the only thing that resolves which code is running. **Measured exposure of `0196`'s window: `Removed 49 files, 53.0MiB total` before a single line compiled, 1m18s to come back, benign ONLY because the build succeeded.**
- **W29 -- A WITHDRAWAL IS A CLAIM, AND IT NEEDS THE SAME EVIDENCE AS THE FINDING IT RETRACTS.** vc correctly withdrew a finding of mine and, in the same message, withdrew _every drive since 16:30Z_ -- which swept up a run that really happened, at rc=0, with substantive output, against the DEBUG binary that had not vanished. **Withdrawing a real result costs the same as keeping a fabricated one.** The right move is to name the limitation the evidence supports -- _that build is somebody's uncommitted tree_ -- rather than the widest one available.

- **W30 -- A PARKED ARTEFACT IS A MEASUREMENT WITH A TIMESTAMP ON IT, AND THE TREE MOVES UNDERNEATH IT** (vc's statement, from my near-miss). Text written, held because an instrument was unavailable, then landed later is **evidence about the moment it was parked, not about the moment it lands.** `0193`'s parked body named three builds and a behaviour that existed only in a peer's uncommitted tree; re-driving the one command before landing found `553ac304` refusing, which made it three-of-four and the outlier an outlier. **Had it gone in as written it would have asserted a v3 behaviour present in NO build anyone can install.** The rule: **re-drive before landing anything that waited**, and say which build the claim is about. Related: W23, W27, W28.
- **W34 -- DOING THE WORK IS NOT REGISTERING IT, AND THE INSTRUMENT READS THE REGISTER.** vc drove `0162` and `0194`, wrote both into `known-defects.md`, and committed -- and AC-02.3 still counted both UNDISPOSITIONED, because the tool reads a TSV manifest and neither commit touched it. **The hard half was done and the cheap half was invisible.** Nothing failed and nothing warned: two files, one fact, and only one of them is what the checker opens. **Cure: after stating anything, RUN THE INSTRUMENT and watch the number move.** Corollary that nearly cost me: **I was holding a working copy of that shared manifest across several appends**, so a peer's rows landing meanwhile would have been overwritten by my next `st attach`. **Check HEAD before appending to a shared data file, every time.**
- **W32 -- THE ESTATE MAY ALREADY OWN YOUR FINDING, AND A REDISCOVERY IS INVISIBLE TO YOU BECAUSE YOU SEARCHED YOUR MEMORY INSTEAD OF THE REGISTER.** Under an explicit instruction to FILE, I came within one command of filing a third record of `0151`/`0154`. What stopped it was reading the sibling rows my own board already NAMED -- the board said _same family as `0185` and `0154`_ and I had never opened `0154`. **A finding that arrives with a family attached is a finding to look up, not to file.** This is Highlander with the register as the registry: search before you create, and the search is `issues show` on the siblings you can already name. **The prize for looking is bigger than avoiding the duplicate** -- `0154` turned out to have PREDICTED the half-fix that then happened, which no new row could have said.
- **W33 -- A BROKEN INSTRUMENT THAT RETURNS THE SAME ANSWER ON BOTH ARMS READS AS A CLEAN TWO-SIDED CONTROL.** Checking `--note` across builds, I looped `for v in "at green" "at na"` and zsh passed each phrase as ONE argv token, so every invocation errored and every grep found nothing. Output: `(no --note declared)` in BOTH columns -- **symmetry, which is exactly what a negative control looks like** -- and it contradicted a driven rc=0 I already had. **A control is only a control if the instrument was ever capable of returning the other answer.** Cure: when both arms agree, positive-control the instrument before believing the agreement, and dump one arm RAW rather than through a filter. Third time this session on zsh's no-word-split; the new half is that this one FAILED SYMMETRICALLY and so looked like evidence. Related: W28, and the precision-is-a-claim-about-the-corpus family.
- **W31 -- A REWRITTEN ARCHIVE LOOKS CORRECT AFTERWARDS, WHICH IS WHY ONLY A GUARD CAN SEE IT** (vc's framing of the append-only class). I rewrote a parked file under `.history/` to add a row -- 2 removed, 3 added -- and the pre-commit guard refused, correctly. **Every other check passes and the file reads as a coherent record, because the act destroys its own evidence.** `.history/` only ever grows: restore to HEAD and APPEND, never edit. The guard's own words are the keeper -- _a removal means a write landed where an append was meant_.

## Decisions

**hv PROVENANCE ENTRIES ARE VERBATIM AND ARE NEVER COMPRESSED** -- a ruling's own words cannot be re-derived.

- **AN AC REWORD THAT LEAVES ITS AT BEHIND CONVERTS A STRENGTHENED CRITERION INTO A WEAKER ONE** (my finding, vc's naming and sweep, `062a41c7` / `2868e301`). **The AT is what a driver EXECUTES and the AC is what a reader READS**, both stay individually coherent, and **the gate reads the AT**. Swept all 69 threads: 24 criteria carry a reword marker; **exposure is confined to NON-TEST rows, because a test row's bar is a cited artefact that gets re-driven while a non-test row's bar is prose nobody re-reads.** Two were weaker, both mine; `AT-11.1` checked and matches. **Class closed for this estate.**
- **A FIGURE TRANSCRIBED INTO A CRITERION IS A CLAIM ABOUT A CORPUS AT A MOMENT.** AC-02.3 carried _72 open of 128_; a day later it was **103 of 164**, and 105 of 166 an hour after that. **A parenthetical that rots in a day, inside a criterion whose own point is being AUDITABLE RATHER THAN ASSERTED, teaches the next reader to trust a number the row cannot keep true.** Struck by vc under the standing pen. **The count belongs in the derivation.**
- **D-DELETE -- A DELETE HAS THREE POPULATIONS AND I HAD ONE.** **(1) WHAT EXECUTES THIS.** **(2) WHAT CITES THIS AS EVIDENCE -- AND THE POPULATION IS THE STORE, NOT THE TREE.** **(3) WHAT CHECKS THIS -- A DELETE CAN HOLLOW A SURVIVOR**, and nothing else catches it. **THE GENERAL FORM: blast radius measured as WHAT WENT RED misses everything that went VACUOUS, and vacuous leaves no corpse.**
- **D-POP -- THE INSTRUMENT'S POPULATION EXCLUDED ITS OWN SUBJECT.** Nine instances, none of them the empty set. **THE CURES: state the denominator before the finding; positive-control on a case it MUST catch; and when a narrowing flag is in the command, re-read what it narrowed.**
- **D-SHARED -- THE SHARED TREE BREAKS EVERY COMPARISON THAT LOOKS SELF-CONTAINED.** `git commit --only <paths>` in ONE call, and **`unset GIT_INDEX_FILE` BEFORE any reset, as its own call.**
- **D-FACES -- A DECLARATION HAS CONSUMERS YOU DID NOT WRITE, AND THE COMPILER GUARDS ONLY THE ONES IT CAN SEE.** Every hand-written roster of a generated surface rots; derive it or delete it.
- **D-ADVICE -- A DEFECT THAT CORRUPTS NO NUMBER HAS NO INSTRUMENT WATCHING IT.** **Advisory output is where defects live longest, because nothing downstream disagrees with them.**
- **A TEST WHOSE SUBJECT IS GONE IS DELETED WITH ITS REASON, NEVER PATCHED TO KEEP PASSING**, and **the property it protected is NAMED at the deletion site.**
- **A NEW GUARD IS DRIVEN TWO-SIDED ON A PLANTED FIXTURE BEFORE IT IS BELIEVED, AND ITS LIMIT GOES IN ITS OWN HEADER.** `absent_at_check.sh`: nine mutants against a prediction written first, four of them REFUSALS, because **"0 examined" is ambiguous and a tool must refuse rather than choose the reassuring reading.**
- **VERIFY A PEER'S CLAIM ABOUT YOUR OWN INSTRUMENT, EVEN WHEN THEY ARE RIGHT.** **A property asserted from a description is still an assertion.**
- **A VERB CAN BE SEMANTICALLY CORRECT AND STILL BE A SILENT FAILURE, BECAUSE CORRECTNESS IS ABOUT WHAT IT DID AND SILENCE IS ABOUT WHAT IT SAID** (vc, on my `at fc` find; `0158`).
- **A PERMISSIVE READER MAKES A CONTRACT VIOLATION AND A CONFORMING IMPLEMENTATION INDISTINGUISHABLE.** Refuse at the read.
- **hv HAD ALREADY RULED THE THING I WAS INSTRUCTED TO BUILD, THE OTHER WAY.** Read hv's board BODY at pickup, never just its header. **AND THE BODY IS NO LONGER ENOUGH: `fileindex` was ruled RETIRE and lived in `.history/` alone, because the fold keyed on DATED where hv's rule keys on DONE.** **THE DURABLE FORM: BEFORE PUTTING A QUESTION TO hv, CHECK WHETHER hv HAS ALREADY ANSWERED IT.** Three findings on 2026-08-31 had that shape and none needed new measurement, only re-measurement.
- **A RULING'S PREMISE CAN BE CORRECTLY MEASURED AND STILL NOT COVER WHAT YOU BUILD.** Surface the change rather than absorbing it.
- **A DECISION THAT REACHES A QUESTION IT WAS NOT ABOUT IS THE STRONGEST EVIDENCE FOR IT** (vc).
- **ic's WORDING FOR WHY THE INNOCENT EXPLANATION WINS: _a correct general model is what made me stop measuring._** Not laziness -- **a true and relevant model is genuinely good evidence, right up until it is the reason you stop looking.**
- **A FOLD IS A WRITE, SO IT NEEDS THE SAME READ-BACK ANY OTHER WRITE NEEDS, AND THE WRITER IS THE WORST READER OF IT IN THE SAME SESSION.** A previous fold put `D-POP` in this section three times, byte-identical -- **the gate-figure defect at document scale, produced by the operation whose whole purpose is removing duplicates.**

- **TWO hv RULINGS, 2026-08-30, ARRIVING BETWEEN THE 14:59Z AND 15:02Z CLOCK READS OF THIS SESSION -- THE MINUTE IS NOT RECOVERABLE AND IS NOT INVENTED. FIRST-HAND IN THIS dc SESSION. THE WORDING IS hv's RATHER THAN A PARAPHRASE.**
