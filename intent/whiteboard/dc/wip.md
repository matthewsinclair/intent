## D42 -- TIME. Read this before writing anything, anywhere.

**DB records have a timestamp field. That is the source of truth for time. Nothing else. Ever.** No clauses. hv ruled it four times and it was reinterpreted after three of them, twice by me inside ten minutes.

- **You never ask what time it is.** Not the OS, not `date`, not the filesystem, **and not the database either.** Asking SQLite and then writing the answer is still writing a time you obtained.
- **The stamp is applied BY the write**, at INSERT/UPDATE/UPSERT/DELETE. Read-then-write leaves a gap that two writers interleave in, so two records get stamped in the opposite order to the one they were written in.
- **hv's structural close, and it is the form to build against: NO cli or intentsvcs function TAKES a time.** Functions may RETURN times, and every one returned was set by SQLite on a record. **Direction is not symmetric -- IN is forbidden, OUT is fine**: a returned time is evidence a record was written; an accepted time is a second clock with extra steps.
- **THE RULE IS ABOUT SIGNATURES, NOT VALUES, WHICH IS WHY THIS VERSION WILL HOLD.** Every earlier statement of D42 asked where a value came from and whether its source was legitimate -- judgement calls this estate failed three times in one day from three nodes. **A time-typed input parameter is a defect by inspection.** Asking where a caller got a value is a discussion; asking whether a signature accepts one is a grep. **A signature that accepts a time is a standing invitation that gets accepted eventually**, no matter how careful today's author is.
- **The defect is always one step earlier.** Reaching for a clock means you are about to write a time into something that is not a durable record. The fix is never a better clock; it is not writing the time.
- **Not exceptions:** test fixtures; "only reading it"; **"but it came from the database"**; "it's just a label". The third fooled cc, vc and me independently -- **better provenance is not the absence of a confection.**
- **SCOPE, hv: devbin is NOT Intent** -- external, vendored, no db, does what it likes with time. My whole D42 directive resolved to a no-op, and reporting that beat inventing work to look responsive.
- **A board stamp is a label, not data, and nothing may read it as one.** The ordering that exists and cannot be fabricated is the **commit**. The `## (...)` heading is legacy, kept only because nodes parse the shipped format live.

- **A CITATION IS A CLAIM ABOUT A FILE, AND A FILE WITHOUT A COMMIT IS NOT A REFERENT.** vc corrected my `resolve:477` to `:495`, filed it as their own rule pointed at a peer, and was right -- **about a different tree.** Mine was upstream, theirs was the patched vendored copy, the delta is exactly the patch's net `+30/-12`, and **the export is `:441` in BOTH, which is precisely what makes one party look wrong rather than the pair look under-specified.** Neither statement had named its tree. The general form is the same one the whole day was about: `HEAD` is a pointer, `rust` is a pointer at a tree, and a line number is a pointer into a file -- **each is read at a moment, and none of them says which moment.**
- **READ THE DESTINATION'S ISSUE TRACKER BEFORE CARRYING INTO IT, BECAUSE IT KNOWS THINGS ABOUT YOUR PATCH THAT YOU DO NOT.** Devbin's open 0015 -- a completed run that sealed in-flight, filed by cc from Prolix a week earlier -- is an instance of the exact class my patch addresses, **and its invocation was a single gate, which is the one path my patch could not see.** Nobody in the four-node discussion found that, and no test would have: the check was green because it was never asked the question. **The upstream repository was the fixture.**
- **PROVE THE BRANCH IS REACHABLE BEFORE YOU BUILD A CHECK FOR IT -- especially when it looks unconstructible, because that is when you will skip the step.** `write_errors_file` truncates the seal at rc=0, so "green run, non-empty seal" should not exist; the check would have been dead code. It IS reachable: **when the truncation fails the function warns and returns 0, and the marker survives.** Driven against a read-only seal with controls either side proving the probe drove the real function. **The warn was the entire defence, and a note cannot notice.** The probe took ten minutes and was the difference between a guard and a decoration.

- **"DIFFERS AND PARSES" IS NOT ENOUGH TO TRUST A MUTANT: AN EMPTY FILE DOES BOTH.** A `sed` that fails silently writes a zero-byte mutant, which differs from the original and which `bash -n` ACCEPTS, because an empty script is valid bash. It then reds every test -- **which reads like the mutation working spectacularly**, and is the same trap as the byte-identical mutant wearing the opposite face. The third condition is what caught it: **the UNRELATED tests must stay green, or the reds are about a broken file rather than about the branch.** It was printing that as a count for me to read, so it now REFUSES on a red baseline. **A note cannot notice** -- which is my own rule, and I had built the weak form of it that morning. Fourth condition learned the same hour: a harness deriving paths from `$0` behaves differently depending on how it is invoked, and the failure looked exactly like a finding about the mutant.
- **A WRONG ZERO CERTIFIES ABSENCE; A WRONG MAXIMUM CERTIFIES CATASTROPHE -- AND THE SECOND IS FAR MORE PERSUASIVE, BECAUSE IT LOOKS LIKE DILIGENCE REWARDED.** Nobody re-checks an instrument that has just found something big. My devbin measurement reported ALL 27 files diverged and I was one step from filing that as an issue; the cause was zsh tying `path` to `PATH`. **The control is identical in both directions and it is the MATCHING files, not the mismatching ones**: a run with zero matches is a broken run, not a wholly-forked tree, and `int vendor` now says exactly that rather than reporting the alarm.
- **INTERNAL CONSISTENCY IS NOT CORRESPONDENCE, AND A PIPELINE FULL OF CHECKS CAN BE UNANIMOUS ABOUT THE WRONG BYTES.** Four controls in the macOS release path all asked "do these artefacts agree with each other" -- the round trip re-downloads and re-hashes, the formula reads only the sums file, checksum refuses an unclassified artefact, publish verifies the tag exists. **Every one of them passes on a build made from a peer's uncommitted work, because that build is perfectly self-consistent.** The question none of them asked is the one the release actually makes: are these the bytes the TAG names. **The tell is a set of checks that all take their inputs from the same place** -- they cannot disagree, so their agreement carries no information. **Ask what OUTSIDE the set the artefact is supposed to correspond to.** Same shape as ic's seal-versus-return-code, one level up: two claims about one run, and nothing comparing them.
- **PARSING ANOTHER PROGRAM'S HUMAN-FACING OUTPUT MAKES THAT PROGRAM'S RENDERING AN API NOBODY DECLARED -- and rendering is the layer we change most freely and document least (cc's form, better than mine, adopted).** My `sed` over `intent info` was a contract with cc's formatter and neither of us signed it. Mine was the symptom; this is the cause. **The remedy is never vigilance on either side; it is the exit code, which is declared, tested, and cannot be improved into breaking you.** It ran BOTH directions inside one day: my fix falsified a policy row in cc's `exit_code_consumers.rs` that said "nothing branches on it", and nothing anywhere was watching that sentence either.
- **A GATE KEYED TO A MOVING EXIT CODE UNDER-ENFORCES EVERYWHERE; AN UNREACHABLE BRANCH UNDER-ENFORCES ONCE.** The asymmetry is that the first fails in one CONDITION and the second fails in one WINDOW -- and the window is every consumer immediately before it upgrades, which is when guards matter most. **Corollary vc measured and I would not have: a control that is correct today BECAUSE OF AN OPEN DEFECT is a control that whoever fixes that defect will silently break.** `intent info` returns 0 while printing a hard error; rc-gating would have been fine this morning for exactly that reason.
- **A MUTANT MUST DIFFER, MUST PARSE, AND MUST STILL PASS THE BASELINE -- THREE CONDITIONS, AND I HIT TWO FAILURES OF THEM IN ONE SESSION.** An anchor that silently misses produces a byte-identical copy that reports ALL-GREEN, which is what a working guard looks like. A mutation that deletes a line out of an `if` body leaves an empty block, and a file that does not parse reds EVERYTHING, which is what the strongest possible finding looks like. **Both directions are indistinguishable from the result you were hoping for.** The harness now refuses on all three; both refusals fired today on real mutants.
- **THE THING I HAVE IS NARROWER THAN THE THING I SAID -- twice in one session, both times the POPULATION rather than the premise.** Re-verifying a premise at the moment of acting is the right instinct and it caught a wrong reason; it does NOT widen a population, and the population is where this hides. My blocker went one file -> two -> five (vc measured the five). My fmt finding went four damaged files -> one, by going back to the artefact. **Both were corrected by someone else's measurement or by re-reading the diff, never by thinking harder about the claim.**
- **A STALE COPY OF A GUARD IS NOT A MISSING GUARD -- FIND THE OTHER CHAIN MEMBER BEFORE RAISING THE ALARM.** This clone's `.git/hooks/pre-commit.intent` is 148 lines behind HEAD and carries the pre-0042 resolver with the masked `$?`, and its guard roster has no header guard in it. I had the announce half-written for three peers. **`int precommit` runs the header guard from a different chain member**, so both guards are live and nothing is unenforced. One command's difference between a finding and a false alarm sent to everybody -- and it is the same shape as blaming a file for a defect its neighbour has.
- **RUNNING A GATE TO TEST IT MUTATES THE TREE, AND IN A SHARED CLONE THAT IS SOMEBODY ELSE'S TREE.** `int fmt all`, run purely to prove a summary still prints its green line, rewrote four tracked files I had no business touching. Reverted -- but the useful half is that ONE of the four was real damage I would never have found by reading. **A side effect is not automatically noise; look at what it did before undoing it.**

- **A GUARD'S PRECONDITION CAN BE INVALIDATED BY A CHANGE THAT IS CORRECT ON ITS OWN TERMS AND NEVER LOOKS AT THE GUARD.** My total-failure branch tested for an EMPTY resolution, which was the true signature of an unresolvable install on the day I wrote it. cc later implemented `info` to render `<not set>` -- better for a human, and non-empty -- and my branch became unreachable in the one condition it exists for. **Neither change was wrong and nothing connected them**, because the coupling is a `sed` over display text and is written down nowhere. **The tell to look for: a guard that keys off the ABSENCE of output from another tool is keyed to that tool's current silence, and silence is the least stable thing a program emits.** Prefer the exit code, which is a contract, over the rendering, which is prose.
- **A MUTATION THAT FAILS TO APPLY REPORTS ALL-GREEN, AND ALL-GREEN IS WHAT A WORKING GUARD LOOKS LIKE.** My first classification mutant used a Python anchor that did not match, so the "mutant" was a byte-identical copy -- and the run printed `ok 5`, `ok 6` beside two genuine mutants that had worked. **The AssertionError was three lines up the same output and I read past it, because the verdict underneath said what I expected.** This is the fixture-never-reached-the-branch trap in the direction that feels safest: not a red I would have investigated, a green I already believed. **The mechanism, and it is one line: assert the mutant DIFFERS from the original before running anything against it** -- `diff -q` and refuse. An anchor that silently misses is indistinguishable from a guard that holds.
- **A GUARD THAT CANNOT TELL INVOCATION FROM MENTION IS STILL RIGHT TO FAIL YOU, AND THE FIX BELONGS ON YOUR SIDE.** ic's retarget guard refused three of my test lines that carried the dispatcher path inside a grep pattern. The allowlist was RIGHT THERE with a precedent row reading "it contains the needle as data" -- exactly my case -- and taking it would have blanket-exempted the file forever, including any real bypassing invocation added later. **The literal bought nothing: those tests assert that a regenerator's status is CHECKED, and how the CLI is spelled is incidental.** Matching on structure is the stronger assertion anyway -- it survives the script moving to `$INTENT_BIN`. **A guard that can be argued with case by case is not a guard; the tell that you are arguing is reaching for its allowlist rather than for its point.**
- **THE WORKING TREE MOVES UNDER YOU IN A SHARED CLONE, AND A REBUILD SILENTLY ADOPTS A PEER'S UNCOMMITTED WORK.** I rebuilt and measured `intent info` at exit 1 where my own fold had recorded exit 0 -- and the honest first hypothesis was that I had mis-measured, since masked exit status is a failure I have made. It was neither: cc had the fix uncommitted in the tree my build compiled. **`git status` was empty when I started the turn and not ten minutes later.** So a measurement names a COMMIT, and if the tree is dirty it names nothing -- and I was one sentence from reporting a peer's fix as landed on the strength of a binary built from their in-flight edit.
- **THE COST I WAS TOLD TO MEASURE BEFORE CHOOSING DID NOT EXIST.** The asset-shape decision was held all session on "it changes signing, notarisation and the checksum step, all built against a single binary". `notarize` already staged a DIRECTORY and submitted a zip of it -- so a third non-Mach-O artefact never reaches signing or notarisation at all, and the only real cost was in `checksum`, where two sets had been silently one. **The hold was real; the reason recorded for it was three-quarters wrong, and reading the code I had written closed it in ten minutes.** A remembered cost is a guess about code that is sitting right there.

- **I FABRICATED A HEARTBEAT ON THIS FOLD, IN THE ONE FIELD THE WHOLE CLOCK DISCIPLINE EXISTS FOR, AND THE GUARD DID NOT CATCH IT.** Rewriting my board through a python heredoc I typed `heartbeat_at: 2026-08-17 03:05Z` as a literal in the script body. I had read `03:01Z` before it and read `03:04Z` after, so it was **in the future when I wrote it** -- and it committed clean, because it sat inside the guard's 120s jitter tolerance. **My recorded mechanism is "read the clock into a shell variable and SUBSTITUTE it", and I applied it correctly to the two messages in the same minute -- passing the stamp as `argv[1]` -- and not to the board, because the board was being generated rather than typed.** That is the mechanism-incomplete failure again, and the missing clause is exact: **when a script writes a stamp, the stamp is passed INTO the script as an argument; a stamp appearing anywhere in a script's own body is fabricated by construction.** Both forms were in one session, one right and one wrong, which is what makes the clause worth having rather than another resolution to be careful. The live value has been replaced by a real read; the fabricated one is in `267c5a00` and is recorded here rather than quietly corrected, because a corrected-looking fake is worse than an admitted one.
- **CALIBRATE AN INSTRUMENT AGAINST A KNOWN GOOD BEFORE BELIEVING IT, AND A ZERO IS A CLAIM LIKE ANY OTHER.** A tool giving a real-looking answer usually means it was asked in the wrong context -- `spctl` on a bare Mach-O, `brew style` outside a tap, bare `rustfmt` without the repo's config, prettier cleared twice from the wrong instrument. **The sharper half is the negative: a result from an unverified invocation is not evidence, and it is the shape that feels MOST like evidence, because nothing failed.** Measured cost: a grep asking which consumers invoke `intent` by explicit path returned zero; calibrating it against a call site I had already read by hand turned zero into four, **two of which were the release-regenerator defect.** A wrong zero does not merely fail to find things -- it certifies their absence, and the more sweeping the question, the more load the answer carries.
- **THE INSTRUMENT GOES STALE TOO, AND SO DOES A HOLD.** A binary 57 seconds behind a fix reports the old behaviour as confidently as one 14 minutes behind, and staleness is invisible in the output. `stat` the binary against `git log -1 --format=%ct <fix>` before believing a measurement about that fix. **Same rule one level up: a hold must be re-verified when it is HONOURED, not only when it is written.** Mine was stale in twelve minutes -- and the re-check had two staleness layers, the premise and the binary I would have re-measured with. **A positive result from a stale instrument is still a result about the past, and it is the direction that feels safe because the news is good.**
- **PROSE AND MECHANISM SHARE A SPELLING, AND EVERY WAY THAT GOES WRONG IS THE SAME DEFECT.** A check a comment can satisfy is not a check (anchor structural tests to `^` structure). A grep for a mechanism counts its prose (`deny_unknown_fields` returned three; all three were the doc comment explaining why the file has none). **And a comment that predicts its own defect is still a defect** -- `usage()`'s hardcoded `5,34p` window carried the words "it will move again if the header does", and the header moved, and `--help` printed no flags at all. **A note cannot notice.**
- **AGREEMENT IS NOT TRUTH; ONLY A CANARY IS.** Two things written in the same breath by the same author agreeing is not evidence -- my lock refusal's comment said "every changed line is a version line" and the code tested exactly that, and the INVARIANT was wrong, so it accepted the one change it exists to refuse. **Diffing a comment against its check tests agreement. Only running the refusal against a case it should refuse tests truth.**
- **A MUTANT THAT CANNOT REFUSE ANYTHING IS NOT A MUTANT, AND A FIXTURE THAT NEVER REACHED THE BRANCH PROVES NOTHING.** The mutant must still pass the BASELINE case before its verdict means anything, or a broken file reads as the strongest possible finding. **Corollary with a heuristic attached: uniformity across cases that should differ is evidence about the instrument, not the subject** -- three resolver conditions all returning nothing meant the hook was exiting before the block under test, not that the block was quiet.
- **A NEEDLE LIST CATCHES THE INSTANCE; DERIVING THE SET CLOSES THE CLASS.** An allowlist forbids everything its author did not think of; a needle list forbids only what they did. **Now with the mutant that proves the second door is real**: the hand-picked `--help` test passes on a parser arm the header never documents, and the derived one names the flag. The unwritten cases are where the risk lives.
- **"THE GUARD IS ABSENT" AND "THE TOOL THAT LOCATES GUARDS IS ABSENT" ARE DIFFERENT ABSENCES, AND ONE `else` CANNOT TELL THEM APART.** Benign absence and total absence took the same branch, so two mild warnings meant nothing was enforcing anything. **The general form: an absence treated as a property of the THING when it is a property of the RESOLVER.** Same shape appeared in `check critic --languages`, blaming a project's language declarations for a failure of the tool.
- **A GUARD THAT WATCHES FOR CHANGE IS STRUCTURALLY BLIND TO SAMENESS.** The release's dirty-tree check exists to stop an inconsistent tag; a failed sidecar REGENERATION leaves the file at the previous version, so the tree is clean and the cut proceeds. **The tests asserted the stamp happens BEFORE the commit and could not assert it WORKED** -- ordering was the fix everyone remembered, so ordering is what got tested. **Whenever a control asks "did something change", ask what it does when the answer is legitimately no and should not have been.**
- **A PARTIAL FIX LEAVES THE HALF YOU DID NOT CHECK ASSERTING THE OPPOSITE, AND AN EXTRACTION IS NOT A DELETION.** Replacing a claim obliges you to re-read what surrounded it, because its neighbours were written to agree with the thing that is now gone. **And "the old form must not survive" is the wrong predicate for a refactor** -- extraction MOVES code, so the right assertion is Highlander's: exactly ONE home, which also catches the copy pasted back inline. Both times the reasoning was already present one line away and simply not carried across.
