## Decisions

- (2026-08-14) **Fix the class, not the instances -- and say which mechanism the guard actually proves.** 0025 was three shapes of one bug: readers branching on an ambient `PROJECT_ROOT`, a guard that suppressed resolution when it was set, and a `require_` helper that tested a variable instead of resolving. Fixing the reported instance would have left the other two. The fix names an authority (`resolve_project_root`) and routes every reader through it. **The honest half is the mutation matrix**: removing the dispatcher scrub reds NOTHING, because every reader that exists today also resolves -- so the scrub is fail-safe cover for readers not yet written, and the issue says exactly that rather than implying a test proved it.
- (2026-08-14) **A generic environment variable is not evidence.** `PROJECT_ROOT` is a name any parent can export -- Makefile, direnv, CI, devbin on every invocation. Code reading it raw asks "did someone set a variable?" while meaning "am I in a project?"; those agree often enough to look correct and differ exactly when it matters. The adoption of devbin did not create the bug, it made it fire every time, which is the only reason it was found. **A tool that makes a latent defect deterministic is doing you a favour.**

- (2026-08-14) **A mutation that fails to produce an expected red is itself the finding.** 0024's test 5 asserted a negative as `grep -q "..." && false || true` -- a form whose trailing `|| true` swallows the failure, so it can never go red. It passed the baseline, which proves nothing, and then passed M1, a mutation that should have killed it. **The red that did not arrive was the only signal it was vacuous**, and I would have shipped it otherwise. So the mutation pass is not just "does the guard fail when I break the code" -- it is a per-test expectation, written down BEFORE the run, and an unexpected green is investigated exactly as hard as an unexpected red. Sharpens the standing "a test that passes is not a test that works", and rhymes with vc's own harness-can-lie finding from the same day.
- (2026-08-14) **A queued program is evidence with an expiry date, same as a number or a green claim.** My board's top item was "sweep Lamplight" -- an estate already at 2.19.0, with ~40 files in flight from a sweep their own nodes ran, four of their sessions live in it, and their hv having ruled the remediation dead outright. **Every part of the premise had expired and none of it decayed visibly.** Checking the target's actual state cost one command and was the difference between a report and a collision with another agent's in-flight surgery. Their cc corrected the identical failure on their own board the same morning, from the same ruling. **Verify the premise of a queued action at the moment you act on it, not when you queued it** -- and for anything touching another project, that check includes who is live in it.
- (2026-08-14) **A record must name the commit it covers, never "HEAD".** `intent/wip.md` claimed "Full suite GREEN at HEAD" while three code commits postdated the run; it was in four documents, and it is a claim that decays silently every time anyone commits. Same class as `steel_threads.md` and the AT reference -- a reader answering confidently from stale evidence, which is what this whole release was about. **The corollary is the sharp part: a stale green is cheap while it is redundant and expensive at the single moment it is not.** Pre-flight normally re-establishes it, but `--skip-tests` is the documented recovery from a half-done abort, so the written record becomes the sole evidence of a run exactly on the occasion something already went wrong.
