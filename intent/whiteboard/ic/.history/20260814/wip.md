## Findings -- first pickup

- **v2 has no single usage convention, measured not read.** Four commands at `9cdebe0`, three behaviours: `intent st` and `intent wp` bare emit `error: ... is required` on **stderr** with rc=1; `intent ac` bare emits a 1342-byte usage block on **stdout** with rc=1; `intent todo --help` emits 1077 bytes of usage on **stdout** with **rc=1** -- an explicit help request answered with a failure code. Superseded by the full census in `parity/README.md` finding 2 (45 stderr-only, 12 stdout-only, 2 both).
- **`lib/help/` cannot serve as the machine-readable spec.** 11 help files for 27 `bin/intent_*` scripts; 18 commands have none. The `@`-section grammar the renderer supports (`@usage:`, `@options:`, `@arguments:`, `@examples:`) is used **exactly once each**. Naming drift too: `stzero.help.md` against `bin/intent_st_zero`, and `rules.help.md` documents a `claude` subcommand rather than a top-level one. Now `parity/README.md` finding 8.
- **Static parsing cannot enumerate this surface.** Subcommand dispatch is formatted inconsistently across scripts -- `bin/intent_todo:384` puts its arms at zero indent, `bin/intent_st:295` nests them -- so one regex over 27 heterogeneous files silently undercounts. A probe of mine scored `intent_st` (1621 lines) at zero subcommands. Now the method note in `parity/README.md`.
- **`bin/intent_migrations` is mode 644 and is not a command.** It exists only to be sourced by the upgrade orchestrator, and `bin/intent_help`'s auto-list requires `-x`, so it is correctly absent from help. Resolves whether `intent migrations` belongs in the surface: it does not.

## Findings -- BATS estate recon

Swept by sub-agent across 94 files / 1235 cases. Retained here because several items are NOT carried into the register and would otherwise be lost -- the register classifies files, it does not record these.

- **~151 invocations bypass `bin/intent` altogether**, concentrated in `treeindex_commands.bats` (53 tests), `fileindex_commands.bats` (47) and `intent_critic.bats` (21). They never get the dispatcher's `PROJECT_ROOT` resolution, its `INTENT_ORIG_CWD` export (`bin/intent:217`) or its `cd "$PROJECT_ROOT"` (`bin/intent:218`).
- **~87 tests (7%) test shell functions directly and die with bash** -- `critic_runner_proxies.bats` (33), `critic_runner_applies_to.bats` (19), `helpers.bats` (17), the two `intent_migrations_*` files (14). The migrations ones retire **by design**: D09's two-hop policy says v2's own upgrade ledger is never reimplemented in Rust.
- **The file-layout problem is about half what the raw count suggests.** Of 569 file/dir assertions, **244** point at CLI-written project artefacts (`intent/st/**`, `config.json`, `issues/**`, `.treeindex/**`) -- genuinely exposed to a JSON canon -- while **220** are repo-content pins (`RULE.md` x47, `AGENTS.md` x26, `SKILL.md` x25, `lib/templates/**`) that survive a binary swap untouched.
- **Assertion classes**: 58% pure output/exit-code, 20% mixed output+layout, 10% layout-only, 11% shell-internal. Frontmatter-literal coupling to the v2 markdown canon: `status:` 159, `id:` 69, `intent_version:` 32, `title:` 31, `created:` 30, `satisfied:` 29.
- **The voice contract is stricter than "same words".** 112 `assert_output` calls are exact whole-output matches, so any added banner, warning or trailing space breaks them; `output_width.bats:44-140` pins byte-exact table rendering and width-independent canonical markdown, and `title_pipe_sanitize_guard.bats` pins the `|`-to-`/` substitution because `render_table` splits on `IFS='|'`. v3 must reproduce column padding exactly, not merely say the same things.
- **A live vacuous-green risk.** `pre_commit_hook.bats` (15 tests) depends on the real `intent` being on PATH; without it `lib/templates/hooks/pre-commit.sh:48` fail-opens and the tests pass having proved nothing. CI adds `bin/` to PATH for exactly this reason (`.github/workflows/tests.yml:49-56`, with a comment saying so).
- **Two cheap unrelated wins.** CI clones `bats-support` / `bats-assert` / `bats-file` over the network on every run (`tests.yml:82-84, 152-154`) and **zero `bats_load_library` calls exist** -- every helper is hand-rolled in `test_helper.bash:105-195`. And 46 `run_intent` calls carry no `run` wrapper (`intent_agents.bats:94-95`, `output_width.bats:48`), so an exit-code drift aborts the test opaquely instead of failing an assertion.
- **Other traps for the harness**: the suite is not parallel-safe (global `/tmp/intent/` sentinels); `setup_fake_home` is called in only 10 files and some tests `cp` real content into `$HOME/.claude`; several tests assert against the live git working tree (`no_absolute_home_paths.bats:37, 100, 103`); `no_template_fallback.bats:26` copies the whole `bin/` tree to build a deliberately broken install, a shape a self-contained binary cannot have; `create_test_project` hard-codes `intent_version: 2.10.0` (`test_helper.bash:68`) while `st_commands.bats:63-64` asserts the live `VERSION` file. `tests/docs/` and `tests/releases/` are empty untracked directories holding no tests at all, and `intent/llm/MODULES.md:258` documents a `tests/fixtures/upgrade/` tree that does not exist.
- **Fixtures are not the migration surface; the test bodies are.** `tests/fixtures/` is rule- and extension-shaped (and `fixtures/critics/` is referenced by no `.bats` file at all). The v2-markdown fixture surface is inline: 181 heredoc writes, 73 writing `info.md` and 13 writing `acceptance.md`.
