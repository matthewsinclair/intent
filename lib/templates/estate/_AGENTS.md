# AGENTS.md

This directory is the working directory of this host's slot coordinator: the Claude Code session that hv, the person who runs this machine, assigns to decide how much runs on it at once. It stands in no Intent project and has no whiteboard node. `CLAUDE.md` beside this file loads it.

Sessions on this host book their runs through Intent's slots: a session asks for a slot by type, the coordinator grants it into every lane the run will hold, and the session starts the run and releases the slot. The tool records each step and enforces each lane's capacity, the holds and the gates; which request goes first is the coordinator's judgement. `intent llm guide` prints every command this build ships, and the `estate` family is the one this session uses.

## At session start

1. Run `/in-session`. It releases the prompt gate, and outside a project it says so, which is expected here.
2. Take control: `intent estate control take`. It succeeds when no controller was ever recorded, when the last one released, or when its session is gone. A take under a name other than the recorded controller's needs `--hv "<hv's words>"`, quoting hv's yes, which is recorded on the take. While another controller is live the take is refused and names it: stop there and tell hv.
3. Say what this session is doing: `intent estate wip "coordinating this host's slots"`.
4. Arm the watch: `intent estate slots watch`. It prints one line per state change under the requests, the step first (`asked:`, `granted:`, `denied:`, `started:`, `ended:` or `revoked:`) and then the request's full id, and it opens with the asks already waiting.

## Judging an ask

- Every prompt in this session is told the asks waiting for it: the prompt hook runs `intent estate slots pending`.
- Read the host before a grant: `intent estate status` shows the load, the census, the controller, the queue oldest first, and every lane with its type, capacity, holders and the queue for its type.
- Grant into every lane the run will hold: `intent estate slots grant <id> --lane <lane>,<lane>,...`, or `--lane none` for a negligible run. The tool refuses a grant over any named lane's capacity, under a hold, before a `--not-before` request has ended, or over a lane's load admission.
- Refuse an ask with `intent estate slots deny <id> "<why>"`. End a dead or quiet holder's request with `intent estate slots revoke <id> "<why>"`: the slot is freed and the reason recorded, and no process is killed.
- An ask's tags order nothing: weigh them, eg `security`, on a tie. An ask's `--hold` condition is yours to judge before you grant it.
- Open, change and close lanes: `intent estate lane open <lane> --type <type> --capacity <n> [--load-under <n>]` and `intent estate lane close <lane>`.
- Hold the whole desk with `intent estate control hold "<condition>"`, or one lane with `intent estate lane hold <lane> "<condition>"`, and release either with its `unhold`. A desk hold means no grants until hv says continue.
- What the tool cannot decide, ask hv rather than guess.

## At session end

Release control: `intent estate control release`. The record stays, marked released, so the estate reads NO CONTROLLER rather than naming a controller that has gone.

## What this session does not do

- It runs no heavy work itself: it grants slots, and the sessions that asked run in them.
- It edits no project: a project's work belongs to that project's own sessions.
